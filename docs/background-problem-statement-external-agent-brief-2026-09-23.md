### 3. 当前工作的必要上下文

以下是需要忠实表达的当前意图，不是要求你照抄的叙事顺序。

**C1：资源维度对齐。**
通过设备标定、参数调优中的资源记录、资源画像与瓶颈判断，观察算子实现如何受到寄存器、shared memory、带宽、算力和 occupancy 等因素影响。
当参数方向的性能趋势与资源限制相遇时，结构改写可能用其他维度的余量缓解当前限制，再重新调参。
“对齐”强调迭代中的资源交换和可观测边界，不等于资源占用越高越好，也不等于每项任务都已达到物理最优。
实测带宽或算力构成的 floor 需说明流量、算量、精度和硬件假设，不能自动提升为不可突破的严格界。

**C2：资源/性能响应引导的结构改写。**
在固定其他旋钮的条件下，对某个参数轴实测两个端点，同时记录性能与资源变化，用这些局部响应帮助 agent 选择结构改写方向。
核心不只是“参数变化后更快或更慢”，还包括“哪些资源随之变化，交换是否可能有价值”。
这是观测到的有限差分响应，不是连续结构空间的解析梯度，也不保证参数响应能无误预测新结构收益。
当前 G0/G1/G2 对照中，G1 已有 J、delta-J、gain 和性能斜率；G2 额外获得资源侧信息。
G2 的新增视图包括 resource_deltas、resource_slopes、fresh metrics 与资源状态等，不能描述成只增加一个孤立标量的干预。
四个父状态中 G2 对 G0 为 4/4、对 G1 为 3/4，是有限案例结果，不是方法总能选对方向的证明。

**C3：目标引导的算子优化。**
将验收从孤立算子的 latency 推广为用户声明的模型级目标 J，例如 TTFT、单流吞吐或并发吞吐。
目标包含工作负载和质量条件，影响优化哪个算子组以及如何判断候选是否值得接受。
应区分站点选择、候选优化和模型级验收；算子单测更慢但模型目标改善，在满足质量门时仍可能是可接受结果。
C3 不再是旧版“信息获取效率”，也不是在固定 kernel latency 上换一种搜索预算度量。

**核心回路与模型级扩展。**
核心输入是一段参考实现与固定输入形状；当前文档的流程为：
设备标定与基线 → 结构互异的种子 → 正确性门及修复 → 参数调参 → 资源画像与瓶颈判断 → 响应采集 → 结构改写，并循环后做最终独立复评。
核心搜索在墙钟预算内进行，不能把“意图逼近资源边界”写成“只在已证明达到上限时才停止”。
C3 在前面增加目标合同化、短窗口 profile、算子分组与资格门、站点排名、任务包生成，再接入核心优化回路，并改用端到端目标与质量门验收。
它是模型级扩展，不是另起一套与 C1/C2 无关的算法。请自行判断 Background 中应交代到什么程度，细节留给 Method。

### 6. 形式化与证据的共同边界

请在正式起草前检查以下区别，并在必要处用简洁定义或脚注澄清：

- **硬件执行资源与搜索预算**：寄存器、shared memory、带宽等，不等于尝试次数、GPU 时、墙钟或 agent token。
- **硬容量与性能指标**：容量约束、吞吐上限、occupancy 和 spill 不能全部当成同一种可行性不等式；spill 不必然使候选不可运行。
- **理想语义与经验正确性**：对所有输入成立的正确性定义，不等于有限测试通过；数值门、精度和负载条件应显式说明。
- **观察值与真实最优**：预算内最佳值不是结构真实最优；平台期不是局部最优证明，经验 floor 也不是全局最优证明。
- **局部响应与解析梯度**：有限差分依赖被固定的其他参数、采样端点和噪声，不能声称可沿结构空间梯度直接下降。
- **结构与描述坐标**：descriptor 是候选的描述或投影，不是完整结构本身，也不是天然的一一映射。
- **kernel latency 与 C3 目标**：模型目标依赖工作负载、目标方向、替换上下文和质量契约，不能继续用固定 kernel 延迟覆盖全部问题。

# v5 研究基础：统一目标驱动的资源对齐与条件响应框架

> 日期：2026-09-15。状态：研究设计草案，面向未来 v5，不是最终实施计划或实现批准。
> 本文只综合两份前序研究材料，不报告新增代码审计、文献检索、测试或性能实验。
> 优先级是核心方法及其通用应用，不是建设安全、监控、隔离或发布平台。

## 执行摘要：用一条主线解释整个方法

**目标决定什么叫更好，资源解释实现受到什么限制，固定搭档的响应检验有用方向，完整任务决定是否成功。**
用户先说明要完成什么任务、希望改善什么；框架确认评价方式，然后让已有 C1/C2 和 A/B/C/D 都服从这个目标。
例如，同一程序可以分别追求响应更快或占用内存更少，但不能靠减少工作量或降低质量来获得优势。
C1 把程序的资源需求、可用边界和结构动作联系起来，回答“限制在哪里，哪些变换可能相关”。
C2 固定其他程序参数，测一个旋钮变化时完整目标 J 如何变化，回答“当前方向是否值得继续探索”。
已有改写与搜索控制器据此提出新结构；新结构仍必须完成同一任务，并由同一评价器重新判断。
这不是追求最高 occupancy，也不承诺达到物理峰值、越过硬件限制或找到全局最优。

统一流程是：任务目标 → 确认 evaluator 与协议 → C1 资源对齐 → C2 条件目标响应 → 原有结构搜索 → 完整任务验收。
“支持不同目标”不是只改最终分数：参数选择、最佳候选、结构族比较、收敛、反馈与报告必须具有相同目标含义。
不过，正确且完整的标量目标接入可能已经构成全部所需方法；不能为制造第三贡献而额外发明控制器。
论文可写成“统一框架、资源对齐、条件响应”三条贡献，但只有后两项是待检验的方法机制。
应用泛化证明同一核心在不同任务和目标下有效，不自动构成第三个独立算法。

## 2. v4 基线：复用什么，概念上还缺什么

| 能力 | 历史快照中的状态 | 本研究采用的边界 |
|---|---|---|
| A/B/C/D 主循环 | 参数化与正确性修复、调参、结构改写、停滞后的新结构族探索已有 | 保留主循环，不建立另一套优化器 |
| 完整 forward 候选 | 支持一个完整调用包含多个 custom kernel 与 vendor 算子 | 不是从单 kernel 升级成全模型表达系统 |
| 资源向量与反馈 | 已有资源维度、分析报告和送入改写的通路 | 改进资源归属与目标解释，尽量复用报告 |
| 条件 C4 | 固定搭档、fresh 发现对和独立验证对已有 | 复用受控测量，而不是重新发明单轴扫描 |
| 方向 token 与消费 | 已有来源生命周期、投递及生产 trial 回填 | 目标和上下文适用性需要与新评价口径一致 |
| fresh 测量接线 | 已有绕过测量缓存的实际生产路径 | 缓存结果仍不能冒充新的独立重复 |
| 提示与 tuner 接线 | 条件简报进入 analyst/rewriter，扫描点进入 tuner | 保留 sampler 和 rewriter 两类消费者 |
| 默认行为 | 条件机制默认 off | 实现存在不表示所有运行已启用，旧默认路径应兼容 |
| 评分链 | 仍围绕 `robust_ms`，方向增益链也偏向延迟 | 不能只更换最终报告标题或一个延迟变量 |
| 经验方向门 | 正值最小化的 log 增益门，含 4% 下限、每端两次 fresh trial、每 trial 约 20 次 timing | 这是旧延迟协议，不是所有目标的统计标准 |
| 应用语义 | 完整 checkpoint 映射、KV 状态、应用质量、完整生成及指标泛化在该快照尚未闭合 | 不等于后续分支仍缺失，规划时重新确认 |

已有软墙数据来源、当前搭档适用性和结果简报完整性的疑问，会限制相关机制解释的强度。
应在作对应主张前核对这些局限，但本文不复制八项修复队列，也不要求先修完全部历史问题。
软墙缺数据时标未知；搭档不同不能当成当前条件响应；简报缺结果不能靠文字推断成功。
历史候选、后端与协议身份不足以自动说明新目标下的完整任务可比性，需补足实验所需上下文含义。
这些是对研究证据的限制，不是新建证据账本、隔离平台或健康门系统的理由。

## 3. 统一问题定义：先分清任务、目标与约束

设语义 S 规定输入输出、权重与状态、允许误差和合法变换，工作负载 W 规定必须完成的工作及其分布。
环境 E 包含硬件、软件、执行与并发政策；目标 O 规定指标、单位、方向和固定聚合。
约束 K 决定候选是否可接受，搜索预算 B 决定可花费多少尝试与实际成本；它们分别声明，不相互替代。
候选 π 可以是完整程序、完整模型，或已声明边界的项目 pipeline，不是任意项目中的所有外部系统。
θ 表示该候选的程序参数；结构改写改变 π，调参改变 θ，二者都不能偷偷改变 S 或 W。
资源观测写为 `r(π, θ; S, W, E)`，原始任务指标写为 `m(π, θ; S, W, E)`。
资源向量解释实现，指标向量描述任务表现；二者允许有关联，但不能混成没有单位解释的“效率分”。

权威目标为 `J = eval(π, θ; S, W, E, O)`，或对完整原始指标作冻结聚合 `J = A_O(m)`。
评价结果不只返回标量，还应足以判断测量 valid、任务质量与约束 feasible，并保留必要原始指标。
无效测量、语义错误和有效但不可行是不同情况；不能都填成一个极差的伪造 J。
普通选择是在有效、满足约束的候选中按 J 比较；寻找可行解可另用已声明的约束违反量。
不能把约束写成巨大惩罚或无穷大，再拿这个不连续值计算 C2 的目标“斜率”。

“任何 eval”仅指概念上的标量评价接口，不表示任意黑盒目标都能得到可靠响应估计或保证优化成功。
首先支持可测的正值连续型最小化、最大化目标和显式约束；其他目标按估计器能力逐项声明。
若所需指标根本不可测或评价协议不支持，应在搜索前明确报不支持，而不是生成一个近似分数。
若 J 可评价但没有合适的 C2 信号，则降级到普通搜索，不必拒绝整个任务或强制追加大量探针。
有限有序 choices 不等于连续变量；类别型算法只能做受控对照，不能按编号求导。

## 4. 从自然语言目标到固定评价协议

用户声明体验或成本目标，agent 可以把它翻译成已注册的指标、聚合方式与评价模板。
例如“更流畅”可能指平均每 token 时间，也可能指尾部卡顿；不能由 agent 静默选择对自己有利的含义。
有歧义的业务取舍由任务所有者在搜索前确认；指标已有明确含义时直接采用，不增加审批队列。
初期从已知 evaluator 能力出发，不以任意生成并执行评价代码作为通用性前提。
搜索开始后，agent 可以修候选、更新内部假设，但不能因为得分差而改 scorer、质量容差或请求集合。
这一冻结保证实验比较的是同一道题，不是安全补丁平台或自治治理机制。

评价适配职责是：在固定工作负载上运行 reference 和 candidate，测原始指标，核验输出、质量与状态语义。
薄后端适配只处理执行边界、函数语义、权重与状态恢复，以及该后端如何取得合法测量。
优化策略不能藏在适配器里，核心也不能出现“遇到某模型就优化 prefill”这样的名称规则。
checkpoint 与候选的权重映射应明确，随机种子相同不保证结构变化后仍构造出同一状态。
KV、随机数、可变 buffer 和请求之间的状态需按任务定义恢复，避免前一个候选改变后一个候选的题目。
这是测量正确性的必要条件，不要求建立监控产品、逐 trial 新进程或庞大的故障注入设施。

原始指标足够且条件完全相同时，可以按新目标离线重评分，不必为换一条规则重复运行 GPU。
旧记录缺少所需指标时才补测，不能从延迟猜出内存，也不能从平均数还原尾分位数。
离线重评分仍是固定候选库选择，不是 fresh 独立复测，也不是目标驱动自适应搜索的新证据。
改变 workload、partners、状态政策或环境后，旧响应不能直接当作新上下文中的条件结论。

## 5. C1：资源维度对齐，为结构动作提供解释

C1 的输入是已有资源观测、程序结构、目标与约束，输出是有归属、有适用范围的限制解释及候选动作族。
观测至少标明粒度、所属算子或 kernel、后端与适用上下文；多个 kernel 的极值不能拼成一个虚构瓶颈。
区分程序需求与可用边界，按任务需要选择资源维度，不强制每次运行收集全部 counters。
未知维度是缺失，不是零；不适用的指标也不应被补成看似良好的资源状态。

| 边界类型 | 能回答的问题 | 不允许推断 |
|---|---|---|
| 硬可行性 | 当前 shared memory、launch 等资源需求是否允许执行 | 可运行就接近最快，或硬限额可以被程序突破 |
| 校准吞吐包络 | 当前环境下可持续吞吐及剩余空间的近似范围 | 理论峰值必达，校准误差可忽略 |
| 经验转折 | 给定程序和搭档下的 spill、物化或访存行为在哪里变化 | 所有任务共享同一软墙，缺 profile 也能确定转折 |

每块或每 SM 的 shared-memory 限制与整卡总 VRAM 容量是不同资源，workspace 也不等于 shared memory。
occupancy、带宽占用率或计算利用率只是诊断，不是默认目标；提高它们可能让完整 J 变差。
结构动作族从观测到的程序结构产生，例如减少中间物化、改变分块、复用数据或调整合法融合边界。
模型名称可以用于装载模型，不能用于决定采用哪种结构动作；同一种结构应得到同一类分析。
C1 复用已有资源报告与改写入口，但报告需让目标 J、约束和完整测量边界可读。
研究问题不是“报告写得更丰富”，而是同等信息预算下，解释是否提高有效结构行动及最终目标收益。

## 6. C2：测程序旋钮对目标的条件响应

固定 π、其他参数 `θ_-j`、工作负载和评价协议，在两个合法端点 a、b 上定义：
`ΔJ_j = J(θ_j=b, θ_-j) - J(θ_j=a, θ_-j)`。
只有旋钮间距具有实质意义时，才可另报 `ΔJ_j / Δθ_j`；默认解释是有限端点对照，不是连续导数。
同时报告 `Δr_j = r(θ_j=b, θ_-j) - r(θ_j=a, θ_-j)`，并保留资源实体和约束状态。
固定搭档减少混杂，但改变一个旋钮仍可能同时改变 shared memory、寄存器、访存和 launch 数。
因此 C2 不是单一硬件资源的因果导数，也不是资源用量与性能的静态比值。
这里若使用“效率”一词，只指当前条件下程序变化带来的目标响应，不赋予通用比率含义。

### 6.1 目标方向、增益与不确定性必须一起泛化

正值最小化目标可报告相对改善 `g = 1 - J_new / J_old`。
正值最大化目标可报告相对改善 `g = J_new / J_old - 1`。
对一般有限数值，定义方向系数 `q=+1` 表示最大化、`q=-1` 表示最小化，方向化绝对改善为 `g_abs=q*(J_new-J_old)`。
`g_abs` 保留目标单位，不能直接将毫秒、字节和吞吐的差值跨指标混排或相加。
基线为零时相对改善未定义，应弃用相对量，改用绝对量或预先声明的公共尺度，不加 epsilon 掩盖问题。
对负值目标也应使用适合其语义的方向化差值或固定尺度，不能沿用正值比率的解释。
把 `J=-throughput` 送给最小化器是机械适配，但负值不能进入旧的正值 log 门。

严格单调变换并匹配方向时可以保持冠军排序，却会改变响应幅度、噪声包络和行动排序。
非严格单调变换还可能引入并列；不能用“赢家相同”证明所有中间决策等价。
因此原始 J 的解释、比较尺度与优化器内部 loss 应分开固定，不能运行中挑一种变换放大信号。
方向支持来自适合该指标的重复与不确定性估计，不是只把 latency 字段改成 J。
旧 4% 门与每端两次 fresh trial 不能直接移植到内存、吞吐、成功率或完整生成。
两次外层重复中各约 20 次内部 timing，不是足够的独立请求，更不能自动支持 p99 结论。
先用 pilot 估计测量波动和成本，再定目标特定阈值与重复量，不预设所有新指标统一八对或统一 τ。

### 6.2 约束、平台区和非光滑目标

有效但违反约束的候选可以保留原始指标，用于解释可行性；编译失败只提供边界信息，不造无穷大斜率。
用于可行域内性能主张的 C2 端点应都有效且可行；寻找可行解的响应单独标成约束响应。
若内存只是 cap，满足 cap 后“更少分配”并不天然更好；若内存本身是 J，才按其目标方向比较。
二元结果、成功率估计、稀疏奖励或宽平台区可能没有可辨认方向，不能自动声称存在有意义的斜率。
可以事先声明连续辅助指标帮助普通搜索，但不能把辅助信号冒充真实 J 的响应。
对于 `max` 或 worst-shape 聚合，保留逐案例指标及两端的限制案例，解释活跃项可能切换。
不假设跨转折光滑，不把各 kernel 的局部改善相加当作完整任务改善。
无方向、测量不足或不支持的估计返回 unknown；在预算内继续普通搜索，而非认定结构无望。

### 6.3 复用条件测量，不重新造探测平台

扫描几何、固定搭档、fresh 发现与验证、来源消费和生命周期尽量复用已有机制。
其语义从“延迟方向”改为“指定目标与上下文下的方向”，适用范围变化后不能继续消费旧响应。
应用收益主张要求两端 J 来自完整目标任务；每个正式 B 候选也由同一完整 J 参与选优。
编译和静态探针可以廉价诊断资源，不要求每次编译回答都同时运行整个大模型。
若完整 J 太贵，先缩小机制面板、固定可行 workload profile 或限制结构族预算，再评估是否值得继续。
不能让未声明的局部性能分数悄悄决定 best；局部 proxy 只可作为清楚命名的可选消融。
这一成本取舍不需要新多保真调度平台，也不允许事后缩短工作量使某候选获胜。

## 7. C1/C2 如何进入原有结构搜索

已有控制器同时消费“资源限制解释”和“该目标的受控响应”，而非建立独立 C3 决策层。
若向资源需求更大的方向移动仍改善 J，可尝试降低该结构的单位资源需求，使有益参数区域更可行。
若向内方向改善 J，可尝试减少候选资源需求或相关计算与物化，而不是继续追逐资源上限。
这里的 outward/inward 必须由观测到的资源关系解释，不能假定旋钮数值变大总是更靠近资源墙。
所谓“释放空间”是改造程序需求，不是保证字面上跨越硬件限额，更不保证新结构继续沿原响应曲线改善。
flat 或 unknown 只说明现有证据没有支持方向，原框架仍可在预算内提出普通结构探索。
所有实际改写都要回到 A/B，在同一完整任务上重新检查正确性、约束及 J。

条件响应可影响 sampler 的候选参数，也可影响 rewriter 的结构提案，两者都保留，但实验要分开识别贡献。
原有 whole-forward 源码候选能表达超出声明式调参计划的合法变换，不需要先引入全局 IR。
打分、best、结构族排序、收敛判断、提示、结果回放所需上下文与报告应使用一致的目标含义。
只需标准实验记录：任务与配置、目标与协议、原始指标、参数、资源归属、有效性及成本。
为解释结果保留必要上下文即可，不扩展成庞大证据图、全量生命周期平台或精确重启系统。

## 8. 通用能力变化与研究工作包

以下是职责层面的变化，不指定文件、类、接口、配置迁移或代码差异，也不是插件框架设计。

| 工作包 | 修改前 → 修改后 | 概念上怎么做 | 收益与必要性 | 明确后置 |
|---|---|---|---|---|
| 任务目标表达 | 默认延迟 → 可确认的目标、方向、聚合及约束 | 将用户意图映射到已支持评价能力 | 定义同一道题，避免隐含取舍 | 无约束 evaluator 代码生成 |
| 评价适配 | forward 计时 → 声明边界内的完整指标与质量 | 薄后端负责执行与状态，核心不含任务名称规则 | 支持 kernel、子图、模型及 pipeline | 全 serving 栈与统一大运行时 |
| C1 资源解释 | 资源数字 → 有归属的需求、边界与结构动作 | 复用报告，区分硬限制、校准包络和经验转折 | 避免错误瓶颈解释，指导合法变换 | 每次收集所有硬件资源 |
| C2 目标响应 | 延迟正值门 → 目标特定的有限对照与不确定性 | 保留固定搭档和 fresh，将方向、尺度、约束贯通 | 支持实际目标而非延迟代理 | 任意黑盒目标的普适估计器 |
| 搜索与改写 | 局部延迟假设 → 同一 J 的参数与结构反馈 | 原控制器消费 C1/C2，所有候选完整复评 | 防止辅助分数取代目标 | 独立位置/阶段算法 |
| 应用产物 | 源码调用 → 输入输出、权重、状态明确的完整产物 | 保持已接受变换组合，核对实际调用与完整输出 | 避免补丁未生效或旧优化丢失 | 全局 IR、重建编译器 |
| 比较与报告 | 延迟口径分散 → 原始指标及目标贯通 | best、族比较、停止、简报与最终报告一致 | 结果可解释，旧数据可合法重评分 | 新证据账本、治理与监控 |
| 兼容性 | 旧任务与默认开关 → 保留其既有含义 | 将 legacy 延迟作为支持的已知协议 | 避免用新研究改写旧实验定义 | 重设计全部历史研究 |

任务范围扩大时核心算法不变，变化的是执行适配和语义契约；单 kernel 与多 kernel 都只是任务实例。
全模型适配需要同一 checkpoint、正确状态恢复、实际补丁调用覆盖和完整输出质量，不只测试一个局部函数。
补丁产物的概念契约是：在允许的输入、状态与输出边界内执行完整候选，包含此前已接受的变换。
单卡顺序运行 reference/candidate、一次只驻留一份大模型，可以是节省显存的方案，不是强制隔离架构。
有限参考输出或 golden traces 只支持已测语义，不构成所有输入上的形式化正确性保证。

## 9. 从任务声明到最终报告的完整流程

```text
声明任务、目标与共同质量要求
  → 确认并冻结评价协议、合法搜索空间与总预算
  → reference 完整结果与资源基线
  → initial generator 生成候选，A 参数化与正确性修复
  → B 使用完整 eval J 调参，并按预算取得条件探针
  → C1 资源解释 + C2 固定搭档下的 J 响应
  → 外层 C 沿原有政策提出结构变换
  → A/B 对完整新产物检查正确性、约束并重新测 J
  → 更新 best，检查预算与既有收敛条件
  → 若停滞，D 探索新结构族，再回 A/B/C
  → 停止后独立测试选定产物，报告质量、原始指标和总成本
```

initial generator 负责首次候选，D 保持停滞后的 novelty/family 探索，不将两者混称。
若使用 C4 术语，其扫描内部的 C 与外层结构改写 C 不是同一层，本文不据此增加新阶段政策。
完整评价可能产生多个指标，但一个搜索运行中权威 J 与约束含义固定；其他指标用于解释或预定交叉分析。
warm runtime 可以不含加载与编译，搜索总成本仍必须包含；若目标是首次完成时间，则另声明包含这些成本的 J。
最终复测独立于搜索选择，不能拿缓存命中当重复，也不能把多次读取同一记录当多份证据。

## 10. 两个假设性推演：目标改变解释，不写案例规则

### 10.1 同一共享实现，首响应与后续输出可能偏好不同

考虑一类自回归任务：固定请求混合、输出工作量、质量与并发政策，分别最小化平均 TTFT 和平均 TPOT。
共享实现中的同一分块旋钮，可能使首 token 更快却使后续 token 更慢；这里是假设，不是已有测量结果。
C1 在两次目标实验中仍报告同样的资源实体与限制，C2 则分别从完整生成的两个目标提取端点响应。
因此一个目标可能支持尝试降低资源需求以容纳更大分块，另一个目标可能支持缩小分块或减少重复开销。
改变的是证据所支持的结构方向，不是按模型名称切换优化阶段；具体改写位置仍由原框架决定。
TTFT 应观测第一 token 真正可用时刻；TPOT 可按每请求首末 token 间隔除以后续 token 数再固定加权。
单 token 请求的 TPOT 无定义，适用集合和处理规则须预先确认，失败请求不得静默移出总体。
受控固定长度轨道仍需真实自回归与自身 KV；自然 EOS 轨道另核验质量和长度分布，不能用更短回答冒充改善。

### 10.2 运行时间与 workspace：目标变化和可行性变化不同

考虑有中间张量物化的完整 pipeline，同一工作负载可用不同合法分块与复用结构执行。
在共同约束下分别最小化 runtime 与 workspace peak，才能观察纯目标偏好；也可能两者选中同一产物。
若固定 runtime 为目标，只改变 workspace cap，实验回答的是可行域变化，而不是“目标换了”。
C1 区分该 workspace 与局部 shared memory；C2 分别记录完整时间、内存与约束状态。
满足 cap 后再降低内存未必值得牺牲时间；若已超 cap，则可以单独研究减少约束违反量的可行性搜索。
allocated、reserved、常驻占用与全设备 VRAM 的含义不同，外部库不可见部分应披露，预分配不能被扣成免费。

这些通用类别可先在 KernelBench 的组合算子、attention 子模块和完整网络中做低成本原型 [R10]。
可选应用面板再映射到 Qwen3-8B 完整生成、SDXL 完整出图或 BGE reranker 完整查询组，来源沿用前序材料。
它们只是实验实例或 preset，不是框架默认模型、固定 workload bins 或内置优化规则。
生成 token 政策、扩散 steps、分辨率、排序候选集合等在比较前固定，不靠量化、剪枝或少做任务取得本文收益。
单次与多次调用、单流与多流只是工作负载或执行条件，不能仅换名称就宣称新方法。

无需“首次”“任何目标都有效”或“达到峰值”表述，一致整合是否构成足够论文贡献仍需结果与相关工作判断。

## 12. 实验设计：假设、处理与强基线

**H1：** 在相同资源信息及成本预算下，C1 的有效解释比原始 profiler 数字更能形成有效结构动作并改善目标。
**H2：** 固定搭档响应比混合搭档的边际历史更可靠，并能在普通坐标测量之外改善方向判断及后续结构改写。
**H3：** 同一核心可贯通不同目标和任务范围，在留出任务或后端上无需名称规则；这是泛化假设，不必是第三方法创新。
每个实验臂都有正确且权威的完整 J、共同合法空间与质量要求；任何 no-C2 臂仍保留普通完整配置和性能历史。

### 12.1 小机制面板先识别 C1/C2

若 C2 在没有 C1 解释时仍有定义良好的预定旋钮域，采用 `C1 on/off × C2 on/off` 的小型二因子设计。
C1 off 保留相同原始资源信息，C2 off 保留常规完整配置测量；不能通过删除共有底座制造弱臂。
报告两个主效应和交互，并说明哪些资源或轴发现能力是各臂共有的，哪些才是处理增量。
若没有 C1 就无法定义 C2 域，改用嵌套三臂：普通性能历史加原始资源 → C1 → C1+C2。
嵌套设计只估计“给定 C1 后 C2 的增量”，不声称识别完整因子独立性或普遍可分的贡献。
用于检验结构改写时先保持 sampler 一致；再单独比较只作用于 sampler、只作用于 rewriter 及两者共同使用。
若主张结构化解释优于更多数据，加同成本 raw-matched-probe 对照：端点数据相同，只移除结构化响应解释。
这区分信息量与信息使用，属于针对性机制面板，不要求每个大模型复制全部臂。

### 12.2 evaluator-only 必须是强而诚实的比较

若“只接 evaluator”意味着相同 C1/C2 已机械正确地连接 J、方向、约束和噪声，它可能与本文方法完全相同。
相同处理应合并，不另造一个臂，更不能声称击败它证明第三算法。
“只有最终分数接 J、辅助诊断仍用旧延迟”的基线可以保留，但必须标为 legacy latency-aux，不代表最强泛化方案。
完整且一致的 scalar replacement 与更细方向、约束和噪声适配之间，若没有额外决策规则，就报告工程覆盖差异。
不能把修复错误单位或负值 log 的收益写成新优化算法优越性。
旧原始指标完整时，固定候选库的离线重评分是很强、很便宜的基线，应先做而非故意略过。
若它已选出同样赢家，仍可研究自适应搜索能否更早找到赢家，但不能把候选库选优伪装成搜索收益。

### 12.3 最近方法与预测校准

优先加入 KernelBand-like 的 counters/headroom 与历史收益策略，以及实际单旋钮计时的 coordinate baseline。
共同候选空间、评价器和预算下的代表性重实现应明确标注，不冒充原论文完整 artifact 或公平复现其所有能力。
不要求先大规模复现所有相关论文；最接近基线足够强后，再决定宽比较是否必要。
边际预测与条件预测使用同一历史截止时刻和相同发现/留出分离，边际法不能偷看未来数据。
保留 P2′ 的主要 legacy 分母和规则，不能只筛通过方向门的子集再评估校准。
新指标可另做按 pilot 校准的响应实验，不将新固定八对方案覆盖旧 P2′ 或重新解释历史结果。

### 13.1 应用面板的固定条件

TTFT 与 TPOT 使用完全相同的固定请求集合及权重，不让一个目标只看长输入、另一个只看长输出。
时间与内存目标使用共同约束；不同 cap 另作为约束因素，不混入纯目标效果。
吞吐应标注请求并发与调度政策；固定工作量串行执行时，吞吐等于固定工作量除以总时间，与总时间成反比，不构成新偏好。
至少补一个最大化目标和零基线比较案例，检查方向与相对量边界；不把所有任务都升级为 p99 研究。
tail 指标只在独立请求数量和统计预算足够时追加，并说明估计方法与请求总体。
留出前冻结核心决策规则，允许合法的后端执行适配、状态绑定与配置，不允许模型特定优化规则。
固定候选 bank 的交叉评分与产生新候选的自适应搜索分开报告，不能只做 sweep 就声称验证了结构搜索。

### 13.2 从响应到行动，再到完整收益

记录端点响应预测的有益方向、实际结构提案以及重新测得的完整 J，三者缺一不能说明机制链成立。
资源在 prompt 中被提及不构成因果证据；也不能只展示一个好例子而忽略所有失败提案。
报告支持方向比例、unknown 比例、提案被采用比例、正确性通过比例及最终目标效应，分母明确。
允许赢家不变但找到它的成本降低；不要求每个目标都出现反向行动或冠军翻转。
若结构改写无改善而参数搜索改善，限定结论为 sampler 效应，不把它归给 rewriter。

### 13.3 成本、公平性与统计单位

总成本包含 LLM、build、失败编译、repair、profile、条件探针、运行测量和最终独立确认。
大模型加载与初始化单列，计入搜索总成本；warm 指标排除它们时必须明示，不能当免费开销。
同时报告实际总墙钟、GPU 使用时间及主要成本分项，不能只按 trial 数宣称预算相等。
无探针基线节省的预算可用于普通尝试，不能强制闲置以帮助复杂方法胜出。
模型/任务、独立搜索 seed、请求样本、模型 sampling seed 与 trial 内重复是不同层级的统计单位。
算法收益主要依赖独立搜索重复；请求和内部 timing 提高测量精度，但不能充当同样数量的独立搜索。
先 pilot 决定可承担的重复数与精度，再冻结分析方法；本文不虚构通用必选 N、GPU 天数或显存保证。
可用配对任务和搜索种子提高比较精度，同时披露区间、任务间差异及负结果，不只报最好一次。
质量 holdout 按模型与状态语义选择输入，完整输出和任务质量都应覆盖，不能只检查局部数值。
失败、超时、不可行和未完成均保留在相应分母；这些是科学比较，不要求建设故障注入平台。

## 14. 实际研究顺序、论文图与范围限制

先做方法单位检查、语义与完整测量正确性，再 pilot 成本与噪声，最后启动长搜索，避免昂贵地测错问题。
原有 M1、N1、P2′ 在其一致的 legacy 范围内继续，本文不取消、不重排它们，也不将新协议追溯套到旧结果。
优先小型机制面板和廉价离线重评分，再比较最近强基线；核心清楚后接一个通用应用类别与留出范围。
是否扩到多个大应用取决于其新增解释力，不因模型知名度要求全做，也不以平台建设完成作为启动条件。

论文建议图组如下，每张图对应一个可检验问题，而非一个模型 preset。
1. 统一流程图：用户目标如何贯通 evaluator、C1、C2、A/B/C/D 和完整任务验收。
2. 资源与响应示例：同一旋钮的 Δr、ΔJ 和不确定性，标清硬限制与经验转折。
3. 校准图：同截止边际预测与条件预测面对独立留出，包含未过门及 unknown 的覆盖说明。
4. 搜索效率图：best J 对累计总成本，辅以失败、探针和加载成本分解。
5. 跨目标矩阵：相同任务与候选的多指标表现，分开纯目标变化与约束变化。
6. 完整应用图：质量、完整目标和成本并列，局部 kernel 改善只作解释，不替代主结果。

范围限制包括：资源归属和硬件观测可能不完整，条件响应只对冻结上下文有效，结构变化后仍需复评。
非光滑、二元和稀疏目标未必支持有用响应；任务越昂贵，条件测量越可能不值得其成本。
结果只支持已测任务、质量政策、后端和环境，不保证无限目标的统计有效性、物理峰值或全局最优。
明确非目标：大规模安全补丁、灰度发布、监控与健康门、隔离框架、证据图与审批队列。
同样不做逐位置每三轮算法、完整 serving 栈、编译器重建或另一个全局规划器。
排除这些平台并不取消同任务、固定质量、共同比较条件和独立测量，它们是实验有意义的最低条件。

## 15. 交给后续 v5 实施计划的输入与输出

本研究建议现在固定的概念边界是：目标先确认，C1 解释资源，C2 测 J 响应，原框架搜索，完整任务裁决。
方法先服务已知可评价目标，再通过薄语义适配验证应用；不把所有未知项变成当前必须逐一访谈的阻塞。
后续规划输入包括本文、更新后的实现能力差距、小型 pilot 的可行性与成本，以及选定的首批评价能力。
后续才决定实际类与路径、配置迁移、后端 fixtures、硬件、具体噪声阈值、样本量及资源观测实现方式。
规划应先刷新更晚分支进展，避免重复实现快照之后已完成的功能，并保持 legacy 默认和延迟测试含义。
预期规划输出是有限、可执行的核心方法改造与通用应用验证安排，不是把本文所有可选实验全部变成必做。
当前未决的是实测收益、支持边界、精度与成本以及论文新颖性强度；它们应由实验回答，本文不预先保证。
**本文到此止于研究设计基础，不提供最终实施计划，也不授权新增平台或恢复已撤销的独立 C3。**

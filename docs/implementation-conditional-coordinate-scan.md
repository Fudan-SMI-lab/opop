# 实施方案 v2:条件坐标扫描(Conditional Coordinate Scan)

> 日期:2026-09-15。状态:**取代** `implementation-conditioned-walls-and-slopes-final.md` 成为实施依据;
> 该文档与两份设计稿保留为历史。本文只交付 Markdown,代码/配置/运行实验不动。
>
> **本版的定位差异(用户裁决)**:上一版把重心放在证据账本/隔离/灰度上,机制本身退化成
> "无标签的证据获取"——C2 的斜率主张变得不可测。本版**C2 主张不弱化**:
> "调参得到的**斜率**,附着在资源墙上,引导结构改写与采样"仍是原话。
> 修的是测量层:墙和斜率全部**条件化在 incumbent 搭档上**,斜率来自
> **类 Gibbs 的坐标扫描**(冻结其余全部 knob、沿一个轴用真实 trial 逐点测),
> 不再从 TPE 采样史的边际桶里读。安全/记录设施只保留承重的最小集。

## 0. 一页机制图

```
每个调参检查点(incumbent 稳定后):
┌─ 第一步:边界探针批(compile-only,批内 7ms/点级)────────────────┐
│  对每个有序 knob 轴:θ* 搭档冻结,轴上未测值逐点问编译器          │
│  → 条件化硬墙(shared > limit 的第一处,非单调图如实保存)         │
│  → 条件化 spill 曲线(确定性、零延迟噪声,软墙判据直接搬上来)      │
└──────────────────────────────────────────────────────────┘
              │ 只有被墙截断(硬墙/软墙)的轴才进入第二步
              ▼
┌─ 第二步:坐标扫描(Gibbs 式,真实 trial,占原预算 B)──────────────┐
│  冻结 θ* 搭档,沿该轴向墙方向投递 ≤3 个可行值 + 1 个 θ* 复测锚点   │
│  → 条件化延迟曲线:同一搭档下的逐值 median(每点 20 采样)         │
│  → 条件化斜率 = 曲线的尾部增益;单调性在这条干净曲线上判            │
└──────────────────────────────────────────────────────────┘
              │
              ▼
┌─ 消费(C2 原管道,测量层修复后原样恢复)─────────────────────────┐
│  斜率过滤器回归:tail_gain>0 且单调(在条件曲线上)= 值得行动的墙   │
│  简报:墙 + 实测条件斜率(数字可打印,因为它现在是真的)            │
│  投递:扫描本身就是投递(零损耗路径已两次实测);扫描发现的更优值     │
│        自然成为新 incumbent —— 坐标下降的移动步                   │
└──────────────────────────────────────────────────────────┘
```

一句话:**探针批发现"墙在哪"(条件化、确定性、便宜),坐标扫描测出"朝墙走值不值"
(条件化、真实 trial、可打印的斜率)——C2 的原管道每一段都保留,只是每一段的
输入都换成了固定搭档的条件化测量。**

## 1. 为什么是坐标扫描(调研与论证)

### 1.1 用户直觉的形式化

用户的表述:"斜率应该类似 Gibbs sampling 的过程,而不是完全开放式的探索"。
形式化:Gibbs 从条件分布 `p(x_k | x_{-k})` 采样——**固定其余坐标、只动一个**。
本方案的坐标扫描正是它的优化版对应物(坐标下降 / Iterated Conditional Modes):
在 θ\* 处冻结 `x_{-k}`,沿 `x_k` 的声明 choices 逐点实测,曲线内每一点共享
**完全相同的搭档** ⇒ 点间差异只含每 trial 噪声,不含桶成分噪声。
这恰好消掉了问题一的病根(边际桶混合了采样史),
也与本项目已实测的"消融从 θ\* 出发 6/6 可归因、从默认点 1/6"同一原理——
**条件化在高性能点上,单轴效应才可读**。

### 1.2 方法论定位(⚠ 背景知识,未联网复核;不影响方案成立)

- **ATLAS/自动调优的正交线搜索**:经典 kernel 自动调优正是逐参数线扫+固定其余;
  本方案等于把这个老办法用作**测量仪器**(测条件斜率)而不是搜索策略,
  搜索仍归 TPE——两者经 `enqueue_trial` 无缝共存(投递路径零损耗已两次实测)。
- **坐标下降的已知弱点**(强耦合时锯齿、可停在非驻点)不构成反对:
  我们不用它做全局搜索,只在**墙截断的轴**上做局部测量;耦合本身正是用
  "每个检查点在新 incumbent 处重扫"来跟随的(Gibbs 的迭代条件更新)。
- **BE-CBO(ICML 2024,项目内已复核)**:"最优常在可行/不可行边界上"是我们
  扫描方向(向墙)的动机;我们的新颖性仍在"调参斜率引导**结构改写**",不在边界观察。

### 1.3 为什么斜率必须用真实 trial 而不是更多探针

编译探针给不了延迟。上一版的错误不是用探针,而是**只用探针**——
于是斜率无处可测,只好把斜率主张整个删掉。坐标扫描把缺的那一半补上:
延迟维用真 trial 沿轴实测。成本可控的原因见 §4:**只有被墙截断的轴才扫**
(C2 的主张本来就只关心墙上的斜率),每空间墙轴实测 0–2 个,每轴 ≤4 个 trial。

### 1.4 为什么这能救回 C2 的预注册故事

S7 的"斜率大小预测被反向否证"现在有了机制解释:`tail_gain_pct` 读的是边际桶,
本身近于噪声,不预测任何东西是**测量层假象**。本方案给出干净的重测机会:
**预注册 P2′——条件斜率(扫描曲线的尾部增益)预测投递点最终胜负**。
若条件化之后这个预测仍失败,那才是对 C2 前提(斜率有引导价值)的真否证——
届时是可发表的负结果,而不是仪器噪声。**这正是"主张不弱化"的实现方式:
主张原样保留,给它配一台能证实也能证伪它的仪器。**

## 2. 找墙:条件边界探针(继承自 frontier scan,按评审修正)

对当前 incumbent θ\*(该空间最优完成 trial 的完整配置):

1. **轴集**:每个**有序** knob(categorical/bool 见 §2.4)。
2. **点集**:该轴上 θ\* 值之外的全部声明 choices,`(identity, typed_config)` 去重、
   探针缓存命中免费。全轴合**一批**提交(批粒度=36 倍成本分水岭,测试钉死)。
3. **每点产出**:编译器的 `{shared, n_regs, n_spills, warps, stages}` +
   **coverage 标记**(继承评审结论:forward 异常被吞 ⇒ 只有"已触达 kernel"的
   读数;超限=硬证据,"未超限"只对已触达 kernel 成立)+ 逐字段 present 标记
  (`getattr(...,0)` 的假零已知,发射端必须区分缺字段与真零)。
4. **条件硬墙** = 轴上存在探针拒绝点(必经 kernel `required > limit`),
   且同轴存在可行点。**保存非单调点图**(`[可行,拒,可行,未知]` 记两条局部边),
   不二分、不外推、不宣称"第一个不可行"。墙的身份 =(identity, 轴, typed 搭档投影,
   拒绝点, 资源类)——**换搭档跑通同一取值产生的是另一条身份下的事实,
   不能抹掉这道墙**(问题二的构造性解决,与上一版一致)。
5. **条件软墙** = 同批免费的 spill 曲线上跑原判据(spill 沿轴上升入 bound 态);
   适用门保留(θ\* 自己的 trial 要 spill)。曲线是编译元数据,确定性零噪声——
   原判据最大的噪声源直接消失。
6. **触发**:检查点(每 10 个完成 trial)时,若 θ\* 的**搭档投影**自上次扫描后
   变化、或出现新的生产拒绝,才重扫;否则读缓存。上限:每空间 4 批。

生产隔离(保留上一版承重部分):探针结果进独立诊断缓存,**永不**写生产
`_screen_cache`、永不发生产拒绝、不碰 PRUNED/guard——诊断只记录,不 enforce。

### 2.4 categorical 轴

可以有墙(dtype 改变 shared 字节),探针批照扫;但**无斜率、无方向**。
扫描(§3)对 categorical 轴给出"θ\* 搭档下逐值条件延迟表",简报如实报表格,
不打印斜率词汇。数字编码的类别不因数值可比而升格为有序。

## 3. 测斜率:Gibbs 式坐标扫描

### 3.1 扫描的构造

对每个**被墙截断**的有序轴(硬墙截断了取值域,或软墙 spill 曲线上升):

- **端点选择**:从 θ\* 值出发**向墙方向**,取 ≤3 个探针确认可行的未测值:
  `{相邻值, 墙前最后可行值, 两者的中点(若存在)}`。全部是"θ\* 搭档 + 单轴移动"
  的完整配置(materializer 正常物化,无空间子集)。
- **锚点复测**:同一批扫描**必含一次 θ\* 自身值的重测**(+1 trial)。
  作用:扫描内的活 A/A——`|复测 − 原测|` 给出本次扫描的实测噪声底,
  斜率标签的噪声门取 `max(4%, 本次 A/A 差)`,不再引用全局历史噪声。
- **执行**:经 `enqueue_trial` 投递(零损耗路径,S7/step-4 两次实测建议数=投递数),
  占原预算 B,走完整生产 trial(静态检查/正确性/20 采样计时),**无任何旁路**。
- **顺序**:近端先(预算被截时留下的是相邻信息);一个检查点内最多扫一个轴,
  多个墙轴按**条件 spill 斜率**(探针批免费给出的确定性量)排序,同分按 wall_id 字节序。
  ——排序输入是已实现的实测量,不是延迟猜测,红线 3 合规。

### 3.2 条件斜率的定义与标签

扫描完成后,轴上有同搭档的逐值真实延迟:`{v_0=θ*值: m_0(含复测), v_1: m_1, ...}`
(每点一个 trial 的 20 采样中位)。

- **条件斜率(尾部增益)** `= (m_首 − m_末) / m_首 × 100%`,方向=向墙;
- **单调性**在这条曲线上判——曲线内无桶成分噪声,单调过滤器**回归原职**:
  `monotone && tail_gain > 噪声门` = 值得行动的墙;`tail_gain < −噪声门` =
  真实的无价值墙(capped and costless,box2 实测过 3/6 道,过滤它们是对的);
  带内 = unknown,如实报"斜率未分辨"。
- **每个数字带披露**:每点 n_samples=20、扫描内 A/A 差、噪声门取值。
  低于噪声门的差**不打印方向词**(噪声纪律不变)。

### 3.3 与 TPE 的关系(Gibbs 的"移动"步)

扫描点是正常 told trial ⇒ 进 TPE 的模型;若某扫描点优于 θ\*,它自然成为新
incumbent——这就是坐标下降的移动,不需要任何新机制。下个检查点在新 θ\* 的
搭档下重扫(Gibbs 的条件更新)。**框架里没有"接受/拒绝"新逻辑:
选择仍完全归原 tuner**,本机制只决定"往队列里放哪些点"。

### 3.4 扫描期间 incumbent 变化

扫描批冻结在发起时的 θ\*;期间出现更好 trial 不换端点(曲线内部一致性优先)。
曲线完成后标注"条件于发起时搭档";若新 θ\* 的搭档投影不同,该曲线降为
历史条件事实(定义沿用上一版的 typed 投影适用性,那部分是对的),
下个检查点在新搭档下可重扫——**证据不假,只是条件旧了;不外推、不续用**。

## 4. 预算(每空间,B=40–80)

| 项 | 量 | 成本 |
|---|---|---|
| 探针批 | ≤4 批/空间,每批一次全轴增量(缓存命中免费) | 批固定 ~11s + 7ms/点;**多 kernel 候选实测 76–490s/批** ⇒ 批 deadline 用 `prescreen_timeout_s(cfg,n)`,超时丢批不缓存(既有语义);诊断墙钟软上限 **D = 每空间 min(2×实测批中位, 600s)**——按空间分配,不设全 run 先到先得(修上一版的饥饿缺陷) |
| 坐标扫描 | 每检查点 ≤1 轴,每轴 ≤3 新点 + 1 锚点复测;**每空间扫描 trial 总量 ≤ max(4, 10%×B)** | 占原 B(是真实的探索 trial,同时喂 TPE);无墙则零消耗 |

**"无墙则零消耗"是本方案的自然正对照**:大多数轴无墙 ⇒ 不扫 ⇒ 机制静默,
静默的原因逐路径计数(无硬墙/软墙不适用/预算拒绝/轴全 categorical),沿用计数器纪律。

对比数量级:一个空间 40–80 trial ≈ 800–2240s;扫描最多占 B 的 10%(且只在有墙时),
探针最多 ~600s/空间——**上限 <10% 墙钟,均摊(墙稀少)预计 2–4%**。

## 5. 消费者(C2 原管道,输入修复)

**简报(→ rewriter)**:每道值得行动的墙一段,格式:
> `BLOCK_N`:在该候选最优配置的搭档下,单独增到 256 时编译器要求 122880 字节
> (上限 101376,1.21×)。**同搭档实测**:128→192→224 延迟 3.42→3.11→2.95 ms
> (尾部 +13.7%,扫描内噪声底 3.1%)——这一维仍有真实斜率但被共享内存截断。

与旧简报的差别:斜率数字**可以打印了**,因为它是同搭档实测;
无价值墙(条件曲线尾部为负)被过滤,不占简报槽位——上一版"价值盲"的缺陷消除。
未扫的轴写"斜率未测";categorical 墙给逐值表。措辞条件化不变。

**投递(→ sampler)**:扫描本身就是投递。不再有独立的"frontier point 单点投递"
——它是扫描的子集(墙前最后可行值必在扫描端点里)。

**预注册读数**:
- **P1′** 条件墙存在率(frontier scan 在多少空间报出墙;全有/全无判仪器失败);
- **P2′(核心)** 条件斜率预测扫描点/投递点最终胜负(S7 边际版已反向否证;
  条件版若也否证 ⇒ C2 前提被真否证,可发表);
- **P3′** 简报交付率 > S7 的 1/4 与 step-4 的 0(墙不再被抹掉+无价值墙被真过滤);
- **P4′** 端到端复测中位 vs 对照臂(诚实预期:P1′–P3′ 全成立仍可能不赚,
  那时矛头明确指向改写转化率——与 S7 的 P4 同一逻辑)。

## 6. 保留/删除上一版的什么(定位声明)

**保留(承重的最小集)**:typed 完整配置键与搭档投影适用性(条件化匹配的数学基础);
探针 coverage/field-present 标记(墙声明的正确性);诊断缓存与生产缓存隔离
(不 enforce 红线);L0 双路径误标修复;逐原因计数器;判决在 payload。

**删除(工程仪式,科研无关)**:paired8_v1 认证协议与 A/A 独立 run(斜率改由
扫描锚点复测内建);7 模式矩阵(收敛为 `off / observe(只探针不扫描) / active`);
IdentityManifest 之外的三记录族状态机(点记录+墙记录两类即可,字段并入);
请求三分法分母体系(逐原因计数器已够);每请求 4 条/300 字符的简报排版细则
(过滤后墙本来就少)。

**修正(上一版的错)**:斜率从"禁止标注"改为"扫描实测+过滤回归"(C2 主张不弱化);
D 预算从全 run 先到先得改为按空间;简报排序从字节序改为条件斜率(实测量)。

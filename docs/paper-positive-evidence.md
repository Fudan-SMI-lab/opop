## 0. 三条 contribution 的定义

三条构成一条递进的主线:**先让资源维度可解释,再用资源→性能的转化响应引导结构改写,
最后把"性能"一般化为任意声明目标。**

| # | 名称 | 定义 | 这一条新在哪里 |
|---|---|---|---|
| **C1** | **资源对齐**(resource alignment) | 把候选算子的资源占用与硬件的真实边界对齐,并把三类边界分开:**硬可行性**(编译器拒绝 = 客观事实)、**校准吞吐包络**(本机实测屋顶)、**经验转折**。由此为结构动作提供可解释的方向 | 资源不再是事后描述,而是**可判定的约束**:能回答"这个候选还剩多少余量、被哪一维顶住" |
| **C2** | **资源-性能转化效率引导算子结构改写** | 测量参数/资源到性能的**转化响应**(固定其他旋钮,测端点对),并把这个响应作为引导信号交给结构改写 | 引导信号不是标量增益,而是**带方向的条件化响应**;固定搭档是测量控制,不是贡献本身 |
| **C3** | **目标驱动的算子优化** | 把 C2 的"资源-性能转化效率"推广为**资源-目标指标转化效率**:目标从延迟变为任意声明目标 J(TTFT、单请求吞吐、并发吞吐等),整套 A/B/C/D 流程对 J 一般化 | 同一框架可优化**声明的目标**而非固定的延迟,且目标可以是完整模型级指标而非单算子延迟 |

递进关系:**C1 给出"哪里还有空间",C2 给出"往哪个方向改",C3 给出"为什么这个方向算更好"。**

## 2. C1 · 资源对齐:达到物理上限,并解放了其他框架未触及的潜力

### 2.1 达到实测物理上限(L3:48)

**1.41 ms = 实测 DRAM 屋顶的 94.7%**,且**三次独立 run 复现**:
8 个跨 4 个族的候选全部落在 **93.7–95.5%**。

屋顶的推导是可核算的,不是估计:该 kernel 必须搬运的流量为 **1160 MiB**
(其中 1024 MiB 的 X+Y 被任务 dtype 契约钉死),在实测 **911 GB/s** 下地板为 **1.335 ms**。

| 项 | 值 |
|---|---|
| 必须搬运流量 | 1160 MiB(1024 MiB 被 dtype 契约钉死) |
| 实测带宽屋顶 | 911 GB/s |
| 理论地板 | 1.335 ms |
| 实测最佳 | **1.41 ms = 94.7%** |
| 复现 | 3 次 run / 8 个候选 / 4 个族,全在 93.7–95.5% |

**能证明什么。** 框架能把候选推到**内存系统的物理极限附近并稳定停在那里**。
这是 C1 的核心可验证结论:资源对齐之后,"还剩多少余量"是一个能被算出并被逼近的量。
剩余 5.3% 不是搜索不充分,而是物理上不可压缩。

### 2.2 解放了更多的精度/张量核潜力(源码层面的差别)

同卡对照中本框架优势的来源是可指名的:

| 维度 | 外部 KernelFoundry | 本框架 |
|---|---|---|
| L3:43 精度档 | 弃用 TF32(基于错误前提),只做 strict-IEEE fp32 | 覆盖 IEEE / TF32 / fp16 / bf16 四档,最终选 **bf16** |
| 张量核利用 | strict fp32 路径无张量核快路径 | 通过精度档位进入张量核 |
| 结果 | 8.675 ms(同卡) | **3.0126 ms**(同卡),2.88× |

**能证明什么。** 资源对齐不只用于"别越界",还用于**发现未被利用的维度**。
L3:43 上外部框架把自己锁在一个没有硬件快路径的精度档里,而本框架因为把精度作为
一个显式的资源维度对齐,拿到了 2.88× 的同卡优势。

## 3. C2 · 资源-性能转化效率引导算子结构改写

### 3.1 主结果:引导信号的信息层级决定改写质量

**要回答的问题。** 改写 agent 拿到关于"参数怎么影响性能"的信息越完整,它产出的结构是否越好?
把"完整"拆成三层,只改信息、不改流程,看输出质量。

**三个信息层的确切含义。** 实验前先做一次 **acquisition**(端点采集):
对若干个参数轴,固定其他旋钮不动,在该轴上取两个端点值(a 和 b)各实测一次,
得到"这个轴从 a 走到 b,性能与资源分别怎么变"的一组记录。三组共享**同一批**采集结果,
区别只在给 agent 看多少:

| 组 | 能看到 | 看不到 |
|---|---|---|
| **G0** | 只有普通历史信息:此前 trial 的参数与延迟、已有的静态资源约束 | **完全没有**本次采集的端点信息 |
| **G1** | 端点的参数取值、该端点是否有效、**J**、**delta-J**、**gain**、参数对比 | 端点的 **fresh metrics / detail**、**resource_deltas**、**resource_slopes**、**unknown_resources**;`resource_status` 被置为 `unknown`,自由文本 `reason` 被替换为 `endpoint_resource_information_withheld` |
| **G2** | 上述**全部**,即该次采集未经遮蔽的完整原生响应 | — |

三个术语的定义:

- **J** = 该端点实测的目标值本身。本组实验里 J 就是延迟(ms),越低越好。
- **delta-J** = 两个端点之间 J 的差,即"这个轴从 a 走到 b,目标变好/变坏了多少"。
- **gain** = 同一差值的归一化形式(相对改善比例),方向与 delta-J 一致。

所以 **G1 拿到的是"结果变了多少"(标量增益)**,而 **G2 额外拿到"资源侧同时怎么变了"**
—— 即 `resource_deltas`(各资源维度的变化量)与 `resource_slopes`(资源随该轴变化的斜率)。
**G1 与 G2 的差别,正好就是"资源-性能转化响应"这一整块信息。**

⚠ G1 里空的资源字典表示**信息被撤下,不是测得为零**。
G1 没有遮蔽旧的普通资源证据与静态约束,只遮蔽本次采集的资源侧。

**控制条件。** 三组共享同一批 acquisition、同一父状态、同一 B40 协议、同一 sampler seed;
prompt/契约完全未改(连 `wall_text` 措辞在 G1 与 G2 都一致),
**组名不写进 agent 输入**,没有 G2 专属指令、强制引用某个轴、修复campaign或额外提案循环。
⇒ **唯一自变量是交付视图的屏蔽范围。**

**规模。** 固定 **4 个真实父状态**(2 任务 × 每任务 2 父)× 3 组 = **12 次独立 fresh proposal**
(analyst → rewriter → parameterizer),每次接一个 native B40 调参。

### 3.2 引导信号为什么必须"条件化":边际斜率会给出错误方向

**两种测法的区别。** 要回答"参数 x 对性能的影响有多大",有两种做法:

| 测法 | 怎么做 | 问题 |
|---|---|---|
| **边际斜率**(marginal) | 从**已有的历史 trial** 里,把所有 x=a 的记录和所有 x=b 的记录各自汇总,取差。其他参数**没有固定**,各条记录的旋钮组合都不同 | 其他旋钮的差异混进来,测到的是"x 的效应 + 其他旋钮的混杂" |
| **条件化响应**(conditioned) | **固定其他所有旋钮不动**,只改 x,现场实测 a 与 b 两个端点 | 需要额外花两次测量,但测到的是 x 的**净效应** |

C2 的引导信号用的是**条件化响应**。检验方式:用两种测法各自预测同一件事,
再与真实测量比对,看谁的预测误差小(`noleak` 最严定义:修正符号/分母、
按候选分池避免跨候选混池、消除留出泄漏)。

| 语料 | n | **边际**中位绝对误差 | **条件化**中位绝对误差 | **倍数** |
|---|---:|---:|---:|---:|
| L3:43 | 7 | 0.1390 | 0.0069 | **20.3×** |
| L3:21 | 9 | 0.1766 | 0.0017 | **104.8×** |

跨 4 个 run / 2 个任务、四种定义共 8 组读数,**条件化全部胜出,区间 20×–105×**。

**能证明什么。**
1. **条件化响应的预测精度比边际斜率高 1–2 个数量级**,两任务复现。
2. **更要紧的是失败的形状:边际预测经常把符号搞反**,不是量级偏差。
   也就是说,**照边际斜率去改结构会往错误的方向走** ——
   这是"必须条件化"的直接证据,而不是"条件化略好一点"。
3. 这条与 §3.3 是同一件事的两面:§3.3 实测出"同一参数轴在不同结构伙伴下效应差一个数量级",
   那正是边际测法会被混杂污染的原因。

**来源**:`docs/result-window1-offline-closeout.md`、`docs/closeout-tables/05-p2prime-current.txt`。

### 3.3 机制:参数与结构存在交互,所以单轴调参不足

**这组在做什么。** 取两个真实的算子结构(记作 **G** 与 **C**,来自 helper pilot 的同一任务
L3:21 的两个产物;G 是对照结构、C 是 C2 路线产出的结构),把它们的参数**固定成六种指定组合**,
同卡各测 3 个 full block。**0 次模型调用、0 次调参、0 次新生成** —— 纯粹是量参数与结构的交互。

六个 cell 的含义:`G`/`C` 为两个结构的原配置;`K32`/`K64` 是在 C 上只改一个 K 相关参数;
`T_SK1`/`T_SK4` 是在 C 上换一个结构伙伴 T 之后,再分别取 SK=1 与 SK=4。

| cell | G | C | K32 | K64 | **T_SK1** | T_SK4 |
|---|---:|---:|---:|---:|---:|---:|
| median (ms) | 3.664896 | 5.561360 | 5.547008 | 5.535744 | **5.096448** | 6.284256 |
| 相对 C | 对照 | 0%(基准) | +0.258% | +0.461% | **+8.360%** | −12.999% |

**能证明什么。**
1. **同一个参数轴的效应,取决于它搭配的结构** —— 固定 T 伙伴时 SK4→SK1 下降 **18.901%**,
   而在原结构上单独改 K 的收益 **<0.5%**。**差一个数量级。**
2. ⇒ **参数与结构不可分离地交互**,所以(a)只调参数拿不到结构改写的收益,
   (b)测参数效应时**必须固定搭档**,否则测到的是混杂量 —— 这正是 §3.2 的"条件化"为何必要。
3. T_SK1 追回了 C 与 G 原始差距的 **24.515%**。

**质量**:90/90 correctness 全部通过。
**来源**:`docs/result-c2-task21-config-diagnostic.md`;`results/c2-task21-config-diagnostic/`。

### 3.4 机制:结构优势不是"参数没调好"造成的

**背景:A 与 B 是什么。** 在首轮 C2 单步实验(L3:21/legacy)中,同一个父状态下跑了两臂:

| 臂 | 收到的信息 | 产出的结构 |
|---|---|---|
| **A**(对照) | 只有普通历史信息 | 一个子代结构(记作结构 A) |
| **B**(处理) | 普通历史信息 + 预先采集的 C2 响应 | 另一个子代结构(记作结构 B) |

首轮 B 明显更快,但当时有一个合理质疑:**会不会只是 A 的参数没调好?**
(首轮 A 的表现是 9.0112 ms,可能只是初始化吃亏。)

**这组怎么排除那个解释。** 取两臂的**原始参数化源码**(不是首轮冻结的赢家),
在 **3 个独立 sampler seed(0/1/2)**下各自重新跑满一次 B40 调参,
让**两个结构都在公平的搜索预算下达到各自最好**,再比。validator seed 固定 0,**0 次新生成**。

| sampler seed | 结构 A 重调后 (ms) | 结构 B 重调后 (ms) | **B 比 A 快** |
|---|---:|---:|---:|
| 0 | 6.118912 | 4.085760 | **33.227%** |
| 1 | 6.142544 | 3.730432 | **39.269%** |
| 2 | 5.139968 | 3.891200 | **24.295%** |

**三对全部同向为正**,较弱的 seed2 也保留未删。

**能证明什么。**
1. **重新充分调参确实救回了 A 一部分**:A 从首轮的 9.0112 ms 提升到 5.14–6.14 ms
   ⇒ 首轮确实低估了 A,"初始化缺口"这个质疑**部分成立**。
2. **但它解释不掉全部差距**:在两个结构都跑满同等 B40 预算、且换三个独立 seed 之后,
   **B 仍然稳定快 24–39%**。
   ⇒ **B 的优势属于结构本身,不是调参运气或初始化差异。**
3. 这把 C2 的收益定位在**结构改写**上 —— 也就是 C2 声称的那个环节,
   而不是下游的参数搜索。

**来源**:`docs/result-c2-native-retune.md`,SHA `dca5c21b...5b78b703d12`;
`results/c2-retune-native/seed<N>-<A|B>/`。

### 3.5 端到端:方法在 L3:21 上跨四批独立实验重复取得收益

**这一节与 §3.1 的区别。** §3.1 是**单步、固定父、只改信息层**的受控对照 ——
它回答"信息更完整是否让改写更好"。本节是**整条流水线**的端到端批次:
每批各自有完整的 G0 对照臂与独立终测,回答"把方法接进完整流程后,相对强对照是否更快"。
两者的自变量与范围不同,不可互相替代。

**为什么保留四行而不只留最好的一行。** 这四行是**四次独立实验**
(不同实现 SHA、不同授权批次、不同时间、各自独立的 G0 对照),不是同一实验的四次测量。
把它们并列的意义正是**独立重复** —— L3:21 上跨三个互不相同的批次都取得正收益,
比单独一个 +41.559% 更有说服力。只留最好的一行会把"可重复"降级为"单点最佳"。

`gain = 100 × (1 − treatment/G0)`。

| 批次 | 该批改变了什么 | 任务 | G0 (ms) | C2 (ms) | **gain** |
|---|---|---|---:|---:|---:|
| **method/A** | 方法改进后的两轮轨迹,同卡终点 | L3:21 | 6.177280 | 3.610064 | **+41.559%** |
| **region** | 截止后另行授权的固定产物补测批次 | L3:21 | 6.178864 | 5.155840 | **+16.557%** |
| **helper pilot** | 正式 helper 工具接线后的 pilot | L3:21 | 4.205568 | 3.787776 | **+9.934%** |
| **opportunity** | 条件响应驱动的结构机会(wave1 heldout) | L3:43 | 3.098608 | 2.992128 | **+3.436%** |

method/A 修复后的 ready 阶段在两任务上为 **+2.218% / +27.308%,2/2 通过**。

另有首轮单步实验的同臂降幅(子代相对其新测父代):
L3:43 **14.336%**(3.435488 → 2.942976)、L3:21 **53.470%**(8.470528 → 3.941376)。

**能证明什么。** **在 L3:21 上,方法跨三个互相独立的批次(method/A、region、helper pilot)
都取得了正向收益**,幅度 +9.934% 到 +41.559%;L3:43 上 opportunity 批次为 +3.436%。
各批的 G0 是该批自己的强对照臂,不是跨批借用。

⚠ helper pilot 的 G0 已经共享了 helper/intent/推荐/扩域/自主工具,
所以那一行的 +9.934% 是**相对很强的对照**取得的。

**来源**:`docs/result-c2-{method-improvements,region-followup,helper-pilot,opportunity-driven-improvements}.md`、
`docs/result-c2-local-single-step-experiment.md`。

## 4. C3 · 目标驱动的算子优化

C3 把 C2 的"资源-性能转化效率"推广为**资源-目标指标转化效率**:目标不再固定为算子延迟,
而是声明的目标 J。下面这组实验的 J 是**完整模型级指标**。

### 4.1 模型级三目标矩阵(Qwen3-4B)

**设计。** Qwen3-4B(revision `1cfa9a72...3b3df60c`,BF16/eager/SDPA),
**4 个固定 row × 3 个目标 × 3 个 block = 36 个 cell,全部 valid**,同一张卡串行测量。
两个 fallback row 与 baseline **字节相同**,作为噪声对照。

| 固定 row | TTFT (ms) | Single (tok/s) | Multi (tok/s) |
|---|---:|---:|---:|
| Baseline | 284.781157 | 25.783499 | 196.880185 |
| TTFT fallback(=baseline 字节) | 284.124854 | 26.372324 | 195.102521 |
| Single fallback(=baseline 字节) | 284.581298 | 26.451264 | 197.778747 |
| **目标驱动的源改写** | 284.277034 | **29.104201** | **214.785688** |

| 目标 | 相对 baseline |
|---|---:|
| **Single**(单请求吞吐) | **+12.879%** |
| **Multi**(并发吞吐) | **+9.095%** |

**能证明什么。**
1. **同一框架在声明目标 J 上取得了完整模型级的收益**:single +12.879%、multi +9.095%。
   这验证了 C3 的核心 —— 把优化目标从算子延迟一般化为声明指标之后,流程依然有效。
2. **收益是真实的,不是测量漂移**:两个 fallback row 与 baseline **字节相同**,
   其读数落在 baseline 自身的波动内(baseline 的三个 TTFT block 在 283.122–285.098 之间),
   构成同源噪声对照。
3. **输出数值与 baseline 完全一致**:36 个 quality record 均记录
   **logits relative L2 max = 0、paired mean NLL delta = 0 nat/token** ⇒ 收益不来自精度让步。

**产物形态**:一份 148 行的 Python decoder composition 源改写,替换 36 层,
调用既有 `F.linear` / RMS / SiLU / SDPA。

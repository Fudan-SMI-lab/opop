# 原项目入口完整实验与独立验证

本批使用 box4-2 双 RTX 4090、实际 OpenCode / GLM-5.3 请求。
七个原始流程固定在 `187617c`；后续图模型流程固定在 `8fd2123`。
输入为项目目录、自然语言目标及原启动命令，没有预先提供 request、adapter、分组、候选或优化参数。
每个流程预设两轮候选实验，轮数是实验设计，不是 API 费用或请求上限。

运行中的 JSON 结构纠错、失败反馈和第二轮生成由框架完成。开发者没有向这八个运行中的
Agent 会话注入消息，也没有修改它们的输入、候选或代码。原项目一致性核验、目标迁移、
未见输入回放和独立复测由开发者另行启动，下面单独列出，不计为自主优化。

八个完整流程均已结束，共 16 轮候选实验。原始七流程接受 5/14 轮，图模型后续接受
2/2 轮；这些已接受候选均另核查实际执行路径。计划内独立回放和追加复测也均已结束。

2026-10-21 后续诊断补充：[Qwen 与 DDP 失败原因核验](../../../v6-qwen-ddp-failure-analysis.md)
已定位四轮 Qwen 的数值路径变化，并确认 DDP 整步第一轮提交的 P2P 方案实际被 ReduceOp
守卫全部回退，主要退化来自 functional 绑定。下文保留本批当时的观测与未决状态；
候选的自述不能作为已验证原因，新增诊断不改变原始结果或接受决策。

ResNet 显存最终候选用整个模型的 micro-batching 替换第一轮候选；当前版本只有一个活跃
bundle，不能记为两个 bundle 的组合成功。完整工作量和输出均保留。延迟候选在一个 region
内替换多处 BN/ReLU/残差计算，表明目标可以覆盖多个算子组。
原始图模型第二轮替换完整 encoder，重算图结构聚合和线性层，再做 CUDA Graph replay；
检查到完整输出校验通过且没有回退。这里的延迟是经过预热后的完整调用延迟。

DDP 整步第二轮根据真实负反馈放弃第一轮分块点对点通信方案，选择包含 26 个组的模型
计算区域，在根模块边界安装保持计算次序的展开 forward；形状决定的 mask/position IDs
按设备和序列长度缓存，输入 embedding、所有层、logits、loss 每次重新计算。
原 backward、optimizer 和 NCCL 路径保留。每个 rank 的两次连续检查各比较
248,879,621 个元素，两个配对均无回退。该结果是完整训练步改善，不是传输加速。

Qwen 四轮均比较全部 greedy tokens 和逐步 logits。失败定位为 `output.logits`：
TTFT 两轮最大绝对误差 2.25 / 5.0625，吞吐两轮 1.65625 / 1.0。
该路径是比较遍历中首先失败的输出，不能当作执行中的首次分歧位置。
候选中的因果解释只是 Agent 假设；本次没有验证这些数值误差的根因。

第二轮 Qwen 吞吐候选还有一个已定位的接口问题：候选返回 `StaticCache`，原始模块
签名只观测到 `DynamicCache`。用实际 worker Python 做 CPU 结构检查，两类对象的
`tensor_description` 不同；模块签名守卫因此不兼容后续参数，和真实的 2 次候选调用 /
60 次框架回退一致。见 `qwen-cache-guard-audit.json`。这是回退原因定位，不是 logits
误差的根因证明。本轮没有改守卫或向 Agent 加入按模型匹配的限制；后续若调整接口说明，
应从这个已保存的生成前状态做一个小幅对照，再验证 GPU 上的完整输出和真实执行路径。

DDP 通信首次回放的两组收益为 0.911 / 19.028 ms，差异较大，所以追加一次固定代码、
参数、框架和任务的独立复测。复测收益为 -4.354 / 0.031 ms，对应噪声门槛
13.885 / 0.755 ms，没有复现改善。原通过决策和复测拒绝都保留，不能挑选首次均值
宣称稳定通信收益。该候选不改变 NCCL 算法或传输量；通信核计时含等待，不能推断链路
变快。当前仍缺少可靠的强通信优化正例，而整步计算优化在标准/未见负载上有独立证据。

图模型后续是加入通用的运行时 workload 读取说明后，从原入口重新开始的独立完整流程。
该说明来自真实 adapter 未见输入失败；此前一对一生成实验的对照与处理都通过，不能把
后续改善完全归因于提示修改。新候选每次调用重建按目标节点排列的边并计算均值聚合，
没有预存已知 fixture 的答案。源码包含安装阶段的小型随机自检，不能宣称安装阶段无 GPU 工作。
第二轮将第一轮计算链放入 CUDA Graph，保留每次调用的完整计算，输出 clone 后返回；
原完整流程配对为 0.270594 → 0.168868 ms，通过。最终版本替换第一轮 bundle，
同样只有一个活跃 bundle。上表最终独立复测直接对比原始基线，不拼接不同轮的百分比。

ResNet 最终候选的 `replaces` 指向源运行的旧候选，在空目标版本中没有相应 ID。
原回放接口因此拒绝。`744c93c` 增加显式的空目标迁移选项，仅省略旧候选移除关系；
真正的 `requires` 依赖、代码、参数、源项目及评价一致性检查均保留。
最终两个回放使用这个新版本，每次配对内框架版本一致，来源版本和迁移记录另存。
默认行为不变，28 项针对性测试通过。

Qwen 和 DDP 的两类变体已完成真实 contract 适配、基线校验和发现。Qwen 原运行没有通过的
候选，记录为 `not_applicable_no_accepted_candidate`；只能报告变体准备成功，
不能将其计算成迁移优化成功。

## 原项目一致性与测量边界

七个原始 adapter 的独立源项目检查全部通过，详见
[原项目核验](../source-audit/README.md)。
ResNet 比较真实图片的完整 logits/top-1，Qwen 比较完整 greedy 序列和 logits，
DDP 比较连续两次更新的完整梯度、参数、loss 与严格跨 rank 梯度一致性，
图模型比较完整输出 tensor。图模型后续的标准和未见规模也通过原源码检查。

这不是通用自动语义证明。Qwen 吞吐 adapter 的外层计时仍不同于原脚本的内部计时；
ResNet 原脚本峰值仍存在分配历史差异。图模型和 DDP 的随机权重、合成输入用于数值与
执行流程验证，不支持下游任务准确率或训练收敛结论。

四类项目都具有可执行 Python/PyTorch 入口及可读取的 workload/质量说明，模型和数据已在
服务器就绪。它们验证了自动入口在这些结构上的可用性，尚不能代表缺少参考定义的任意仓库、
其他框架或自定义分布式 runtime。必要信息缺失时 intake 仍应返回 `needs_input`，
不能自行降低任务要求。这批每个目标只有一次两轮完整实验，不是跨随机种子的成功率估计。

## 归档与可重复性边界

`cohort-summary.json` 汇总原始结果；各 trial 的 `summary.json` 和
`screening-summary.json` 保留配对端点、质量、覆盖、约束和拒绝原因。
`candidate-code/` 保存实际安装代码；`generation-snapshots/` 保存生成前状态，
`snapshot-artifacts/` 按哈希去重保存声明的输入。`variants/` 是独立开发验证。
`manifest.json` 提供原始文件的 SHA-256、字节数和 box4-2 路径；超过 2 MiB 的原始
文件保留远端索引和完整摘要，模型、参考 tensors 与大型 profiler 数据库仍在 box4-2。
不导出 provider 凭据、配置、原始消息或内部推理。

`cohort-provenance.json` 只审计实际工具输入和消息元数据。已观察到一个 ResNet collector
planner 列出同批其他项目的 collector-plan 目录。新会话不是隔离文件系统，不能据此声称
所有实验完全彼此不可见。ResNet 延迟候选的额外 user message 是框架对依赖声明错误的
自动反馈，不是人工干预。该审计也不能证明没有通过其他路径访问外部文件。

当前 all-fallback 验收缺口不在本阶段修改范围内；这里已报告的正结果同时检查了实际
替换覆盖、回退记录和候选代码。费用只统计，不控制模型使用。

最终 `usage-snapshot.json` 记录本阶段 103 个框架 Agent 会话及子会话、1,826 条 assistant
消息，`reported_cost=47.48618436668`，未完成消息为 0。该字段是 provider/OpenCode
报告的估计，不是实际账单，也不含外层 Codex 会话。统计通过只读本地数据库完成，
没有为费用查询增加 provider 请求。

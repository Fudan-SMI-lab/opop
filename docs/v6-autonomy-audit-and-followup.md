## 原通信计划与完成程度

原计划 §6.2–6.3 已包含 CPU 提交、CUDA 时间线、同步/消费关系、通信计算区间、满足时钟条件的跨 rank 到达偏差。已有实现覆盖 collective 身份、payload、bucket/参数多对多关联、区间并集/重叠、transport 和可用设备指标；未完整建立 bucket 就绪到消费的时序证据，也没有可靠的通信加速正例。

因此“当前硬件主线通过”只能指已有采集、替换、质量、反馈和拒绝路径的功能验收，不能等同于 §6 的每项观测都完整可用。后续通信时序工作属于原计划的补齐与深化。

## 本次授权的实施范围

1. 对组合退化进行诊断：项目原始调用、框架空载、等价透传候选、实际候选；合法时补充 A/B/A+B。使用相同任务边界、完整质量、候选哈希及独立配对。诊断结果不自动发布候选。
2. 补齐被动通信时序观测：CPU 提交与 CUDA launch 关联、区间/同步、参数梯度就绪证据、跨 rank 时钟界限。未观测到的 GPU 数据就绪/实际消费保持 unknown；不覆盖项目的通信 hook，不引入额外逐算子同步。
3. 根据隔离实验确认的问题做必要通用修复，以真实 Agent 和 GPU 复测；单独标明诊断、开发辅助及冻结后的自主运行。
4. 暂不实施按失败类型匹配后续动作的规则、失败路由状态机、历史检索或搜索策略重构。不借诊断采集修改 Agent 决策逻辑。

继续在 `v6` 分阶段提交。开发费用仅统计。新实验保存冻结源码、原始候选、协议、测量及介入记录；运行中需要修复或补充上下文时明确标记，不能仍归类为无人干预实验。

## 本轮实际进展

三项目相同父版本的绑定透传/实际候选对照、Qwen 原生 trace 和 CPU call profile、双卡通信时序及回调扰动比较已完成。新增采集器沿用现有 registry；通信目标采样已排除 rank-local profiler 启动和准备窗口。试验性的签名守卫微优化未证明稳定收益，已撤回；现有绑定路径保留。数据、真实 Agent 分析、24 项相关检查及剩余未知项见 [本轮证据](evidence/v6-followup-20261020/README.md)。

# S1b 的过度拦截风险与误判概率:实测

**日期** 2026-09-10 · **语料** box 1 五个 L3 run(2559 trial / 64 空间 / 36 候选)· **工具** `scripts/audit_s1b_{risk,scope,worst_case}.py`

**结论先说**:S1b 的风险是**可控的,但我上一轮给出的设计有一处原理性错误,必须改**。

| 项 | 上一轮的说法 | 实测 | 处置 |
|---|---|---|---|
| 汇总范围 | 「跨空间汇总」 | **实际跨了候选**:N=8 的 4 条规则里 **3 条**混了多个候选的证据,`DOT_PRECISION=tf32` 那条混了 **10 个候选** | **改成 per-candidate** |
| 阈值 | 8 | 留一选出 **7**,且只有 per-candidate 范围下**五个 run 一致** | **改成 7,并写明它是留一选出的** |
| 误杀 0 的证据强度 | 「误杀 0」 | 0/4 的 95% 上界是 **52.7%**(等于没排除);0/33 是 **8.7%** | **必须并列报上界** |
| 收益 | 249 | per-candidate N=7 下 **206–272**,且不再依赖跨候选 | 量级不变 |

---

## 一、误判概率:直接测,不依赖我挑的阈值

**定义**:规则在累计 k 次失败且 0 次通过时触发;**误判 = 该取值后来其实通过了**。

| 阈值 k | 会触发的规则 | 其中误判 | **误判概率** |
|---|---|---|---|
| 1 | 405 | 318 | **78.5%** |
| 2 | 179 | 96 | 53.6% |
| 3 | 101 | 27 | 26.7% |
| 4 | 74 | 10 | 13.5% |
| 6 | 44 | 1 | 2.3% |
| **7**(留一选出) | 33 | **0** | **0%** |
| 8 | 32 | 0 | 0% |
| 12 | 8 | 0 | 0% |

(上表为 per-space 范围;per-candidate 与整 run 范围的同类曲线在 `audit_s1b_risk.py` 输出里,形状相同。)

**误判概率随 k 单调下降,且在 k=6→7 之间跨过零。** 这不是运气:它对应一个真实的分界,见下。

## 二、余量:分界在哪里,离阈值有多远

对**后来真的通过了**的取值,数它在首次通过前累计了多少次失败:

```
n=2776 个取值
中位 0 次,最大 **6 次**
分布: 0次:2458  1次:222  2次:69  3次:17  4次:8  5次:1  6次:1
≥5 次的只有 2 个,≥8 次的 **0 个**
```

**这是本文最重要的一个数字。** 一个真的能通过的取值,**在这份语料里从未连续失败 7 次以上**。最惨的那个卡在 **6**。

**所以 N=7 不是随手挑的常数,它是「观测到的最长失败前缀 + 1」。** 但也必须说清:**它只领先 1 步**。语料里出现一个连败 7 次后通过的取值,N=7 就会误判一次。这是真实的脆弱性,不能用「误杀 0」掩盖。

## 三、原理性错误:「跨空间」在这份语料里等于「跨候选」

上一轮我说「跨空间汇总(仍在同一个 run 内)」。**实测下来那不是我以为的东西**:

| 阈值 | 触发规则 | **证据来自多个候选的** |
|---|---|---|
| 6 | 5 | **4** |
| 8 | 4 | **3** |
| 12 | 3 | **3** |

```
DOT_PRECISION=tf32   ← 10 个候选的失败被混在一起
COMPUTE_DTYPE=bf16   ← 9 个候选
BC_CACHE_DTYPE=bf16  ← 2 个候选
RED_CB=128           ← 6 个候选
```

**为什么这是原理错误而不只是不精确**:S1b 的根因是「**候选自己**把低精度放在未补偿的 `dot`,或 `PREC` 门控整个算法」—— 那是**那个候选源码的性质**。把 10 个候选的失败混起来判定「tf32 是死的」,成立的前提是这 10 个候选**恰好都犯同一个错**。在这份语料里它们确实都犯了,所以数字好看;**但那是语料的性质,不是机制的性质。** 一个正确实现了 tf32 补偿的候选会被前 9 个候选的历史提前判死。

**这与我否掉 S1 的理由同形**:用一个恰好在当前语料上成立的关联当规则。

**修法**:汇总键改为 `(candidate_id, knob, value)` —— 仍跨该候选的**多个空间**(打破单空间算术天花板所必需,每候选中位 2 个空间),但**不跨候选**。

## 四、三种汇总范围的完整对比(同一前瞻式模拟)

| 汇总范围 | N | 触发 | 省下失败 | 误杀通过 | **误杀率(0 时给 95% 上界)** |
|---|---|---|---|---|---|
| 每空间独立 | 8 | 32 | 63 | 0 | 0% (**≤8.9%**, n=32) |
| **每候选(跨其空间)** | **8** | **33** | **206** | **0** | **0% (≤8.7%, n=33)** |
| 整个 run(跨候选) | 8 | 4 | 249 | 0 | 0% (**≤52.7%**, n=4) |
| 每空间独立 | 12 | 8 | 11 | 0 | 0% (≤31.2%, n=8) |
| 每候选 | 12 | 20 | 105 | 0 | 0% (≤13.9%, n=20) |
| 整个 run | 12 | 3 | 237 | 0 | 0% (≤63.2%, n=3) |

**这张表推翻了上一轮的选择。** 跨候选那一档的 249 看着最高,但它只由 **4 条规则**支撑 —— 0/4 的 95% 置信上界是 **52.7%**,即**这份数据完全无法排除「真实误杀率高达一半」**。per-candidate 用 33 条规则拿到 206,上界 **8.7%**,证据强度差一个数量级。

**「误杀 0」在 n=4 时几乎不是证据。** 这是我上一轮报「省 249、误杀 0」时没说的部分。

## 五、阈值稳定性:对 S1b 用一次我否掉 S1b 前身的那条判据

当初否掉计数式黑名单的理由之一是「N=12 恰好零误杀,但那是事后挑的」。现在对 S1b 自己做留一:用 4 个 run 选出**最小的零误杀 N**,拿到第 5 个 run 上用。

| 汇总范围 | 五次选出的 N* | 稳定性 | 留出 run 上(误杀/省下) |
|---|---|---|---|
| 每空间独立 | [7, 7, 7, **6**, 7] | **不稳定** | 0/3 · 0/0 · 0/0 · **1/34** · 0/67 |
| **每候选** | **[7, 7, 7, 7, 7]** | **稳定** | 0/26 · 0/0 · 0/0 · 0/66 · 0/147 |
| 整个 run | [**5**, 7, 7, 7, 7] | **不稳定** | **1/83** · 0/0 · 0/0 · 0/18 · 0/157 |

**只有 per-candidate 范围下阈值稳定,而且它是唯一在全部五次留一里零误杀的。** 另两档各有一次留一出现 1 次误杀 —— 恰好是它们选错阈值(6 / 5)的那次。

**三条独立的判据(原理、证据强度、阈值稳定性)全部指向 per-candidate。** 这是本次分析里唯一一处三者一致的地方。

## 六、过度拦截会不会发生:两个层次的答案

### 6.1 会,但幅度已量化

per-candidate N=7 下 33 条规则,触发后:

| | 中位 | 最大 |
|---|---|---|
| 该键触发后还会出现 | 6 次 | 20 次 |
| 占该空间剩余预算 | **18.9%** | — |

**一条规则中位吃掉该空间剩余预算的约 19%。** 这是「拦截量」,不是「误拦量」—— 其中 **0/33 条是错的**。

### 6.2 最坏后果:最优点有没有被挡住

误杀率不是最贴切的指标 —— 误杀一个平庸的通过点几乎无代价,**挡住最优点才是灾难**。所以直接检查:每个空间的最优 trial,是否用了会被降权的取值?

```
检查 64 个空间的最优点 → 0 个用到了会被降权的取值
```

**零命中。** 在这份语料上 S1b 从未挡住任何空间的最优点。这与 §二 的机制一致:被降权的都是**无条件失败**的取值,而无条件失败的取值不可能出现在最优点里(它一次都没通过过)。

**这是 S1b 与 S1 风险结构的根本差别。** S1 删的是「条件失败」的组合 —— 那些组合的成员**正出现在最优点里**(`DOT_PRECISION=fp16` 曾持有一个空间的最优 2.6286 ms,却被我早期错误的计数规则摘掉)。S1b 只动从未通过的取值,所以它**在结构上**碰不到最优点。

## 七、降权强度 k:决定误判能不能被纠正

摘除 = k 无穷 = 永不纠正。降权保留非零概率,但**必须保留到「至少还能被采到一次」**:

| k | 降权后该取值期望仍被采到 |
|---|---|
| 2 | 中位 3.0 次 |
| **4** | **中位 1.5 次** |
| 8 | 中位 0.8 次 ← **< 1,纠正机会不足** |

**k 应取 4,不能取 8。** k=8 时「保留非零概率」在 40-trial 预算内是空话 —— 期望不到一次,等于摘除。

**注意方向**:这些期望是**上界**,因为重放固定了采样顺序(见 §九)。真实的纠正机会**更少**,这加强了「k 不要太大」的结论。

## 八、修订后的 S1b 完整规则

1. 证据按 **`(candidate_id, knob, value)`** 汇总,跨该候选的多个空间,**不跨候选、不跨 run**;
2. 触发:累计 ≥ **7** 次 `correctness_mismatch` 且 **0** 次通过;
3. 撤回:任何一次通过即**永久**撤回;
4. 降权到 **1/4**,保留非零概率。

**预期效果(重放)**:省 206–272 个失败 trial(≈1.5–2.0 h / 5 run),误杀 0(95% 上界 8.7%),最优点命中 0/64。

**新增判据**:

| 判据 | 怎么验 | 反向对照 |
|---|---|---|
| **J1b-7 不跨候选** | 断言汇总键含 `candidate_id` | 🟢 **正对照已实测**:跨候选时 `DOT_PRECISION=tf32` 一条规则混了 10 个候选的证据,且阈值留一不稳定([5,7,7,7,7]) |
| **J1b-8 阈值由留一选出,不是常数** | 记录 N=7 的来源是留一(五个 run 一致),并在新语料上重跑 | 🔴 若新语料选出不同的 N ⇒ 阈值不可移植,退回 |
| **J1b-9 报置信上界** | 误杀 0 时必须并列 Clopper-Pearson 上界与 n | 🟢 **正对照**:0/4 的上界 52.7% 与 0/33 的 8.7% 是不同强度的证据 |
| **J1b-10 最优点零命中** | 每空间最优 trial 不得使用被降权的取值 | 🔴 出现命中 ⇒ 机制碰到了最优点,立即回退 |
| **J1b-11 k 保留可纠正性** | 断言降权后期望被采次数 ≥ 1 | 🟢 k=8 时中位 0.8 < 1 ⇒ 退化为摘除 |

## 九、重放答不了什么(必须写明)

1. **降权会改变采样顺序**,所以「触发后该取值还会出现 6 次」在真实运行里不成立 —— 真实次数**更少**(它被降权了)。**方向:纠正机会与省下的量都被上表高估。**
2. **TPE 对降权的反应完全未测** —— 全部重放用随机采样器。代理模型可能把降权理解成「这个区域没数据」而增加采样,也可能相反。
3. **最优点检查用的是已记录的最优,不是真实最优。** 省下的预算本可能找到更好的点(这对 S1b 有利,但未被测量)。
4. **只有 L3、只有 box 1、只有 GLM、只有 `correctness_mismatch` 这一池。**
5. **余量只领先 1 步**(观测最长失败前缀 6,阈值 7)。**这是本文最脆弱的一点** —— 一个连败 7 次后通过的取值就会造成一次误判。它不是「不会发生」,是「在 2776 个取值里没发生过」。
6. **box 2 的语料不在其中。** 当初黑名单误杀 38.5% 的最锋利证据在那台已关机的机器上;本文的零误杀是在 box 1 语料上得到的。

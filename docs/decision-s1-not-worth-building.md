## 1.4 决定性的一条:能省预算的实现**必然误杀**

**先问能不能分开**(1392 个曾出现在不可行配置里的 (knob,value) 对):

| 判据 | 命中 | 占比 |
|---|---|---|
| **无条件死**(从不出现在可行配置里) | **26** | **1.9%** |

95.6% 是**最乐观读法**:只要**任意一个**搭档取值同现时全败即算可分,哪怕只观察到**一次**。所以做留一法 —— 4 个 run 学规则,第 5 个 run 上问「会不会删掉真跑通过的点」:

| 最小证据数 | 规则数 | 留出 run 可行点 | **误杀** | **误杀率** |
|---|---|---|---|---|
| 1 | 6275 | 1842 | 278 | **15.09%** |
| 2 | 1390 | 1842 | 103 | **5.59%** |
| 3 | 299 | 1842 | 58 | **3.15%** |

**任何会删东西的阈值都误杀真的跑得通的配置;唯一零误杀的阈值学到 0 条规则** —— 退化成现状。

**代码库里早有一条独立审计说了同一件事**(`correctness.py:158-160`):

> 「在全部 16 个 L3:43 候选上审计,`BLOCK_M * BLOCK_N * stages` 的失败最小值低于通过最大值,**15/15** ⇒ 可行集与不可行集在任何这类乘积上重叠。」

**这条在写 S1 之前就在仓库里,我做 S1 计划时没把它当作否证。** 那是我的疏漏。

# 二、S1b:值得做,但方案里的判据实测更危险

S1b 打的是**另一个池子**(`correctness_mismatch`,537 个 trial / 4.7 h),规则形态也不同(**无条件** + **降权而非摘除**)。§1.4 的留一法对它无话可说,所以单独测。

## 2.1 测法必须是**运行内、前瞻式**,不是跨 run 留一

我第一版脚本对 S1b 也做了跨 run 留一(得到 23.83%),**那个数字不能用**:方案 §2.5 的判据显式是**每 run 每空间**的(M 取该 run 同旋钮其他取值的中位样本量),且**随 trial 到达而前瞻触发**。跨 run 留一测的是「结论能否跨 run 迁移」—— S1b 从不主张这件事(方案自己写了「不同版本工具的环境上结论不能照搬」)。

**正确测法**:按 `events.jsonl` 的 append-only 顺序走每个空间的 trial,每步只用**此刻已有**的证据评判三条判据;一旦触发就冻结,然后数**该空间后续**用了这个取值并**通过**的 trial。这与当初否证黑名单的那次测量同形。

## 2.2 结果:方案的判据是全部变体里**最差**的

| 变体 | 触发 | 后续通过 | 省下失败 | 逐 trial 误杀 | **取值级误杀(register 单位)** |
|---|---|---|---|---|---|
| 计数式 N=3(已被否决的黑名单) | 101 | 83 | 345 | 19.39% | 26.7% |
| 计数式 N=6(已被否决的黑名单) | 44 | 1 | 132 | 0.75% | **2.3%** |
| 计数式 N=12(已被否决的黑名单) | 8 | 0 | 11 | 0.00% | 0.0% |
| **方案 S1b:median-M + 活对照** | 203 | **647** | 650 | **49.88%** | **67.5%** |
| 方案 S1b + 下限 N=3 | 70 | 45 | 283 | 13.72% | 21.4% |
| 方案 S1b + 下限 N=6 | 35 | 1 | 118 | 0.84% | 2.9% |

**两个单位都给,因为 register 里的 4.7%/38.5% 数的是「取值」不是「trial」,不同单位并列会像互相矛盾。**

**方案原判据取值级误杀 67.5%,而它要取代的 N=6 黑名单是 2.3%。** 最差的几例:

```
WARPS3=2         : 后续 23 个 trial 里 18 个通过
WARPS1=2         : 后续 23 个里 17 个通过
APPLY_BS=1024    : 后续 18 个里 16 个通过
BLOCK_J=32       : 后续 22 个里 15 个通过
```

**根因**:`median-M` 是**自适应**的,而在早期它很小(其他取值也才试过一两次),于是「M 取中位样本量」让规则**极早**触发 —— 我以为它比固定常数更稳,实际是让它**更容易在证据不足时开火**。「有活着的对照」这一条也没帮上忙:早期任何通过过一次的兄弟取值都满足它。

**结论:方案 §2.5 的三条判据必须删掉。** 承重的是**计数下限**,不是那两条我额外加的条件。

## 2.3 但纯计数下限也不够 —— 收益有**算术上的天花板**

安全的下限(N=8 起)会把收益吃掉,原因是算术的不是统计的:

| 下限 N | 触发 | 该取值总出现 | **触发前已花** | 触发后可省 | 可省份额 |
|---|---|---|---|---|---|
| 3 | 70 | 561 | 233 | 328 | 58.5% |
| 6 | 35 | 332 | 213 | 119 | 35.8% |
| **8** | 26 | 267 | **208** | **59** | **22.1%** |
| 12 | 8 | 107 | 96 | 11 | 10.3% |

**旋钮域中位 4 个取值 ⇒ 一个取值在 40-trial 预算里只出现约 10 次。** 要求看到 8 次失败才敢动,等于**等到它的 trial 花光才动手**。**安全与收益在单空间内直接对冲,这不是调参能解决的。**

## 2.4 突破口:证据**跨空间汇总**(仍在同一个 run 内)

一个 run 有 10–18 个空间,同一个旋钮取值在多个空间里都出现。若在空间 1 学到、空间 2 起就能用,§2.3 的天花板就被绕开。

**但这只在结论真的能迁移时成立,而它未必**:已知根因是**候选自己**把低精度放在未补偿的 `else` 兜底 —— 那是**那个候选的代码属性**,不是精度的属性。所以先直接测迁移(全 hindsight 判定):

| | 数量 |
|---|---|
| 在 ≥2 个空间出现且 ≥1 个空间全败的 (knob,value) | 18 |
| **迁移成立**(在每个空间都全败) | **4** |
| **迁移失败**(在某些空间活着) | **14** |

**并且陷阱的形状就在语料里**:同一个精度词在不同旋钮下行为相反 —— `DOT_PRECISION=tf32` 是 **0/164**,而 `COMPUTE_DTYPE=tf32` **通过 209 次**。**所以绝不能按「dtype 值」汇总,只能按 (knob, value) 汇总。**

14/18 迁移失败,看起来汇总也死了 —— 但那是**无撤回**的读法。

## 2.5 实测过的那一版:**跨空间汇总 + 见通过即永久撤回**

规则:证据在**一个 run 内**按 `(knob, value)` 汇总;累计 ≥N 次失败且 **0 次通过**则触发;**一旦出现任何一次通过,立即永久撤回**;动作是**降权**(保留非零概率)而非摘除。前瞻式模拟(全局顺序、先判后学):

| 汇总方式 | 下限 N | 触发规则 | **省下失败 trial** | **误杀通过 trial** | 误杀率 |
|---|---|---|---|---|---|
| 单空间 | 3 | 101 | 310 | 27 | 8.01% |
| 单空间 | 6 | 44 | 131 | 1 | 0.76% |
| 单空间 | **8** | 32 | **63** | **0** | 0.00% |
| 单空间 | 12 | 8 | 11 | 0 | 0.00% |
| 跨空间 | 3 | 12 | 276 | 7 | 2.47% |
| 跨空间 | 6 | 5 | 257 | 1 | 0.39% |
| **跨空间** | **8** | **4** | **249** | **0** | **0.00%** |
| 跨空间 | 12 | 3 | 237 | 0 | 0.00% |

**跨空间 N=8:省 249 个失败 trial,误杀 0,只需 4 条规则。** 比单空间同阈值(63)高 **4.0 倍**,而误杀同为 0。**撤回机制是关键** —— 它把 §2.4 那 14 个「迁移失败」的取值变成「先误触发、见到第一次通过就退回」,代价是几个 trial 的采样份额而不是丢掉配置。

**收益核对**:249 个 trial × 26.82 s 中位 = **1.85 h / 5 run**,是 S1 全部目标(0.644 h)的 **2.9 倍**,且省的是**贵的那一类**。

## 2.6 触发的规则可以被命名,所以不是「碰巧的阈值」

N=8 时的 4 条规则**全部**是精度类旋钮:

```
DOT_PRECISION=tf32      (run-l3-48-20260909-115701)   0-for-164
COMPUTE_DTYPE=bf16      (run-l3-21-20260908-232211)
BC_CACHE_DTYPE=bf16     (run-l3-48-20260907-202457)   0-for-25
GEMM_PRECISION=bf16     (run-l3-21-20260908-232211)   0-for-8
```

**这与已知根因吻合**:低精度 100% 失败的两个成因是(A)未补偿的 `dot`,(B)`PREC` 门控整个算法而非精度分支 —— 都会让该取值在**该候选的每个空间**里无条件失败,同时**不影响**其他候选。**机制可命名 ⇒ 阈值不是事后挑的。**

**但判据必须保持通用**:规则是「跨空间无条件 + 可撤回」,**不得**写成「只对精度旋钮生效」。精度类只是**当前语料里满足该判据的集合**,把它硬编码进去就是针对单一 case 的特化修改 —— 恰是禁止的那类改动。

## 2.7 S1b 的判据(取代方案 §2.5)

| 判据 | 怎么验 | 反向对照 |
|---|---|---|
| **J1b-1 硬门:误杀 0** | 全部可得历史 run 前瞻重放,逐 trial 与逐取值两个单位都报 | 🟢 **正对照已知且已实测**:方案原判据 67.5%、N=3 计数式 26.7% —— 新实现必须**放过**这些 |
| **J1b-2 省下贵的那一池** | 省下的 `correctness_mismatch` trial ≥ 200(实测 249) | 🟢 省不到 ⇒ 判据太严,退化成不作为 |

# 三、本文档没有验证什么

- **S1 部分只覆盖 shared memory 这一面墙。** 另一面硬墙(寄存器 > 255)在这份语料里**从未**作为不可行点出现。
- **只有 L3、只有 box 1、只有一张卡、只有 GLM。**
- **S1 的误杀测试以「已记录的可行点」为真值**,那是实际跑过的点的子集 ⇒ **真实误杀率只会更高。**
- **没有验证 TPE 对收缩域/降权的反应。** 全部重放用随机采样器(理由见 `result-s1-replay-inconclusive.md`)⇒ 「代理模型在收缩域上表现更好」未被排除;但它要越过的门槛现在是 §1.4 的误杀率,不是 §1.1 的 4.42%。
- **S1b 的 249 个省下 trial 是重放意义上的**:它假设省下的预算被用在**同一空间的其他点**上。**这些点存在**(63/64 空间跑满 40 trial),但它们的**质量**未被测量 —— 与 S1 的 J1-2/J1-3 是同一个结构性限制。**唯一区别是 S1b 的硬门(误杀 0)可以离线验,而 S1 的收益不能。**
- **`correctness_mismatch` 里有多少是真候选被门挡住的,本文没有分离。** 三个任务的噪声底全部低于 `relaxed_pass_frac`(已在 A800 复验)⇒ 这 537 个 trial 里有一部分**不该**被降权避开,而应由门的修正来救。**S1b 只处理无条件失败的那部分,不触碰这个更大的问题。**

# 结果:墙钟总是那个绑定的预算,而论文主张的那个循环只拿到 7–8%

**日期**:2026-09-10 · **语料**:box 1 + box 2 共 **5 个跑完的 L3 run**(66.6 h 墙钟)· **零 GPU 成本**(只读 events.jsonl)· 脚本 `scripts/budget_allocation.py`

---

## 一、结论先说

| 事实 | 数字 | 来源 |
|---|---|---|
| 结束 run 的是墙钟 | **5/5** | 每个 run 的 `elapsed_hours` 都 ≥ `wall_clock_hours` |
| 改写预算实际用掉 | **每族 1–2 轮,上限 5** | `rewrite_rounds_used` |
| 族数实际用掉 | **3–4 个,上限 6** | `families` |
| **loop C(改写)拿到的 agent 时间** | **15–21%,占墙钟 7–8%** | rewriter + novelty 调用时长 |
| **逐候选例行开销(参数化 + 分析)拿到的** | **62%,占墙钟 23–29%** | parameterizer + analyst 调用时长 |

**一句话**:预算不是被结构搜索花掉的,是被"让每个候选可调参、并对每个候选写一份瓶颈分析"花掉的。**论文的核心主张(结构改写由调参反馈引导)在墙钟上只占 7–8%,而它的预算上限从来没被碰到过。**

## 三、为什么例行开销这么贵:它按候选数收费,而改写按轮收费

- `parameterizer` 被调用 **47–73 次**,`analyst` **40–55 次**,而 `rewriter` 只有 **9 次**。
- 原因是结构性的:**每一个候选**(种子 + 每个改写产物 + 每个修复产物)都要走一遍"参数化 → 发布空间 → 调参 → 统计 → 分析"。改写一轮产出 2 个候选,于是那一轮的成本是 1 次 rewriter 调用 **加上** 2 整套例行开销。
- 所以 rewriter 的单价虽然最高(14–19 min/次),总量却最小 —— **想多做几轮改写,先付的是例行开销的钱。**

这不是"agent 太慢"。单次调用时长都在预期内。是**账目结构**:预算的大头花在把每个候选变成可调参的形态并为它写一份分析,而不是花在探索结构。

## 四、Loop D 为什么又是零 —— 这次的原因和先前记录的不同

先前记录的原因是"族数 ≥ `max_families_total`,门直接不调用 agent"。**这五个 run 不是那个原因**:族数 3–4,上限 6,门是开的。

真实原因在 `orchestrator.py:568`:Loop D 只在 `_rewrite_round` 返回 `progressed=False` 时才被调用。而这五个 run 里改写**一直在产出**(每族都还有没用完的轮次),所以控制流从来没走到 Loop D 那个分支,直到墙钟先到。

**这不是缺陷**:先把改写做完再开新族,是合理的优先级。但它意味着 **Loop D 在当前预算下实际不可达** —— 论文的四个循环里有一个在 L3 上从未在正常路径执行过。要么承认"D 需要更长的墙钟才会出现",要么让 D 与 C 竞争预算而非排在 C 之后。**这是设计决定,不在本轮修复范围。**

---

## 五、不改什么,以及为什么

按现行修复标准(只做确定 + 低风险 + 泛化的修复),**这一条只记录、不动手**:

- 把预算从例行开销挪到改写,需要动的是"每个候选是否都值得一份完整分析"这个判断 —— 那是**功效取舍**,不是缺陷修复。少调用 analyst 会直接削弱调参反馈的信息量,而调参反馈引导改写正是论文的主张。
- 抬墙钟同理:不是修复,是换实验规模,并且会改变所有跨 run 比较的基准。
- 有一条**看起来**便宜的:改写一轮产出 2 个候选,若只对更有希望的那个做完整例行开销,单轮成本近乎减半。但这等于**早停剪枝**,而用户已明确否决,且我们有直接反证 —— L3:21 上赢家族的 seed 是四个里最差的([[opop-v2-l3-21-best-result]]),前两次调参完全持平。**便宜的那条路正好是数据说会杀掉赢家的那条。**

**留给下一轮统一处理的选项**(不在此实施):(a) analyst 只在候选进入改写候选池时才调用,而非每个候选都调用;(b) Loop D 与 Loop C 竞争预算;(c) 承认 L3 的 12 h 只够 1–2 轮改写,把跨 run 结论限定在这个规模内陈述。

---

## 六、对论文陈述的直接影响

现在报告"改写轮数上限 5"是**误导性的**,因为从来没有 run 接近过它。诚实的陈述是:

> 在 12 h 墙钟下,每族实际完成 **1–2 轮**结构改写;结束运行的始终是墙钟,而非改写或族数预算。结构改写占用墙钟的 **7–8%**,其余主要是每个候选的参数化与瓶颈分析(23–29%)以及调参试验本身(43–46%)。

这同时是 v3 成本论证的一个约束:**S2c 的资源地图(每计时 trial 约 1/21–1/30 的成本)要挤进的是那个 43–46% 的格子,而不是与 agent 时间竞争。**

# 第 5 项(离线量化,零 GPU):族内非最优候选的墙,在最优候选身上还成立吗

**日期** 2026-09-13 · **checkout** `D:\Pyhon_projects\opop\v3` @ `76d797f`
**探针** `scripts/probes/do_nonbest_walls_hold_on_the_family_best.py`(纯读 events.jsonl,**零 GPU**)
**语料** 本机 `D:\Pyhon_projects\opop\v2\runs\run-l3-*` 全部 19 个 run;
其中 **48 个族可判、105 个非最优成员带完成 trial、152 条候选墙**

## 0. 这个问题决定什么

`orchestrator.py:2932` 把 `parent_crun.wall_text` 交给 rewriter,而 parent 恒为
`family.best.candidate_id`。⇒ **一道长在族内非最优成员上的墙,会被记进事件日志,然后永远进不了任何 prompt。**
三臂 run 上实测只有 **25% 的族**收到过墙文本,于是"把全族的墙都发过去"看起来是个免费的提升。

它不免费:如果非最优成员的那道墙**在最优候选的源码上不存在**,那段文本就会指着一个
rewriter 并没有在改的 knob、一个它到不了的取值、一个它没在看的 kernel。
所以先要的数是:**非最优成员的墙,有多少在最优成员身上仍然成立。**

三种结果,而且**不是两种**:

| 判定 | 含义 | 若按它行动 |
|---|---|---|
| **transfers** | 最优成员有同名 knob,同一侧被截断,且被拒值仍在其已测范围之外 | 加的是**真证据** |
| **does not hold** | knob 存在,但被拒值**落在**最优成员已测范围**之内** —— 它两侧都跑到了 | 加的是**噪声**:声称一道墙,而 tuner 明明跑过那个值 |
| **dimension gone** | 最优成员**根本没有这个 knob**(改写换掉了结构) | **两者皆非**,没有东西可投递 —— 与 `wall_report.freed_lines` 同一条三分规则 |

## 1. 本机语料的硬限制(先说,因为它限定了这个数能怎么被引用)

**本机备份的每一个 run 都在共享内存筛子上线之前**,`failure_kind == "infeasible_shared_memory"`
在 19 个 run 里出现 **0 次**(逐 run 核实),`find_walls` 的唯一输入不存在
⇒ 真硬墙的离线重放得 0 个墙,这一点 `hard_vs_soft_wall_same_corpus.py` 已经记过。

但**迁移问题是几何问题**:它只问"同一个 knob 在另一个候选上是否也被截断",与墙由哪个判据产生无关。
所以探针用的是**边界截断的 knob** —— 候选自己的 `TuningStats` 显示最优取值落在极端 choice 上、
且末段单调趋近(即 `at_boundary`,harness 自己就在算,2e 的 `find_walls` 也要求它)。

⇒ **这个数是关于边界截断的,不是关于实测共享内存拒绝的。**
拿到一个带真拒绝记录的 run 之后,必须用 `--source refusals` 重跑才能当成"共享内存墙的迁移率"引用。

## 2. 结果

### 2.1 汇总(152 条非最优候选墙)

| | 数量 | 占比 |
|---|---|---|
| transfers | 56 | 36.8% |
| does not hold | 27 | 17.8% |
| dimension gone | 69 | 45.4% |

### 2.2 但必须按侧拆开 —— 混池会让低侧扛走头条数字

**共享内存墙只长在高侧**:编译器拒绝的是**更大**的 tile,不是更小的。而低侧
("比试过的任何值再小一档")几乎总在另一个候选的范围之外,迁移几乎免费。

| 侧 | 墙数 | transfers | **仅在 knob 仍存在的分母上** |
|---|---|---|---|
| **high(与共享内存墙同侧)** | 126 | **39 = 31.0%** | **39/64 = 60.9%** |
| low | 26 | 17 = 65.4% | 17/19 = 89.5% |

**两个分母都要给,因为它们答的是两个不同问题**:
- `39/126 = 31.0%` 是"随便挑一条非最优墙,它有多大概率能用";
- `39/64 = 60.9%` 是"**在能投递的那些里**(knob 还在),有多大概率是真的" ——
  `dimension gone` 在任何策略下都投递不了,把它计入分母会让"45% 维度已消失"悄悄变成反对放宽的证据。

混池不是可选的谨慎:本项目已经因为混合不同基础率的类别吃过双向 Simpson 悖论
(`pooling-register-classes-inverts-correlations`)。这里低侧 65.4% vs 高侧 31.0%,差 34 个百分点。

### 2.3 对"族覆盖率"到底有多少提升 —— 这才是这个改动要的那个数

覆盖率数的是**族**,不是行数。一条能迁移的墙,如果它所在的族**最优候选本来就有自己的高侧墙**,
那它只是给一个已经存在的 prompt 多加一行,不是让一个族从没有变成有。

| | 族数 | 占 48 |
|---|---|---|
| 可判族 | 48 | —— |
| 最优候选**本来就有**自己的高侧墙 | **30** | **62%** |
| 靠"迁移过来的非最优墙"**新增覆盖** | **4** | **8%** |
| 本来就覆盖,只多几行 | 13 | 27% |

## 3. 结论

**放宽族覆盖是"扩大样本"还是"制造噪声"?—— 答案是两者都有,而且新增量很小。**

1. **可投递的那些里 60.9% 是真的**(39/64)—— 不是噪声占多数,所以这条路不是死的;
2. **但 45.4% 的非最优墙"维度已消失"** —— 改写换掉了结构,knob 不复存在,没有东西可投递。
   这不是缺陷,是 loop C 在做它该做的事;
3. **而且 17.8% 会是纯噪声**(knob 在,但最优候选**跑过**那个值)—— 这些必须过滤掉,
   过滤判据现成:`does_not_hold` 就是"被拒值落在已测范围之内",与 `find_walls` 同一行代码;
4. **最要紧的一条:族覆盖率只提升 8 个百分点(4/48)。**
   62% 的族其最优候选**本来就有**自己的高侧截断。
   ⇒ 三臂 run 上"只有 25% 的族收到墙文本"**不是**因为墙长在非最优成员身上;
   而是因为**四道门**(有拒绝记录 → 落在范围外 → 单调 → 尾部斜率为正)一起把数量压下来了。

**⇒ 对"下一轮"的建议:放宽族覆盖的收益上限是 +8 个百分点,且需要新增一条 `does_not_hold` 过滤。**
它比第 1 项(top-K 原点,零机时、默认可关)性价比低得多,**建议排在第 3.1 项与第 2 项之后**,
并且不要把它当作"把 25% 拉到高位"的手段 —— 那个 25% 的成因在四道门上,不在投递范围上。
这条正好证实了 `next-round-changes.md` §5 第 3 条那句撤回:提高覆盖率只能**改判据**,不是"多发几份"。

## 4. 探针自己的两个缺陷(读它自己的输出才发现的,记下来)

两个都属同一形态:**一个看起来可信的常数**,而不是 `None`
(`a-constant-reading-is-a-broken-probe`)。两次都会**单方向抬高迁移率**。

1. **算术步长 vs 几何步长。** 第一版用"最后一个测量间隔"当下一档。
   `[16, 32, 64]` 的低侧于是得到 `16 - 16 = 0` —— tile 尺寸 0 不是任何空间提供的取值,
   而且它**低于每一个范围**,所以每一条这样的 knob 都读成 `transfers`。
   高侧同样错:`[2, 4, 8, 16]` 得 24,落在另一个候选的 `[2,4,8,16]` **之内**,读成 `does_not_hold`。
   ⇒ **两个方向都会翻转判定**,不能放过。改成按候选自己的取值**探测**阶梯(比值恒定即几何)。
2. **整数阶梯上的分数档。** 修完 1 之后,`NUM_WARPS ∈ [1,2,4,8]` 的低侧得 0.5。
   半个 warp 不是配置,而 0.5 低于每一个整数范围 ⇒ 又是一个免费的 `transfers`。
   ⇒ 整数阶梯上出现分数档时**丢弃该截断**(共丢弃 14 条)。

**两次修复都只动了低侧:高侧数字全程是 39/126 不变**,这正是修复方向正确的证据 ——
它们移除的是免费的正例,而不是改变了结论。

探针带 **14 条自检**(阶梯两向、判定两向、峰形/平坦曲线不应触发),全部通过才打印数字;
`probe-needs-a-positive-control`:阴性结论必须有一个会大声失败的正对照,
这里反过来 —— 迁移率是个阳性结论,所以对照要能证明"不该触发的确实不触发"。

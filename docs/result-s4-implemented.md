## 二、消费者:一个没有消费者的判决等于没实现

`conversion_verdict` 被计算、被落盘,而 `report.py` **读它 0 次**。后果不只是「少一节报告」——**没有东西作用于它,也没有东西能发现它是错的。**

更糟的是它**在任何一次真实 run 里都还没产出过一条判决**:

| 语料事实 | 数字 |
|---|---|
| `FAMILY_ROUND_RECORDED` 事件 | 9 个 |
| 其中带 `conversion` 字段 | **0** |
| 其中带 `resource_deltas` | **0** |

原因是**五个 run 都早于 G27 的修复**(run 09-07~09-10,修复 09-10),**不是修复失效**。

**所以这一节必须能区分两件在「都没有」的日志里长得一样的事**:

| 状态 | 输出 |
|---|---|
| 没有改写轮 | 「nothing to convert —— 这是关于搜索的事实,不是关于机制的」 |
| 有轮但无 `conversion` 字段 | 「**none carries a conversion verdict** —— 这些轮早于 G27 的修复,**不是「什么都没转化」**」 |
| 有判决 | 判决分布表 + 逐轮明细 |

**`no_conversion` 单独给强调**:某资源实质改善而延迟没动 ⇒ **那个资源不是限制**。这比任何利用率读数都可靠,因为它是**同一族两次真实测量之间的受控比较**,不是与假定天花板的比值。

## 三、互补松弛:这一条检查的是**我们自己**

LP 对偶给出一条可用定理:**非绑定约束的影子价格为零。** 翻译成我们的话:

> **若某维被判 `slack`,则在该维上花资源必须买到零延迟改善。**

于是一轮**既改善了 slack 维、又降低了延迟**,就是**我们的判决错了**的证据 —— 不是候选不好。

**这是它值钱的地方**:这个项目里几乎所有别的检查都在给候选打分,只有这一条在给**我们**打分。

**它必须能大声失败**,所以 `slackness_violations()` 点名违规维度,不做任何软化。诚实的 caveat 随行:**改写后会重新调参**,所以增益可能来自同一轮的别处 —— 这削弱归因但不消除信号,**一个 slack 维的改善反复与延迟增益同时出现,就是一个该被怀疑的判决**。

### 三个状态刻意分开

| 状态 | 输出 | 为什么不能合并 |
|---|---|---|
| 完全没有逐维状态 | 「检查无法运行」 | |
| 有状态但**没有任何维被判 slack** | 「**That is not a pass**」 | 「无可测之物」报成「通过」,正是把探测器故障读成五个阴性结果的那个错 |
| 干净通过 | 「**WEAK pass**」+ 两条理由 | 弱通过被当强通过引用 |

### 一处刻意的不精确,并且写明了方向

slack 集合是**整个 run 的并集**,不是每轮的。因为把 `DIMENSION_STATE`(按候选)对上 `FAMILY_ROUND_RECORDED`(按族+轮)需要**那一刻的 `family.best`**,而那个没有落盘。**编出这个映射就是那个已经两次误判的「猜 payload 路径」。**

**并集的误差方向是可接受的那一边**:它会把某维在「其实绑定」的轮里也算作 slack ⇒ **多报违规而不是少报**。对于一个「全部价值在于能大声失败」的检查,**偏向噪声胜过偏向沉默** —— 且每条违规都带维度/族/轮,可以手查。

## 四、Gables 排序对照

Gables 原文算例四个配置达到 **40 → 1.3 → 2 → 160** Gops/s。**四步里三步是把某资源朝局部正确的方向动、然后变差。**

所以任何「跟着某一个资源走」的规则都复现不了这个排序 —— 这才是它作为**对照**而不是形式检查的理由。而「跟维度 argmax |Δ|」本来就是禁止的:shared 的中位摆幅是 registers 的 **13.5 倍**(纯归一化造成),那个规则会退化成「**永远挑 shared**」(实测 61.5%),什么都没发现。

**并且断言了这个序列是非单调的** —— 否则将来有人把数字换成单调序列,对照就不再对照任何东西,而测试仍然是绿的。

## 五、四条硬约束,逐条是一个测试

| 约束 | 怎么守 | 反例来源 |
|---|---|---|
| 不作 TPE 目标 | grep 断言 `tpe.py`/`stats.py`/`convergence.py` 零出现 | 把转化率当目标 = 优化诊断本身 |
| 噪声底以下报 unknown 而非小数字 | 驱动真实 `conversion_verdict` | L3:48 每 trial std 占均值 16%,而 33 个近平局跨度 9% |
| **绝不筛选剪枝** | 断言公开接口无 prune/screen/reject/kill | **L2:37 最慢的种子所属族改善最多 −30.5%** |
| 每维报区间 | 断言 `before/after/delta/rel/unit/direction` 六项齐全 | 只报方向看不出移动幅度 |

## 六、承重的那个测试,以及为什么其余的不够

`test_the_section_reaches_the_GENERATED_report_not_only_the_helper` 建一个真的 `RunStore`、生成真的报告、**从磁盘读 markdown**。

**手工验证过**:把 `report.py` 里的 `conversion_lines(...)` 调用改成不消费其返回值(语法合法),**这个文件里其余 23 个测试全部照旧通过,只有它一个失败**。这就是它要覆盖的盲区。

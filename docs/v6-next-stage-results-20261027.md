### 绑定与实际路径

T−P 的四个相邻对照差分别为 **1.562209 / 1.021143 / 1.192062 / 0.558859 ms**。这些读数包含包装、交互与端点噪声；不能当固定常数扣除，也不声称每个差值都独立越过噪声界。

独立 Python profile 中，P 的 `binding.dispatch` 调用 32 次，T/C 为 4,672 次；真正进入 `wrapped` 的调用由 32 增至 177。说明绑定在完整生成循环中被访问，而实际匹配的替换范围更小。cProfile 覆盖完整 32-token 调用，会扰动 dispatch 并包含 host wait，不是 TTFT 专项 CPU 时间，不能把累计耗时当成绑定纯成本。

独立 Nsight 捕获了 C 中 `rms_sq_kernel`、`rms_apply_kernel` 各 **145 次**，证实新增计算实际执行。原生时间线与 clean 计时分开。

继承的旧 attention bundle 在所有 C 质量端点仍报告 `parent-fallback:setup-failure:flash-dispatch-refused`，其 decode 部分报告 `parent-delegate`。原有源码和本次原生/调用证据需要一起解释：不能因为两个 bundle 都有调用覆盖，就声称两项优化均已生效。这不影响本次完整版本数值和端到端计时的真实性。

### 原源码一致性与检查缺口

独立 source fidelity 使用原源码创建模型、输入和累积流程，以相同 global batch 8 执行两次连续 SGD 更新。完整梯度和更新参数均通过源定义容差；两步梯度最大误差约 7.45e-9 / 6.80e-8，参数约 3.73e-9；基线 rank 间完整梯度精确相等。**当前基线 adapter 忠实复现原项目的证据成立**，不是只凭自我 controls 判断。

但生成 adapter 的 observe 只返回逐 rank 的 loss、梯度、参数，未执行原源码要求的跨 rank 精确关系检查。逐 rank 容差比较不能保证未来非零但在容差内的偏差仍满足跨 rank 精确一致。当前三轮零误差候选并未因此被证实不正确；下一步先用隔离 worker 的微小梯度扰动验证是否真实漏检，确认后再做只增加一段通用关系检查提示的真实 evaluator A/B，不增加按模型或失败类别硬编码的规则。

另一个证据边界：candidate_diagnostics 当前记录候选中的异常和 False 返回，不记录每次正常调用。本批事件为空不能证明优化分支实际执行；collection planner 对该采集器的描述比实现能力宽，应单独修正，不能把空记录当作执行路径证明。

新合同已放开 bucket/no_sync 等实现选择，但仍将 `foreach=False` 列为 optimizer 不变项，尚需审计，不能声称合同问题全部解决。

### 绑定与实际路径

T−P 的四个相邻对照差分别为 **1.562209 / 1.021143 / 1.192062 / 0.558859 ms**。这些读数包含包装、交互与端点噪声；不能当固定常数扣除，也不声称每个差值都独立越过噪声界。

独立 Python profile 中，P 的 `binding.dispatch` 调用 32 次，T/C 为 4,672 次；真正进入 `wrapped` 的调用由 32 增至 177。说明绑定在完整生成循环中被访问，而实际匹配的替换范围更小。cProfile 覆盖完整 32-token 调用，会扰动 dispatch 并包含 host wait，不是 TTFT 专项 CPU 时间，不能把累计耗时当成绑定纯成本。

独立 Nsight 捕获了 C 中 `rms_sq_kernel`、`rms_apply_kernel` 各 **145 次**，证实新增计算实际执行。原生时间线与 clean 计时分开。

继承的旧 attention bundle 在所有 C 质量端点仍报告 `parent-fallback:setup-failure:flash-dispatch-refused`，其 decode 部分报告 `parent-delegate`。原有源码和本次原生/调用证据需要一起解释：不能因为两个 bundle 都有调用覆盖，就声称两项优化均已生效。这不影响本次完整版本数值和端到端计时的真实性。

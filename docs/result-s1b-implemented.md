## 一、落地的规则

| 项 | 值 | 依据 |
|---|---|---|
| 汇总键 | **`(candidate_id, knob, value)`** | 跨该候选的多空间(每候选中位 2 个),**不跨候选、不跨 run** |
| 触发 | **≥ 7** 次 `correctness_mismatch` 且 **0** 次通过 | 留一选出,五个 run 一致 |

| 池子 | **只有** `correctness_mismatch` | 其余失败类型说明不了「这个取值对不对」 |

## 二、两个上一轮悬空的实现问题,已定

### 2.1 降权怎么在 `suggest_categorical` 上生效

Optuna 的 categorical 没有权重入口。**做法:在 `ask()` 里按概率拒绝并重抽**,与已有的 `guard_ok` 路径同形:

```python
if self.deweight_reject is not None and self.deweight_reject(params):
    self.study.tell(trial, state=TrialState.PRUNED)
    rejects += 1
    continue
```

三个性质都是刻意的:

- **计入同一个 `max_guard_rejects_per_ask` 预算** ⇒ 大量取值触发的空间退化成「少问几次」,**绝不会空转**(`test_rejects_are_bounded_and_never_spin`);
- **PRUNED 而非 FAIL** ⇒ Optuna 保留 pruned 在 TPE 模型里,采样器能看到「这里来过又走了」。**这不是「此点不可行」的断言** —— 该点在后续的 ask 里完全可能被抽中并测量,那正是降权与摘除的区别;
- **发生在 trial 运行之前** ⇒ 零 GPU 代价。

### 2.2 一个配置里有两个已触发取值时的抑制强度

**不复合:1/4,不是 1/16。** 重放把「已触发」当布尔量处理,**从未测量过 k 的复合行为**;而复合会抑制得更狠,方向正是这个机制被质询的过度拦截。证据支持的是弱的那一版(`test_suppression_is_not_compounded_across_two_fired_values`)。

## 三、resume:重建而非快照

账本只有计数器,所以**从 `TRIAL_DONE` 流重建**(`_restore_deweight_ledger`,在任何调参之前)。

**为什么这样是对的而不只是省事**:`observe` **顺序无关** —— 触发要求零通过、通过数只增不减 ⇒ 按顺序重放事件日志得到的是**与未中断运行完全相同**的状态,不是「相近」的状态(`test_ledger_rebuilt_from_a_trial_stream_matches_the_live_one` 断言两个 snapshot 相等)。

**每个 trial 都要折入,包括复用的测量** —— 重建路径读同一条流,活路径若跳过复用记录,中断后的运行会带着不同的证据继续(`test_a_resume_that_skipped_reused_trials_would_diverge` 是这条的正对照)。

## 四、落账:效果必须能从日志读出来

`TUNING_DONE` 每个空间带一份 `deweight` snapshot,**无论有没有触发** —— 「什么都没触发」是一个结果,它的缺席与「开关关着」不可区分。

snapshot 带**规则数**,因为 0 误杀在 4 条规则上和 33 条规则上差一个数量级,**规则数是后续任何关于这个机制的断言必须除的分母**。

## 七、实施中发现的一个真实性质(不是缺陷,但必须写下来)

测试修正时暴露了一件事,值得断言而不是以后再发现:**判据的「无条件性」是相对于已观测证据的,所以一个仅仅与真凶共现的无辜取值也会一起触发。**

实例:`BLOCK_M=64` 本身没问题(坏的是 tf32 路径),但若它在触发所需的那些抽样里**从未与一个能工作的精度共现**,它会跟着被降权。

**这是附带触发(collateral firing),被两件事界住**:首次通过即永久撤回、动作是 1/4 而非摘除。已加测试 `test_a_value_merely_correlated_with_the_culprit_also_fires` 钉死这个行为(并断言撤回附带规则**不会**撤回真规则)。

**这也正是为什么误杀率必须在真实运行上测,而不能从规则形状上论证** —— 真实空间里一个 tile 取值几次抽样内就会与多个精度共现并拿到它的通过。实测 0/33,95% 上界 8.7%。

## 八、本阶段没能验证什么

1. **降权会改变采样顺序。** 重放固定了历史顺序,所以「省 228」与「纠正机会 1.5 次」**两者都是高估**。这是重放的结构性上限,不是可以补测的疏漏。
2. **TPE 对降权的反应完全未测** —— 全部离线验证用的是历史顺序,不是活的代理模型。它可能把降权理解成「这个区域没数据」而增加采样,也可能相反。**这是本阶段最大的未知,只能靠对照 run 看,而 S1b 的判据刻意设计成不依赖它。**
3. **只有 L3、只有 box 1 语料、只有 GLM、只有 `correctness_mismatch` 这一池。**
4. **余量只领先 1 步**:后来真通过的取值首次通过前累计失败**最大 6**,阈值 7。一个连败 7 次后通过的取值就会造成一次误判。
5. **box 2 语料不在其中** —— 当初黑名单误杀 38.5% 的最锋利证据在那台已关机的机器上。
6. **`correctness_mismatch` 里「真候选被门挡住」这个猜想已被实测否证(2026-09-11)。** 我在本文首版写的是「537 个里有一部分该由门的修正来救」。逐条分类 537 个失败后:**门归因 0 例,全部 537 是候选自己的问题**(fp64 相对臂实测拒绝,最小 3.04 倍、中位 6.48 倍参考自身误差)。见 `docs/result-gate-not-at-fault.md`。**所以 S1b 避开的那 228 个不存在「本该救回」的部分**;真正的问题在候选生成侧(未补偿的 `dot` / `PREC` 门控整个算法),那仍是独立一项。

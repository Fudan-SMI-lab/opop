## 1. 本轮复验发现的一件新事(影响排期)

**G27 声称已修,但生产日志里零证据 —— 因为语料全部早于修复。**

```
FAMILY_ROUND_RECORDED 事件:9 个
conversion 判决:9/9 <absent>
携带 resource_deltas 的 round:0
```

**不是修复失效**:五个 run 的日期是 09-07 ~ 09-10,而 G27 的修复 commit `677d956` 是 **09-10**。所以 `conversion` 字段那时还不存在。

**后果,必须写明**:`conversion_verdict` 已经被 `orchestrator.py:2016` 调用(我上一轮说「零消费者」只对 `report.py` 成立,对 orchestrator **不成立** —— 这是一处需要更正的说法),但**它在任何一次真实 run 里都还没产出过一条判决**。所以:

- **S4′ 不能排在前面** —— 它要「补消费者」,而地基本身尚未在生产验证过一次;
- **下一个对照 run 会顺带第一次验证 G27**,这是免费的,但**必须在那次 run 的收尾里显式检查**,否则又是一个「以为修好了」。

**这也是 `FAMILY_ROUND_RECORDED` 只有 9 个的直接后果**:5 个跑完的 run 一共只用了 9 个改写轮(1–2/5),所以**任何 per-round 的机制每 run 只有个位数样本**。S2d 的账本尤其受这一条限制。

### 为什么是这个顺序

| 顺序决定 | 理由(实测) |
|---|---|
| **S2 第一** | 动机在生产里成立:L3:21 上 **19/20 = 95%** 的候选拿到同一个 `kind`(`resource_limited`);L3:48 上 12/17 = 71% 是 `memory_bound`。**单标签确实退化了。** 且它是 S2d 的结构前提 |
| **S2d 紧随 S2** | 账本的记录形状依赖 S2 定义的每维记录;且两者改的是**同一条通路**(agent 看到什么)⇒ 可共用一对对照 run(D-4 允许:S2d 的账本只在第二轮起有内容,不与 S2 首轮归因混淆) |

## 3. S2b 为什么挂起(这是纪律,不是拖延)

方案自己写了 S2b 的开工条件:**「至少一个手写 kernel 必须落在 1/32 墙上,否则这个推导只是在返回好消息」**。当前 checkout 里 `statics.py` **没有任何墙的实现**,也就没有那个正对照。

**为什么不能先写实现再补对照**:已有五次代价记录 —— 探针自身故障被我读成五个阴性结果(`probe-needs-a-positive-control`),以及「三个精确命中全在同一格子里」被当成模型(`three-same-cell-hits-are-not-a-model`)。**一个只会返回好消息的推导,和一个正确的推导,在输出上长得一样。**

**解除条件**:手写一个刻意踩 1/32 访存模式的 kernel,实测它被判定为落在墙上;同时另一个刻意规避的 kernel 不被判定。**两个方向都要**。成本约 0.5 天,可在任何空隙做,**不占关键路径**。

## 4. 开工前必须知道的六条(全部已复验)

| # | 事实 | 对实施的约束 |
|---|---|---|
| 1 | `load_config` 只读**一个** yaml,无 base 层 | **字段默认值就是生产行为**。新开关必须断言 `AppConfig()` 的默认值,不能只断言 yaml |
| 2 | Windows **无 optuna/torch**(设计如此) | 碰 tuner/worker 的测试**只能在 A800 验**;`PYTHONPATH=src` 必须显式给(包未安装进 venv) |
| 3 | **A800 是权威测试机** | 每个阶段收尾跑 `PYTHONPATH=src /root/autodl-tmp/orch-venv/bin/python -m pytest tests/ -q` |
| 4 | box 1 是 **v2 实验机**(branch v2 @ `062f8e8`,有本地改动) | **绝不 scp 覆盖**;需要在它上面跑脚本时用隔离目录(`/tmp/s1acc` 模式) |
| 5 | 5 个 run 只用了 **9 个改写轮** | 任何 per-round 机制每 run 个位数样本 ⇒ **S2d 的有效性第一轮测不出来**,只能累积 |
| 6 | 对照 run **必须同机**(box 3 = Triton 3.4.0,box 1 = 3.5.1,G23 共变因素) | 一对 run 内部不可跨机 |

**scp 到任何远端 checkout 之前**:先 `git status --porcelain`,并找 `linux-server/*.linux.py` 变体(A800 现有 3 个:`cli` / `runtime` / `worker_client`)—— 有变体的文件**主线版本不得覆盖**。

## 实验终态后的执行步骤

1. 核对完成文件与 worker 状态，区分成功/失败；先完成当前结果审计、核心证据导出及 GitHub 留档。暂停启动下一批大实验，保留当前完成守候正常投递。
2. 用本轮 metadata census 更新明确文件清单；检查活跃/保留依赖和引用。对已存在本地的归档核对成员、大小、原文件 SHA；对本地 Git 副本核对提交、实际文件及 dirty/untracked 差异。
3. 对缺失的冷证据分批从 SSH **直接流式归档到本地**，不在仅余3.5 GiB的服务器先生成几十 GiB临时压缩包，不搬到系统盘或 `/dev/shm`。保留相对路径、模式、符号/硬链接语义；完成后对 archive 成员内容哈希逐一验证，并核对服务器文件期间未变。中断的 `.partial` 不算完成。
4. 写入该批归档索引和恢复命令后，只删除清单中已完整保管且无需在线的服务器副本。旧实验根保留小型结果/索引或 `ARCHIVED.json`，清楚指出需恢复的原始文件。删除路径严格限定为本次核实的绝对路径，不用日期通配符清空整目录。
5. 检查保留版本 source/adapter/bundle/reference 可解析、必要冷文件有恢复入口、现存符号链接无未说明损坏；记录前后 df、真正释放字节及未处理项，推送 GitHub `v6`。之后再安排下一批实验。

私有配置/会话库不放公开 GitHub。本地冷归档若包含敏感文件，应保持本地私有；公开记录只写路径、哈希和恢复说明。可重建的失败下载片段可在核实不用后直接清理，不要求保存其无用的大文件内容；研究原始证据仍须完整保存。

这属于实验维护，不给 Agent/API 加额度、不改变目标/质量/搜索逻辑，也不新增复杂自动淘汰系统。后续每批结束后及时做同类冷归档，服务器保留近期可运行状态和必要热数据，避免把全量历史无限堆积。

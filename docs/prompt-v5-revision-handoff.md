## 你必须先读的两份材料

1. **`docs/window1-results.md`** —— 四个 12h run 的完整读数(两个 off 臂 + 两个 active pilot,

2. **`docs/review-research-v5.md`** —— 我们对 v5 文档的评审,列出五条必须修订项
   与两项 v5 文档不知道但现在就能用的资产。每条都带 `file:line` 或实测数字。

**判读纪律(违反其中任何一条,你的修订会被退回):**

- **只信盘上 `events.jsonl` 的读数。** 不要从事件名推断结果——形如 `*_DECIDED` /
  `*_ATTRIBUTED` 的过去分词事件只表示"该步跑完了",判决在 payload 里,
  且 `*_FAILED` 与它并存。历史上数事件当结果曾把某个数夸大 33 倍。
- **终值只在 `RUN_FINISHED.summary.best`**,不在 `payload.best`。
- **不要把不同机器或不同任务的数字并表。** box4 是 8352V、box1 是 8358P,

- **`speedup_vs_eager` 不可报**(它把 fp16 与 fp32 混比)。只报 `same_precision_speedup`。

## 五项必须完成的修订

### 修订 1:把 H2 拆成两半,因为它的两半答案相反

v5 文档 §12 的 **H2** 是:「固定搭档响应比混合搭档的边际历史更可靠,
**并能在普通坐标测量之外改善方向判断及后续结构改写**」。

实测把这句劈成两半:

- **前半(测量可靠性)已确证**:条件化中位 |误差| 0.0039 vs 边际 0.1963(l3:43,n=12,**50 倍**);
  0.0031 vs 0.0802(l3:21,n=11,**26 倍**);符号一致 12/12 与 10/11 vs 边际 5/12 与 7/11。
  边际的失败形状是**符号反转**而非量级偏差(最极端一例:真值 −0.7362,边际读 +0.5136)。
- **后半(行动收益)已否证**:六个投递点终局 **0 赢 / 4 输 / 2 平**,
  败幅 5.4–8.8%,六个点全部双侧 n≥2 真被测量,机制走完了全链
  (找到墙 → 铸有向 token → 投递新值 → 采样器真的抽了它)。

**要做的**:
1. 把 H2 拆成 **H2a(测量可靠性,已有 n=23 双任务证据)** 与 **H2b(行动收益,已有反向证据)**。
2. H2a **不要**再列为待检验——那会花预算重新验证已知结论。改为"已确证,
   v5 的任务是把它推广到新目标"。
3. H2b 的实施设计要针对「**为什么测得准却投不对**」,不是再测一次「是否投得对」。
4. §11 的 C2 证据义务栏里"**收益覆盖成本**"这个分句,在行动层已知未满足。
   保守措辞必须落到:**"更早、更可靠、定量更准"可主张;"因此投递的取值更好"不可主张。**

### 修订 2:阈值问题比 v5 文档写的更严重

v5 文档 §6.1 说「旧 4% 门与每端两次 fresh trial 不能直接移植到内存、吞吐、成功率或完整生成」。
方向对,但**低估了程度**。

实测:N1 是一个 A/A 对——两臂 **125 个配置键逐位相同**、读**同一个**冻结种子集
(四个候选的 `source_sha` 已逐位核对全同)。它测出的**配对**噪声底是:

- 逐候选:0.51% / 1.41% / 4.97% / **10.85%**(中位 3.19%)
- 端到端:**−11.72%**

⇒ **τ 的 4% 下限对延迟这个原生目标本身就已比真实配对噪声底小 2.7 倍。**
所以问题不是"4% 是延迟专用",而是**"4% 从来不是任何目标的合法阈值,
它是一个未经噪声标定的猜测"**。

另一处要**如实改成对 v5 有利**的:v5 §6.1 担心"负值不能进入旧的正值 log 门"。
实现上这**已经是安全失败而非静默腐化**——`gates.py:41-49` 的 `rho()` 对
少于 2 个复现值或任何非正值返回 `None`(UNKNOWN,**不是 0**),
`gates.py:101-104` 对非正复现值直接 `quality_ok=False` 且不出门。
⇒ `J=−throughput` 的后果是"**拒绝出门**",不是"算出错数"。
把这句从"风险"改写成"**已有的正确降级行为,新目标必须保持这个性质**"。

**要做的**:§6.1 的阈值来源从"目标特定"升级为
「**每个目标 × 每个场地都必须由配对 A/A pilot 标定;4% 不作为任何目标的缺省下限**」;
并明确新阈值方案必须复用 `rho()` 的 UNKNOWN 语义(缺复现 ⇒ 不出门,**不补 epsilon**)。

### 修订 3:探针层拿不到软墙,这是实施必做项而不是"证据限制"

v5 文档 §5 把「**经验转折**:spill、物化或访存行为在哪里变化」列为 C1 的第三类边界,
§2 则把它记作"证据限制"。

实测:两个 active pilot 的**软墙都是 0**,且这是**结构性的**——
compile-only 探针在 warmup 编译期读不到 `n_spills`(硬墙可用;软墙只能从真实 trial 读)。
硬墙本身很健康:l3:43 **31 道 / 12 个已探空间(共 19)**,l3:21 **12 道 / 11 of 17**。

**对 v5 的后果比对 v4 更重**:v5 要把目标扩到内存,而 `peak_alloc_bytes` /
`peak_reserved_bytes` 同样**只在真实 trial 的 profile 里**,探针不跑就没有。
若 C1 要为内存目标提供"经验转折",探针层必须先能采集这些量,
否则 C1 对内存的三类边界表里第三类**恒为空**,而 v5 §5 的收益论证依赖它。

**要做的**:把这条从 §2 的"证据限制"移到 §8 的工作包,写成:
「**目标扩展到资源型指标时,探针层必须先具备该指标的采集能力;
compile-only 探针的能力边界要按指标逐项声明,不能假定沿用延迟探针的覆盖面。**」

### 修订 4:§12.1 的二因子设计按当前实现不可执行,把首选与退路对调

v5 文档 §12.1 首选 `C1 on/off × C2 on/off` 二因子,末尾才给退路
「若没有 C1 就无法定义 C2 域,改用嵌套三臂」。

按当前实现,**退路才是唯一可行路径**:
- C4 的**扫描轴域来自探针发现的墙** ⇒ 没有 C1 的资源解释就没有 C2 的轴;
- 现有开关是单一的 `v4.conditional_scan.mode ∈ {off, observe, active}`(缺省 `off`),
  `mode=off` **同时**关掉 C1 的条件化解释与 C2 的响应测量 ⇒ **这是嵌套,不是因子**;
- 另有互斥约束(`config.py:787`):`mode=active` 与 `v3.slope_guide.enabled=true` 不可同开。

把二因子写成首选,实施时会先撞墙再回退,纯浪费一个窗口。

**要做的**:
1. §12.1 的**首选与退路对调**,并注明理由(轴域依赖 C1 ⇒ 因子不可分)。
2. §12.1 里"C1 off 保留相同原始资源信息"要写清在实现上意味着什么:
   `mode=off` 仍然无条件把资源向量写盘(`DIMENSION_STATE` 事件),
   **只是不进 prompt**。这正是需要的"共有底座",应**引用**而不是重新设计。

### 修订 5:给 §13 的八张面板排优先级,并给出最小集合

v5 文档 §13 列了 U / M / P / A / G / L / W / X 八张面板;§15 说"不是全部必做",
但**没有给优先序或最小集合**——这让文档无法进入排期。

实测代价基准(窗口 1):

| 量 | 实测 |
|---|---|
| 一个 12h run 的墙钟 | 12.24 – 12.97h(超时量 +0.24 … +0.97h) |
| 一个 12h run 的 **GPU 墙钟** | 3.86 – 4.16h(其余是 agent 调用与编译) |
| 一个 run 的产出 | **一个场地、一个臂** |
| 可用硬件 | 两台 × 2 张 4090(24GB)。**三张可用卡全是 4090,A800 拒连** |

⇒ **一个窗口 = 两台并行 = 最多 4 个臂。** 由此:
- **M 面板**嵌套三臂 = 1 个窗口(二因子 4 臂也是 1 个,但见修订 4:不可执行)
- **X 面板**要在 M 之上再乘一遍 ⇒ 至少 2–3 个窗口
- **L 面板**(Qwen3-8B 完整生成):bf16 权重约 16GB + KV,**单卡 24GB 装得下但无余量**;
  且 §13.3 自己要求"加载与初始化计入搜索总成本",而窗口 1 的结构是
  GPU 墙钟只占总时长 32% ⇒ **加载会吃掉一个臂相当大的比例**。另:box4 的 HF cache 为空。
- **W 面板**(SDXL 完整出图)同理。

**要做的**:
1. §13 表格增加一栏「**优先级**」。
2. 明确最小集合为 **U → P → M(嵌套三臂)**,理由:U 面板 0 GPU 且是一切前置;
   P 面板可在既有数据上离线做(见下"资产 1");M 面板是唯一必须烧 GPU 的机制识别。
3. **G / L / W / X 明确标为"取决于 M 的结果"**:若 M 显示 C1/C2 增量为 0,
   这四张面板的收益前提不成立,应先改设计而不是照跑。

## 两项 v5 文档不知道、但现在就能用的资产

### 资产 1:§12.2 的"离线重评分基线"今天就能跑,0 GPU

v5 文档 §12.2 说"固定候选库的离线重评分是很强、很便宜的基线,应先做"。
**这句完全正确,但 v5 把它写成了未来工作——数据其实已经在盘上。**

窗口 1 四个 run 共 **3,000 条 `TRIAL_DONE`**,每条的 `trial.profile` 已带:

```

peak_above_resident_bytes, threads_launched, n_regs, n_spills, shared_bytes,
occupancy{occupancy, active_warps, blocks_per_sm, limiter, by_regs, by_shared, by_warps},
sass{tensor_core, spill_store, spill_load, global_load, global_store, shared_load, ...},
compile_s, wall_ms, cpu_issue_ms, overhead_gpu_ms
```

⇒ **"若目标换成最小 peak memory,这四个 run 里谁会赢?与延迟赢家是同一个吗?"
现在就能回答,零 GPU。** 而它直接检验 v5 §10.2 推演的核心假设:
**目标切换会不会改变冠军**。

- 若**不会**:§13 的 G / W 面板价值大幅下降,应缩减;
- 若**会**:那是 v5 最强的一张图,而且**已有数据就能画**。

**要做的**:把 §12.2 与 §13 的 G 面板改写为
「**已有数据的离线重评分先行,且它是 v5 的第一项可交付**」,并附可用字段清单。

### 资产 2:§12.3 要求的两条纪律,现有实现已经满足——不要重新设计

v5 §12.3 要求「边际预测与条件预测使用同一历史截止时刻和相同发现/留出分离」+
「保留 P2′ 的 legacy 分母,不能只筛通过方向门的子集再评估校准」。

**两条现有实现都已做到**(`scripts/probes/v41_p2prime.py`):
- 边际预测用「该 C4 关闭**前**已有的 trial」重算(在追加该 contrast **之前**快照前缀);
- 分母是**全部 fresh-complete C4**,包含未铸币(`unresolved`)的那些;
- 三种拒绝原因分开计,不混进"边际误差"。

**要做的**:v5 应**引用**这套实现作为既有正确基线,不要重新设计校准协议。
新目标可另做按 pilot 标定的响应实验,但**不得覆盖或重新解释旧 P2′**。

## 关于实施时机(写进修订版的结论章)

**不要在当前实验结束前实施 v5。** 三条理由:

1. **v5 §8 要改的 `robust_ms` 评分链(53 处引用、11 个文件;`latency_ms` 108 处、
   18 / 70 个文件)与 analyst / rewriter 的输入语义,是主对照实验两臂的共享部分。**
   主实验的自变量只有 `conditional_scan.mode` **一个键**(两臂 125 个配置键逐位相同,已核对)。
   动共享部分 ⇒ 新旧不可比。历史教训:某次对照实验两臂交付都是 0、
   自变量形同虚设,24 GPU·h 白跑。
2. **待跑的主对照对会直接回答 v5 §5 / §7 两个工作包的收益前提。**
   我们新增了第五档归因(改写是否**测量上**解开了那道墙):
   pilot-p1 上被简报父代的 4 个改写解开 3 个(拒绝率 24%→8%,best −17.0%,**赢家就在其中**),
   **但 off 臂也解开 4/8**,且两个 active pilot **方向相反**(p1 解 3/4 vs p2 解 0/4)。
   ⇒ 这一档的臂差**只有同机同任务的主对照对能测**。若臂差为 0,
   v5 §5 / §7 的收益前提不成立,应先改设计。
3. **但"资产 1"的离线重评分现在就该做**——它不碰运行中的任何代码,零成本零风险。

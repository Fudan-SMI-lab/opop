# 运行中观察:一次 split3 超时造成的 5× trial 数差,以及它为什么不是臂间差异

**日期** 2026-09-11 · **两臂** box1 对照 `run-l3-43-20260911-053020` / box2 处理 `run-l3-43-20260911-052630`,均 L3:43,均启动于 `dceda97`

## 观察到的现象与它**不是**什么

启动后 ~1.4h,box2 有 80 个 trial 而 box1 只有 16–23 个。**5× 的差会毁掉在同等墙钟下的任何对比**,所以逐个排除:

| 假设 | 实测 | 结论 |
|---|---|---|
| 诊断开关拖慢了调参 | 诊断在调参**之后**运行 | 原理上不可能 |
| 每 trial 更贵 | `compile_s` 中位 **0.33 vs 0.32 s** | 排除 |
| 工具链不同 | 两臂 worker 都是 **torch 2.13.0+cu129 / triton 3.7.1** | 排除(两个 venv 名字不同但版本相同) |
| agent 时间不同 | box1 0.33h / box2 0.52h —— **box1 花得更少** | 方向相反 |
| 单 trial 节奏更慢 | 每 trial 间隔中位 **box1 20.5s < box2 29.7s** | 方向相反 |

**真正的原因**:box1 有**一次 1800s 超时**。逐 10 分钟桶的 trial 数直接显示出来:

```
BOX1  +20min: 5    +30~+60min: 0 0 0 0    +70min: 7   +80min: 12
BOX2  +30min: 17   +40min: 21   +50min: 8  +60min: 13  +70min: 17
```

**box1 的速率在最新一桶恢复到 12/10min**,与 box2 的 17/21 同一量级。停顿是一次性事件,不是系统性的臂间差异。扣掉超时与 agent 时间后 box1 是 38.9 trial/可用小时、box2 是 86.1 —— 这个残余差仍在,但它落在**两臂候选本就不同**这个合法自由度里(两臂不要求生成相同 kernel,只要求最终按 `final_reeval_ms` 公平比较)。

## 超时的那个配置,以及它对契约改动的意义

```
COMPUTE_DTYPE=ieee  DOT_MODE=split3  BLOCK_M=128  BLOCK_N=64  NUM_WARPS=1  NUM_STAGES=2
job cand-52e0e567-tr-0e97ad4e-eval-34a70a12 exceeded 1800.0s
```

`split3` 把 MMA 数量变成 3 倍。在**最宽的 tile 上只给 1 个 warp**,它不是"慢一些"而是病态地慢 —— 打满 `build_timeout_s 1200 + eval_timeout_s 600 = 1800s` 天花板。

**这是超时机制按配置正确工作,不是缺陷。** 代价可量化:一次占 12h 预算的 **4.17%**。

**记录但不改**:调 timeout 或对 `split3` 加约束都属于改动运行中实验的行为,会毁掉对照/处理对。留到实验结束后的统一分析。若届时 `split3` 的超时呈现为一类(而非 n=1),候选生成侧的自然修法是让 agent 在 `split3` 分支上声明 warp 下界约束 —— 泛化的、由编译期探测决定,而不是硬编码某个 tile。

## 一个差点被我误判的知识点:`NUM_WARPS=1` 不是坏取值

超时发生在 `NUM_WARPS=1`,很容易顺势认为该取值该退休。实测相反:

| | box1 | box2 |
|---|---|---|
| `NUM_WARPS=1` | n=5 ok=4 **best 3.4284 ms** | n=15 ok=11 best 3.4514 ms |
| 其余 warp 取值最好成绩 | 3.5466 / 3.6864 / 3.8528 ms | 3.2128 / 3.3905 / 3.4586 ms |

**`NUM_WARPS=1` 持有 box1 全场最好成绩。** 按失败次数摘掉它会杀死领跑配置 —— 这正是记录在案的"取值 N 次全败即退休"实测 **38.5% 误杀率**的原因:失败几乎总是**条件性的**(取决于搭档取值),这里的条件是 `split3` + 最宽 tile + 1 warp 三者同时。

判据仍然是"无条件性"而不是计数。此处不做任何改动。

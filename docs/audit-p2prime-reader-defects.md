## 0. 审计怎么做的,以及为什么必须这样做

反馈要求"先对应实际 run / raw logs / reader 版本"。照做:

1. **窗口 1 的 run 早于 `axis_f_value` 那个 commit**(63d097d),所以**已发表的数字
   走的是 reader 的墙回退路径**——`UW_PROBE_BATCH.walls` 按 `(space_id, axis)` 取端点,
   再经 `SCAN_BLOCK_ADMITTED` 重键到 scan。审计**逐字复刻**了这条回退,
   否则会评一批与争议对象不同的 contrast(第一版审计正因未复刻而读出 n=0)。
2. 每个 contrast 同时按**四种定义**算边际,使得"哪一项改动移动哪个数字"可分离:

| 定义 | 公式 | 池 | 前缀 |
|---|---|---|---|
| `old` | `(n_med − f_med)/n_med` | 全 run | 截至 `SCAN_BLOCK_DONE` |
| `signfix` | `1 − n_med/f_med` | 全 run | 同上 |
| `scoped` | `1 − n_med/f_med` | **仅该候选** | 同上 |
| `noleak` | `1 − n_med/f_med` | 仅该候选 | **剔除该 C4 自己的 4 个 scan trial** |

`noleak` 的剔除按 `SCAN_POINT_DONE.trial_id` 反查,不靠到达顺序猜角色。

## 1. 指控一:符号与分母不一致 —— **成立,是我的缺陷**

`scanner.py:421-422`:

```python
c.g_d = 1.0 - exp(log(roles["N_d"]) - log(roles["F_d"]))   # = 1 − N/F
c.y   = 1.0 - exp(log(roles["N_v"]) - log(roles["F_v"]))   # 正 = N 更快
```

`v41_p2prime.py:123`(修正前):

```python
return (n_med - f_med) / n_med          # 正 = N 更慢 —— 符号相反, 分母也不同
```

而该函数的 docstring 写着 "Same sign convention as the conditioned g" —— **注释与代码矛盾**。

反馈给的 F=10 / N=8 反例经纯算术核验**正确**:`g_d = y = 0.20`,而旧式给 `g_m = −0.25`,
凭空造出 `|g_m − y| = 0.45` 的表观误差。

**实测**:12 个 contrast 里 `old` 与 `signfix` 符号相反的有 **12/12**(全部)。
例:`c4-9489cb4d` old −0.1176 → signfix +0.1052;`c4-aa93b3b0` old +0.5136 → signfix −1.0559。

## 2. 指控二:跨候选混池 —— **成立**

`v41_p2prime.py:138-141` 把整个 run 里所有 `status=complete` 的 trial 放进同一个列表;
`_marginal_slope` 只按 axis 分桶,**没有 candidate 过滤,也没有 space 过滤**。
`Contrast.candidate_id` 被读进来了(`:64`)却从未用于过滤。

**实测规模**(池大小 `nAll` vs 该候选 `nCand`):

| contrast | nAll | nCand | 混入比例 |
|---|---|---|---|
| c4-9489cb4d | 238 | 10 | **96%** 来自其他候选 |
| c4-4b20ea61 | 281 | 10 | 96% |
| c4-c55eadf4 | 485 | 10 | 98% |
| c4-b93b09a0 | 516 | 41 | 92% |

⇒ 后期 contrast 的"边际"里 **90–98% 的样本来自别的候选实现**。
同名 `BK=32` 在不同实现上是不同的东西。**这条对晚期 contrast 是决定性的。**

## 3. 指控三:留出泄漏 —— **成立,且是结构性的**

生产顺序(`orchestrator.py`):

```
:1324   store.append("TRIAL_DONE", ...)          ← trial 先落盘
:1335   self._conditional_scan_step(...)         ← 之后才折入 scan, 再写 SCAN_BLOCK_DONE
```

⇒ reader 在 `SCAN_BLOCK_DONE` 处切的前缀,**已经包含该 C4 自己的四个 trial**,
其中含 `y` 所依赖的 validation 对。`v41_p2prime.py:157` 的
"the cutoff: trials BEFORE this close" 注释在事件序上成立,**在信息集上不成立**。

**实测**:`own` 列 = 该 C4 自己进入前缀的 trial 数,**12/12 与 11/11 全部是 4**
(四个点全部泄漏,不是部分)。剔除后 l3:43 有 5 个 contrast 变为不可计算
(n 从 12 降到 7),l3:21 从 11 降到 9 —— 说明**部分 contrast 的边际本来完全依赖自己的泄漏点**。

## 4. 修正后的数字:优势没缩小,方向反而更强

| run | 定义 | n | 边际中位 \|误差\| | 条件化中位 | 倍数 | 边际符号一致 |
|---|---|---|---|---|---|---|
| **l3:43** | old(已发表) | 12 | 0.1963 | 0.0039 | **50.9x** | 5/12 |
| | signfix | 12 | 0.1795 | 0.0039 | 46.5x | 7/12 |
| | scoped | 12 | 0.2392 | 0.0039 | 62.0x | 6/12 |
| | **noleak(最严)** | **7** | **0.1390** | 0.0069 | **20.3x** | **3/7** |
| **l3:21** | old(已发表) | 11 | 0.0802 | 0.0031 | **25.8x** | 7/11 |
| | signfix | 11 | 0.0944 | 0.0031 | 30.3x | 4/11 |
| | scoped | 11 | 0.2471 | 0.0031 | 79.3x | 6/11 |
| | **noleak(最严)** | **9** | **0.1766** | 0.0017 | **104.8x** | 6/9 |

**四条必须一起报的读法:**

1. **倍数在两个 run 上朝相反方向变**:l3:43 50.9x → 20.3x(**变弱**),
   l3:21 25.8x → 104.8x(**变强**)。⇒ **"50 倍/26 倍"这两个具体数字不能再引用**,
   它们是三个缺陷叠加下的产物。可引用的是**方向**:四种定义、两个 run、共 8 组读数里,
   条件化的中位误差**全部**低于边际,倍数区间 **20x – 105x**。
2. **`n` 变小是重要信息,不是噪声**:剔除泄漏后 l3:43 从 12 降到 7、l3:21 从 11 降到 9。
   ⇒ **5 个与 2 个 contrast 的边际预测本来完全建立在它自己的留出点上。**
   这本身就是"边际在该时点无法作预测"的证据,但**必须作为分母缺失报告**,
   不能当成条件化胜出。
3. **符号一致性是真正受损的读数**:l3:43 的边际符号一致率 5/12 → **3/7**(43%),
   l3:21 7/11 → 6/9(67%)。修正后 l3:21 的 `signfix` 掉到 **4/11(36%)**。
   ⇒ "边际会指反方向"这个**定性**结论**加强**了,但**具体比例必须按新口径重算后再引用**。
4. **条件化侧的数字也动了**(0.0039 → 0.0069;0.0031 → 0.0017),因为可比子集变了。
   ⇒ 任何倍数都必须与它的 n 和定义一起给。

## 5. 采纳的结论与拒绝的推论

**采纳(证据充分)**:三项指控全部成立;已发表的 50.9x / 25.8x 与两个符号一致率
**暂停引用**;`v41_p2prime.py` 需修 reader(符号、候选作用域、泄漏剔除),
且**必须保留旧定义与旧数字**,新分析另行标注。

**拒绝(反馈的推论超出其证据)**:反馈 §2 说"当前证据不支持预判更正方向"。
**实测给出了方向**:8 组读数中条件化全部胜出,倍数 20x–105x。
所以正确表述不是"优势待定",而是:

> **条件化优于边际这一定性结论在四种定义下均成立(倍数 20x–105x,两个 run、
> 共 8 组读数);但先前发表的 50.9x / 25.8x 两个点估计不可引用,
> 因为它们同时含符号错误、跨候选混池与留出泄漏三项缺陷。**

**同意反馈的方法学要求**:修核时保留 `no_slope` / `values_unsampled` / `thin_bucket` /
`endpoints_not_journalled` 四类拒答原因分开计;主分母保留全部 fresh-complete C4
(含 unresolved);23 个 contrast 来自 2 个 run,**不是 23 次独立搜索重复**,
任务内与候选内相关性必须披露;"更早"需要独立的时点或成本证据,预测精度不蕴含它。

**一处必须指出反馈自身的问题,但它的核心指控成立**:§5 说我"一边宣称 4% 在任何场合都不合法,
一边据此确定两例平局并普遍否证行动收益"。**这个自相矛盾的指控成立**——我在 §4 用 4% 判 tie,
同时在别处论证 4% 不是合法阈值。两者不能并存。

**改用 N1 实测的配对底(10.85%)重算六个投递点**(`(at−else)/else`):

| run | 空间 | 轴 | 投递值最优 | 其他值最优 | 败幅 | τ=4% | τ=10.85% |
|---|---|---|---|---|---|---|---|
| p1 | sp-574a1146 | COMPUTE_DTYPE | 3.1042 | 3.0371 | +2.2% | tie | tie |
| p1 | sp-603e7d8f | BK | 3.6728 | 3.3771 | +8.8% | LOSS | **tie** |
| p1 | sp-bc082f52 | COMPUTE_DTYPE | 3.2817 | 3.0306 | +8.3% | LOSS | **tie** |
| p1 | sp-d899e57c | BK | 3.5473 | 3.4666 | +2.3% | tie | tie |
| p2 | sp-54aeb248 | BLOCK_N_PROJ | 5.2567 | 4.9162 | +6.9% | LOSS | **tie** |
| p2 | sp-bb386a2c | GEMM_STAGES | 4.4191 | 4.1923 | +5.4% | LOSS | **tie** |

**τ=4%:4 输 / 2 平 / 0 赢。τ=10.85%:0 输 / 6 平 / 0 赢。**

> **⚠ 本节结论随后被再次更正,见 `docs/reply-to-feedback-review-research-v5.md` §2.2。**
> 10.85% 经实测**不是测量噪声**(N1 四个种子上两臂最优配置全都不同,10.85% 那个差 11 个 knob)。
> 真正的同配置 A/A 噪声是 **median 1.03% / p90 2.50% / max 5.33%**(13 个 byte-identical 配置)。
> 投递点该用 **5.33%** ⇒ **回到 4 输 2 平**,与 4% 同判决。**下面"全部不可判"的表述作废。**

⇒ **按配对噪声底,六个投递点全部落在噪声内。行动层既不是胜、也不是负,而是不可判。**
我先前"0 赢 4 输 2 平"的表述**用了一把我自己论证过不合法的尺子**,必须改写为:

> **六个投递点的败幅 2.2%–8.8% 全部小于同机配对 A/A 底 10.85% ⇒ 在本预算下
> 行动层的效应不可判(既未观察到收益,也未证伪收益)。**

这比原表述**更弱**,而且它把反馈 §5 要求的"收益覆盖成本尚未建立"落实为可复核的算术。
⚠ 但**同一把尺子要一致地用**:若采用 10.85% 作 tie 带,则它也是 §3.1 第五档
拒绝率变化、以及 P3 的判据;不能只在对己不利处换尺子。

# 条件扫描 v4 审查：接受核心，实施前补齐自洽性与实验边界

> 日期：2026-09-15。性质：独立文档审查，不是实施授权，也不是已批准的 v5。
> 对象：[实施 v4](implementation-conditional-scan-v4.md)，本轮完整读取 232 行；下文 L 均指该版本。
> 本轮只新增本文。反例均为构造，算术为纯计算，不是 GPU、回放或源码执行结果。

## 0. 总裁决与优先级

**v4 的核心合理，应保留；但规格尚不自洽，不能按现有文字直接实施。**
问题不是“条件斜率不能用”，而是已批准的方向政策没有贯穿 token、几何、排序，且实验解释仍过宽。
无需另建证据平台、增加模式、默认八对、禁止斜率，或重开已裁定的预算与历史上下文议题。

| 优先项 | 分类 | 最小处理 |
|---|---|---|
| 方向链：token、几何、排序 | 主要阻断，确定冲突 | 同一冻结来源派生行动方向，三处同步修改 |
| 实验估计对象与竞争机会 | 主要阻断，科学解释 | 区分来源施用与增益大小排序，报告真实竞争 |
| observe 的 rho 可观测性 | 主要阻断，统计层级错误 | trial 内代理与跨 fresh trial 重复分开 |
| bootstrap 分支和累计成本 | 主要阻断，规格歧义 | 明列五种入口/结果，不用重试成本重冻 D |
| 续空间预算、E4 预留、通用轴对数 | 实施前澄清，含确定错句 | 修限定词、补 4 槽、参数化组合数 |
| 优先 E 相位与适用时刻 | 需明确选定的策略 | 写确定转移表与 admission/start 边界 |

### 已修好的部分，不应回退

- L38 至 L45、L57 至 L59：C4 来源与 E1 行动解耦，首个循环由八槽降为五槽，确实减少行动税。
- L83 至 L88：cadence + ready work 修掉“没有新变化就永远不发下一批”的缺口，仍保留预算与单在途限制。
- L131 至 L146：一来源一次、admission 消费、失败不退、E 不递归生 token，完成钩子减少可避免等待。
- L155 至 L158：允许负墙向来源在反向重新过门后向内行动，符合已批准裁决，不再争论是否应允许。
- L180 至 L188：C4/P2 与打印门保留，不靠放松统计门制造 E；L102 至 L110 的 W 公平轮转也值得保留。
- L174 至 L178：已要求 actual rank-changed selections 和三态漏斗，这是正确方向，但计数本身不创造竞争机会。

## 1. 第一优先：方向必须贯穿整条消费链

### 1.1 token 入口让已批准的向内分支不可达

L39、L131 至 L132 只给“朝墙正向打印门通过”的 C4 发 token；L150 又把 token 作为 E 必要条件。
L155 至 L158 却允许朝墙负、反向正的来源向内行动，L170 至 L172 还保留负向不进改善队列。
这不是可选审美政策，而是同一版的入口和行为互相排斥。

【构造】双端 fresh 重复均为 `N={100,100}`、`F={80,80}`，质量通过，`rho=0`、`tau=4%`。
墙向 `g=1-100/80=-25%`，`I=[-25%,-25%]`，不能过墙向正门。
交换集合重算得 `I_rev=[20%,20%]`，通过向内正门；现行入口仍不给 token，故永远无法行动。

**最小修补：来源不可变，行动方向派生。**
1. C4 原始 F/N 几何、发现/验证角色、`g_d`、`y` 与 P2 分母全部保持冻结。
2. fresh-complete 且质量合格后，计算 `J_out=I`、`J_in=I_rev`。
3. 只有对应 `lower(J)>tau` 的方向能生成一次性来源 token，并记录 action direction。
4. 同一 source contrast 至多一个 token，不按两个方向各发一次，也不对增益盲取绝对值。

这里最多一个方向可过正门：out 通过要求 `max(N)<min(F)`，in 通过要求 `max(F)<min(N)`。
正延迟下两者不可能同时成立；严格正阈值只会进一步缩小集合。
原墙向负事实仍按原打印门带符号披露，行动旁列反向区间及方向，不能覆盖原墙向 g。
不得看完结果重定向 `g_d/y`，也不得按有无 token 筛选 P2 留出样本来宣称预测可靠。

### 1.2 token 修好后，旧几何仍会向错误一侧取点

L167 至 L168 继承“近墙端外侧紧邻 → 区间内 → 内侧”，只适合 outward。
【构造】声明顺序 `x0, x1=F(80), x2=N(100), x3`，朝墙为索引增大；x0/x3 都是合法未测点。
已观察改善在 x0 一侧，但照旧规则会先选 x3；给它贴 inward 标签不能改变实际坐标。
新点收益未知，这个例子只证明方向和几何冲突，不声称 x0 实测一定赢。

| 行动方向 | 首选延伸 | 区间内细化 |
|---|---|---|
| outward | N 外侧朝墙紧邻的未测值 | 优先靠近有利端 N |
| inward | F 外侧离墙紧邻的未测值 | 优先靠近有利端 F |

若还保留相反一侧的最后回退，须明确它是几何回退，不能冒称已有该移动方向的改善证据。
两方向都保持同一已知 screen-fit 分量、不跨 unknown/拒绝/缺口、完整参数合法及完整生产验证。
这只镜像旧优先序，不增加预测器，也不把资源 fit 当新点性能保证。

### 1.3 排序与新旧来源也要使用同一方向语义

L170 继承 v3 的原始 `mean(log F)-mean(log N)`，会把向内合格来源排成负分。
对应方向过 J 门之后，outward 用该分数，inward 用 `mean(log N)-mean(log F)`。
仍按声明 choice 跨度分层、层间原轮转、层内排序；不是取绝对物理导数，也不改跨轴单位政策。
L171 的排除应指“没有合格改善行动方向”，不能按原墙向负号排掉已经合格的 inward。

L139 至 L140 的“较新完整负/unknown 压旧正”原则正确，但必须区分旧方向与整个来源。
新的同可比对象完整 C4 若墙向转负，应撤销旧 outward 资格；若 Jin 合格，可生成新来源的 inward token。
新完整 unknown 仍压下旧资格；较新 provisional 形状或 E2 降级对比不覆盖旧完整 C4。
同可比对象键是同执行身份、精确搭档、轴、冻结 F/N、协议；immutable contrast ID 标识各次来源。
对象键用于比较新旧，contrast ID 用于唯一消费，不能把“ID 不同”误解为永不压旧。
这不是恢复多段覆盖政策，不要求新 schema 平台，也不能以同轴最新一条覆盖不同 F/N。

## 2. 第二优先：即时消费可能消除增益排序的可识别机会

依据 L134 至 L146 的一次消费和优先钩子，以及 L174 至 L176、L203 至 L206 的对照继承。
**能测到来源并施用一次，不等于能测出按来源增益大小排序的价值。**

### 2.1 单来源池的条件证明

限定为冷启动、串行完成 C、无继承 pending 来源，且每个合格 C 在下一个 C 前就获 E 准入消费。
初始 token 池为 0；一次 C 至多增加 1；下一次 E 消费后回到 0；E 输出不生成 token。
归纳可得每次 E 决策的合格来源池至多 1，任意多个这样的循环也不会产生大小竞争。
这不是所有运行的定理：继承多个 pending、优先 E 无法准入而继续 C 等情况可以打破前提。
必须区分 pending 总数和当前合格数，不把不适用 token 也算成真实竞争者。

【预算构造】B=80 时 Q=8，C4+E1 用 5，剩 3，不能再发新 C4。
通常首循环只有一个来源；即使跨很多空间累计很多 E1，仍可能每次都只有唯一候选 X。
同集合、同正向/反向门、同几何时，RR 与 gain 都选 X，E1 事件多不自动增加排名差异。

### 2.2 对照究竟估计什么

v4 §8 继承 v3 L190 至 L193 的宽泛解释“斜率改变搜索目标是否有用”，需要收窄。
若 RR 共享斜率资格门与实测方向，它已经使用斜率，比较只识别**增益大小优先**，不是“是否使用斜率”。
两臂应明确共享 token 优先权及 C/E 决策，只让同层来源的 gain rank 与 RR rank 不同。
若 RR 可选 C 而另一臂强制优先 E，改变的是“优先消费 + 增益排序”组合，不再是单一大小排序因素。
不能两种解释混用；继承旧对照不等于完成新 token 规则下的因素定义。

L174 至 L176 已要求真实 rank difference，值得肯定；它能发现没有对照差异，却不能制造差异。
L163 把 E1 称为“施用事件”可以保留为仪器调用口径，不能自动解释为反事实目标确实改变。
局部 P2 仍可检验冻结 F/N 的留出关系；来源被用、选中好新点、完整 C2 成立是三件事。

### 2.3 最小修补是解释和少量决策记录，不是强制积攒来源

保留即时行动，每次决策记录 pending 数、eligible E source 数、同跨度竞争集大小。
同一 policy snapshot 保存 RR target、C/E target、实际选择及差异频数。
RR 目标必须从快照纯计算，不为反事实调用 TPE ask，不改变 RNG、队列或游标。
在新点结果出现前定义 `eligible>=2` 分层；多个来源落在不同跨度层，仍不保证有同层 gain 竞争。
若实际竞争机会为 0，结论是“本样本未识别增益排序价值”，不是排序有效、无效或 C2 为假。
若机制永久产生相同选择，多跑相同路径仍不可识别，不只是样本量不足或功效低。

若另要检验单 token 的 USE 效应，可另批 slope-aware 对 blind-geometric 的问题。
该可选对照可匹配 C4、Q/B 与合法 guard/几何，但盲臂不按实测门或方向决定行动，不伪造打印证据。
实际行动剂量未必相等，不强制配平；这不是本审查要求的第三臂，更不能静默替换已批准 RR 设计。
延迟 E 来积攒 N 个来源会损害 freshness 并争夺 Q，不作默认修法。
即时消费有利于施用、却可能不利于大小竞争，是应披露的取舍，不是整个 v4 概念错误。

## 3. observe：20 timings 不能免费变成实际 rho

L187 的“既有 20-timing 数据免费测 rho 量级”与 L205 至 L210、L218 的限定不一致。
单 trial 的 20 样本最多给 trial 内条件噪声代理，如 MAD、自相关或组内重采样敏感性。
实际 rho 要同一完整配置、相同执行条件下至少两次真实 fresh trial；双端 rho 则两端各需这样的重复。
若自然历史已含兼容重复，可以分层计算其观察 rho；缓存复制、换 trial ID 都不增加重复数。
没有 fresh 重复就记 rho UNKNOWN，不从 raw CV 或 trial 内代理补值。

observe 仍是零额外 LATENCY trial，主动编译探针照常付费；“无额外 timing”不是全链零成本。
L184 至 L186 的约 78% 只能保留为条件模型诊断，不能写成实际 E 失败率。
它要求 raw CV=.16、iid 正态、n=20 中位数渐近近似、trial 独立及两端重复差独立。
还需无额外状态偏移与小相对误差近似；有限偶数样本、自相关或非正态都可改变结果。
详细推导见 [E 分析 §2.1 至 §2.2](analysis-e-opportunity-and-conditional-scan-v3.md)，这里不重复长数学。
L207 至 L210 的“前五项可测”也应附自然兼容 fresh 重复存在的条件，不把缺数据写成零。

## 4. bootstrap：五种分支写成确定规则

L90 至 L95 混合“首次完整成本冻结 D”和“超时后小重试”，结尾“此后停止”作用域不清。
建议按当前重试条款的意图明确如下，成功首批不是一律停止。

| 情况 | 预算和后续 |
|---|---|
| 入口已有兼容 m_ref | 冻结 D=min(2m_ref,600)，正常准入，不因后续结果重置 |
| 无参考，首批完整成功、成本 c1 | 首批实耗照计，冻结 D=min(2c1,600)，余量足够可继续 |
| 无参考，首批超时 | 固定预声明 BOOTSTRAP 总额 600，c1 全计；可选一次更小批重试 |
| 首批超时但 n=1，或余量/次数不足 | 无法合法缩小或准入，不重试，停止本空间主动诊断 |
| 首批非超时失败 | 原文没有授予重试，默认停止，不扩张成通用失败重试权 |

超时后的唯一重试同时受剩余 600、当前 timeout、run 余量和每空间四次已启动尝试上限约束。
缩点规则须事前声明；现稿未给，至少标成实施前必须确定，不能按首次结果临场挑易成功点。
重试无论成功或失败，之后都 STOP 本空间主动诊断；成功答案可用，自然生产回答仍可补入。
不得用重试成功的成本重新开启 D，也不退首试成本和次数。
【构造】首试 170 秒超时，重试 30 秒成功，已花 200 秒，不能重冻为 D=60 秒再解释旧账。
反过来，首次就完整成功的分支仍能在冻结 D 内继续，不应误写成“所有 bootstrap 后一律停”。
600 与 timeout 是准入/执行限制，锁等待与清理可在其外；不能据此保证全 run 硬墙钟上界。

## 5. 续空间预算：小 B 并非一律没有 E

L60 的 B=20/39“全归 TPE”只对冷启动或无可用继承来源成立，与可变 E1/E2 成本冲突。
L11、L211 的“一切带 token 续空间有结构机会”也过宽，需看接收空间剩余 Q。
最低条件是 `Q_remaining >= 已选行动长度 e`，e 为 1/2/4，并满足 B、时间、新点、身份/搭档各门。
继承合格未消费 token 时，B=10、Q=1 可支付 E1；B=20、Q=2 可支付 E2；B=9、Q=0 不行。
同样 B=20 冷启动不能先取得 C4，不能混用首空间和续空间分母。
L118 至 L119 只写 E1/E2 预留，需显式补 E4 原子预留四个 B 槽和四个扫描机会。
冷启动 B=40 仍无 E，维持已批准 f=.1；B≥50 仅有 C4+E1 预算暴露，不保证全部门通过。
这些是限定词与记账修正，不是增加剂量，也不制造续空间领取额外预算。

## 6. 相位：需要选定语义，不是数学上只有一个答案

L122 至 L123 的普通准入按 requested 相位翻转；L145 的“先 E1 再回原相位”未说明原指何时。
requested C、served C 后相位为 E；requested E、fallback served C 后相位为 C。
“原相位”可指 C 准入前或后，两者不同，不能泛化为翻两次再恢复。
推荐采用 [E 分析 §3.2](analysis-e-opportunity-and-conditional-scan-v3.md) 的最小明确解释：

| C 准入 requested/served | C 后普通相位 | token 优先 E 准入后的相位 |
|---|---|---|
| C / C | E | 明确设 C |
| E / C | C | 明确设 C |

优先准入执行 REGISTERED action kind，不强制 E1；成功 admission 后显式设 C，与 requested 无关。
未能准入则相位不变、token 不消费；普通准入继续旧 requested-flip 规则。
优先钩子不能先套普通 flip 再 restore；这是一项推荐的明确选定，不宣称唯一正确政策。
若作者要恢复 C 后相位，就另写两行结果分别 E/C 的表并明确选定，不能推定已获批准。
预登记 E2/E4 不因预算不够自动降成 E1，除非已有预设规则；默认 E1 只适用于实际选了 E1。

## 7. W 通用性：66 是例子，轮转仍需继承旧细节

L106 至 L110 的“全部 66 对”只适用于 d=12，算法应使用 `choose(d_eligible,2)`。
eligible 轴要求类型受支持且至少两个合法声明值；资源状态 unknown 不能据此排除整个轴。
d=8 为 28 对，d=16 为 120 对；d=12 时 4/66=6.06%、2/66=3.03%，不能严格写 ≤6%、≤3%。
保留稳定索引，不增加资源权重；TARGETED/UNFILTERED 相位按尝试推进，完成模板另记。
目标队列回退到未过滤时仍用同一轴对身份去重，区分 requested/served，避免回退混淆轮转进度。
四角在 W 类别轮转中是一个请求，但其缺角最多占四个 W 点回合，原子预留不等于免费一个点。
显式保留 U/W 交替、空队列回退、批前证据冻结、完整 typed 点去重和仅补缺角规则。
这些来自旧调研 §2.2，v4 写继承不能因少了小标题就被判定已删除，也不能实现时遗忘。
L193 的四角组见证须以完整 scoped 2×2 的实际回答与逐字段检查为前提。
模板尝试不是模板完成，更不自动得到“单独 fit、合改 refused”；字段 unknown 仍是 unknown。
身份、完整域、来源范围可以沿用现有条款，无需扩建通用证据架构。

## 8. 完成钩子是立即评估，不是立即执行

L142 至 L146、L194、L198 至 L201 不保证 enqueue 后立即 ask/start，应分开记 C complete→admit 与 admit→start。
“当前适用”在 ADMISSION 检查还是 START 再检查，需显式选定，不能以“即投递”含混带过。
推荐提交时检查当前适用，实际 trial 保留 committed 完整 PARAMS 与源执行身份，不换成 live partners。
若只因 incumbent 后来换伙伴，已提交点仍按原配置执行，可记 current-at-admission、historical-at-start。
这不同于整个执行身份已改变；后者不能继续声称来源条件相同，须按现有不兼容/失败语义处理。
也不授权在 admission 就故意选已历史化搭档，历史冻结上下文 E 仍按 L16、L230 暂缓。
若 owner 要求 start 时也必须当前适用，需明确 ask 前有界取消与既有失败计费，不默认重型撤销机制。

## 9. 最少纸面 fixtures 与不应新增的“缺陷”

以下只列未来预期，本轮没有编写或运行测试。

| fixture | 预期 |
|---|---|
| 重复 N=100/F=80，x0/x3 合法 | inward token 一次，优先 x0，原墙向 g_d/y 不改 |

L152 至 L153 的 r≤2 是已承认的物理稀缺：合法 C4 后无新 E 点，不是新增代码 bug。

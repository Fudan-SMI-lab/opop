# trial 失败率的正确读法:预筛拦下的不是失败,box3 真实失败率 22% 而非 56%

**日期** 2026-09-11 · 三个在跑的 run,读数来自 on-disk `events.jsonl`

## 起因:我把 box3 的失败率读成 56%

box3 的通知显示 50 个 trial 但逐精度分解只加到 22,于是我读成"56% 失败率,远高于 box1/2",并怀疑 K 扩展打开了一片不可行区域。**两个判断都错了。**

## 一、K 扩展没有打开坏区域

| 空间 | trial | ok | 比例 |
|---|---|---|---|
| `sp-fc83f2bb`(原始) | 40 | 18 | 45% |
| `sp-b2bab578`(K 扩展后) | 10 | 4 | 40% |

40% vs 45%,**基本不变**。扩展加入的小 tile 值既没有变坏、也正是冠军配置的来源(见 `result-fp16-beats-ieee-tenfold-box3.md`)。

## 二、`infeasible_shared_memory` 不是"漏过预筛",而是预筛在工作

17 个 trial 以 `infeasible_shared_memory` 失败,而 `CONFIG_SCREENED_INFEASIBLE` 也正好 17 次。**逐配置比对:17/17 完全重合**,且失败详情第一句就是 `compile-only screen:` ——

```
compile-only screen: _ssd_seq_kernel requires 264704 bytes of shared memory against
this device's per-block opt-in limit of 166912 (159%), so a launch ...
```

机制是:`_screen_config` 在编译期发现不可行 ⇒ 记 `CONFIG_SCREENED_INFEASIBLE` ⇒ **同时把这个 trial 记为失败**,好让 Optuna 学会避开这片区域。它花掉的是**一次编译**,而不是 20 次计时采样 —— 这正是预筛存在的目的:**产生便宜的失败**。

把它算进"失败率"就等于把"省下来的钱"记成"花掉的钱"。

## 三、正确的三 run 对比

| | trial | ok | **预筛拦下** | **真实评测失败** |
|---|---|---|---|---|
| box1 L3:43 | 120 | 80.0% | 19.2% | **0.8%**(1 次 timeout) |
| box2 L3:43 | 200 | 79.0% | 21.0% | **0.0%** |
| box3 L3:48 | 50 | 44.0% | 34.0% | **22.0%**(8 次 correctness + 3 次 runtime) |

box3 的真实失败率是 **22%,不是 56%**。box1/2 则几乎为零 —— 这本身值得记下:**两个 L3:43 臂在 320 个 trial 里只有 1 次真实失败**,预筛把其余全部不可行配置在编译期拦住了。

预筛比例三者都在 19–34%,与记忆里"修法已上线并把 shared-memory 浪费修成 4.42% 且全被预筛拦下"一致 —— 那个 4.42% 说的是**浪费的计时**,而这里 19–34% 说的是**被拦下的配置**,两者不是同一个量。

## 四、box3 的真实失败按精度分组完全一致

8 次 `correctness_mismatch` 有个干净的指纹:**同一精度下不同 tile 读出完全相同的 `frac_within_tol`** —— tf32 全是 `0.976029`,bf16 全是 `0.822258`。**数值失配由精度决定、与 tile 无关。**

- tf32 的 0.976029 距任务噪声底 0.979825 只低 **0.39%**,单看 frac 臂是误杀;
- 但 fp64 相对臂同时以 `ratio_to_reference = 6.786`(阈值 2.0)失败 ⇒ **否决正确**;
- bf16 的 0.822258 远低于噪声底 ⇒ 真实亏空。

据此把 frac-only 审计从 0/134 扩到 **0/142**(95% CP 上界 **2.09%**),见 `result-frac-gate-never-rejects-alone.md`。

## 教训

**报失败率前先分清三类**:(a) 预筛在编译期拦下的 —— 是节省不是失败;(b) 真实评测失败 —— 正确性/运行时/超时;(c) 通过的。把 (a) 计入失败会得到一个虚高两倍以上的数字,并据此怀疑一个正常工作的机制。

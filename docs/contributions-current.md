## C1 · 资源维度对齐 → 到达硬件物理上限

**定义。** 一个能有效对齐算子与环境(硬件)各个资源维度的框架,使算子能够到达硬件物理上限;
基于当前资源维度的使用情况,让 agent 更有效地利用**空闲资源**、**更快**到达物理上限;
并能以此在**多个已达到物理上限的算子**上取性能最优者。

**机制。** `evaluation/dimensions.py` + `digest.py`。`for_prompt()` 是唯一允许产出 agent 可见
资源文本的函数,入口第一行 `assert_no_raw_vector(d)`;每个维度声明自己的 **binding polarity**
(occupancy 低才算绑定、shared_bytes 高才算),不可测就说不可测,屋顶不可达单列 caveat。

### 证据:前半句(到达 + 更快到达)—— **强**

**「对齐优于标签」两次配对同向:**

| 配对 | vector 臂 | label 臂 | 差距 |
|---|---|---|---|
| S2(box2,同箱,干净) | 2.84 ms | 3.11 ms | **−8.68%**(噪声底 3.7 倍) |
| step 3(arm2 vs arm1,跨箱) | 2.49 ms | 2.83 ms | **−12.0%** |

第二次跨箱不干净,但**混淆方向对 vector 不利**:arm2 所在的 box4 CPU 慢 23.8%
(`compile_s` p50 0.423 s vs box1 的 0.321 s,+32%),且少跑 40 个 trial,仍然赢 12%。

**「到达了上限」可直接观测**(`DIMENSION_STATE.binding`,三臂赢家):

| 臂 | 赢家 binding 维度 | 数量 | unreachable ceilings |
|---|---|---|---|
| arm1 | occupancy, n_regs, n_spills | 3 | 无 |
| arm2 | occupancy, n_regs | 2 | 无 |
| arm3 | occupancy | 1 | 无 |

三臂赢家都停在某个资源墙上,且没有"上限测不到"的情况 —— 所以"到达上限"不是修辞,是落盘量。

**「更快到达」有轨迹证据**(best-so-far 在 run 的 25/50/75% 处):

| 臂 | 25% | 50% | 75% | 终值 |
|---|---|---|---|---|
| arm1 `label` | 3.896 | 3.206 | 3.168 | 2.83(后段仍在改善) |
| **arm2 `vector`** | 3.335 | **2.488** | 2.488 | 2.49(**50% 处已到达最终答案**) |
| arm3 `vector`+2e | 3.068 | 3.035 | 3.035 | 2.69 |

arm2 在半程就拿到了它最终的数;同样地,混淆方向不利于它(慢 CPU ⇒ 同一墙钟比例下完成的
trial 更少)。**这是"更快"第一次有轨迹层面的证据,而不是只有终点数字。**

顺带:arm2 的赢家在归一化时间 **0.36** 注册 —— 是四个 run 以来第一个在**前半程**到达的冠军
(此前 4/4 都在后半,均值 0.78,这是当初否掉 Ballooning MAB 的依据)。n=1,且那条规则是
机制性的(改写不可能早于父代调完),所以这是一个**例外**,不是否证。

### 证据:后半句(在已达上限者中取最优)—— **两种裁决规则均已被否证**

1. **固定分母**(都吃满上限则谁快谁效率高):分母固定后离散度压掉为**零** ——
   寄存器 ≥250/255 的赢家延迟仍差 **12.8x**(A800,21 个)/ **2.1x**(box2,16 个);
   赢家资源向量对赢家延迟的 ρ 在两箱间 5/6 维翻符号或塌到 0。
2. **字典序**(平局取资源更省者,因为"有更大提升空间"):承重前提**方向相反** ——
   4/4 个 leaner 候选的剩余增益都**更少**(最极端 0.2% vs 47.0%);且平局本身罕见
   (按各 run 自己的噪声底只有 0–11%)。

⇒ **C1 当前只能宣称「对齐 → 到达上限 + 更快到达」,不能宣称「在已达上限者中选优」。**
后半句若要保留,需要一个新的裁决量,且必须先过这两条否证。

## C2 · 找出「斜率最大但被资源截断」的维度,引导结构改写

**定义。** 基于参数空间的数据,分析出当前哪个参数维度上对性能提升斜率最大、但由于资源限制
导致其取值域被限制;并基于这个信息引导算子**结构改变**(增加其他资源维度的消耗,腾出当前
已达资源上限的维度)。

**机制 = 2e**,三个动词逐一对应:`find_walls` 找截断 → `tail_gain` 量斜率 →
`for_prompt` 引导改写。A3 检验最后那个动词。

### 证据:机制成立(A3 正),端到端无收益

**A3 为正,且走的是设计的那条路径。** 唯一被归因的墙:`cand-dc87a93a` `BLOCK_N` 拒 128,
探针实测 122880 B vs 上限 101376 B(1.212x 超),尾部斜率 +7.5%。两个后代都在
**BLOCK_N=128 上有跑通的 trial**,且**在该取值处**的 `shared_bytes` 降到上限内:

| 后代 | 该取值处 shared_bytes | trial 数 |
|---|---|---|
| `cand-5bd8ddd3` | 77824 B | 4 |
| `cand-e5172b8a` | 45056..98304 B | 25 |

**必须在墙的取值处读,不能在最优点处读**:两个后代在各自最优点是 36864 B 与 **73728 B
(与父代相同)**,后者会让人误判"没降" —— 最优点落在 tuner 偏好的 BLOCK_N 上。

**反事实**:arm2 关了 2e 所以不发墙事件(直接问它"归因的墙"恒为 0、无信息),
改用**出厂的 `find_walls`** 离线跑它自己的 `TuningStats` + 自己的拒绝记录:
**7 个墙 0 个被解开**(2 个维度消失、5 个未尝试)。只看候选确实被改写过的墙:
arm2 **0/2** vs arm3 **1/1**。处理侧 n=1。

**但没有端到端收益,而且不是"测不出差异"——是反向的。**
干净的一对是 arm2 vs arm3(同箱、同 mode、只差 2e):**无 2e 的那臂快 8.0%**,
是再评测噪声底(±4%,符号不稳)的 2.0 倍。**归因是决定性的**:arm3 的获胜者
`cand-c18186fc` 属于 `fam-2ca36f66`,而唯一被归因的墙在 `fam-8e54d0af`
⇒ **墙文本从未进入获胜路径**(全 run 只有 1 个 rewriter 沙箱带该文件;正对照通过:
`fam-8e54d0af` 的两个改写都被正确读作 reached)。成本侧:多花 30.5 s 探针、少产出 2 个改写。

⇒ **C2 的诚实写法 = 机制结果 + 负结果**:「被投递的墙确实被改写腾出了」是可宣称的;
「因此更快」不可宣称。这个负结果本身有价值 —— 它说明**把实测的资源墙告诉 agent
不足以转化为性能**,而这正是 C2 原本假设的那一步。

**注意别与 C3 混同**:2e 的探针只花 run 的 **0.067%**,`walls_skipped_by_cap = 0`
⇒ 它**不分配任何稀缺机时**,它的分配键是 `tail_gain_pct`(实测斜率),不是可靠性。

## C3 · 信息获取效率:把有限的验证机时投到信息增益最大处

**定义。** 待定的新机制。

**候选定义**(`conversion-efficiency-redesign.md` §5.1 第二轮调研收窄的结果):
**「用 agent 自己被实测出的逐维度可靠性来分配验证机时」**。
`declare-then-reconcile` 本身属于 Rehearse(`arXiv:2607.27687`),
GPU 上的预测-纠正闭环属于 GPU Forecasters(`arXiv:2605.31464`),两者都**不能**宣称为本文提出;
可守的只有第三步 —— **用逐维准确率决定测什么**。

**状态:无机制、无实验。** 唯一提案(2c)已于 2026-09-12 取消,理由是落盘读码发现
**它要分配的那笔预算不存在**:`reconcile()`(`evaluation/reconcile.py:141`)读的是那一轮
**已经测好的** `resource_deltas`,不调用任何 evaluator / run_job / prescreen / compile_screen
(`_reconcile_round` 全段 grep 0 命中);而那份 profile **免费覆盖全部 8 个维度**
(box2 12/12、A800 6/6,`declared but never reconciled = 0`)。
要让 2c 成立必须**人为停测某些维度**造出稀缺性,这与它自己引用的
Coverage-Not-Credit(`arXiv:2608.28011`)直接冲突,也违反「不硬编码缩小探索空间」。

### 已有的、可复用的地基(不需要新 GPU 机时)

- **逐维度声明准确率**:71.6% 是 8 维混合的平均;拆开后两箱**同序**,
  `candidate_aten_ops` 88%/100% → `shared_bytes` 36%/20%,**跨度 52/80 个百分点**;
  且维度覆盖均衡(各 12%)⇒ 跨度不是样本量噪声。
- **一个真实的稀缺性**:`only-nine-percent-of-hypotheses-are-ever-implemented` —— analyst 提
  128/78 个假设只有 19/6 个被实现(15%/8%,H1 偏好 22% 对 H3 5%)。
  **改写机时确实稀缺**,而"测哪个假设"是一个真的分配问题。这可能是 C3 的落点,
  但属于**新设计**,需先做调研确认未被占掉。
- **账本准确率是独立信号而非马后炮**:与同轮增益 ρ = **−0.267**。

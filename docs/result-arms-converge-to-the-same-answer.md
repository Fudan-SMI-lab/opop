# 双臂在**结果侧**独立收敛到同一答案:bf16/plain,相差 0.83%

**日期** 2026-09-11 · box1 对照 `run-l3-43-20260911-053020`(129 trial)+ box2 处理 `run-l3-43-20260911-052630`(231 trial)· 读数来自 on-disk `events.jsonl`

## 为什么这条比"配置逐字段相同"更有说服力

此前的可比性证据都是**输入侧**的:

- `audit_arm_comparability.py` —— 两臂 config 7/7 字段一致;
- `compare_calibrations.py` —— 两台机器的天花板与阈值在容差内一致;
- `check_arm_search_parity.py` —— 每空间预算同为 40、速率差是一次 timeout 的尾部。

这些都在说"起点一样"。本条说的是**终点一样** —— 两臂在**各自独立的 TPE 搜索**下落到了同一个答案上。

## 逐精度最优(两臂各自的 best)

| `COMPUTE_DTYPE` | box1 对照 | box2 处理 | 差 |
|---|---|---|---|
| **bf16** | **3.1862** | **3.2128** | **+0.83%** |
| fp16 | 3.3613 | 3.3905 | +0.87% |
| tf32 | 5.2352 | 5.6735 | +8.37% |
| ieee | 16.3538 | 12.6490 | −22.65% |

**三点值得注意:**

1. **排序完全相同**:`bf16 < fp16 < tf32 < ieee`,两臂一致。
2. **冠军精度与 dot 模式完全相同**:两臂都是 **bf16/plain**。这对 J2-5 很重要 —— 最终比较将是同精度同算法的对比,不是拿 bf16 比 fp16。
3. **两个低精度档相差 0.83% / 0.87%**,远在噪声底(borrowed 2.35%、实测 2.99%)之内 —— 而这是**两台不同物理机器**上跑出来的。

## ieee 差 22.65% 有明确原因,不是噪声

box2 的 ieee 最优是 **split3**(12.6490),box1 的是 **plain**(16.3538),且 box1 至今只采样过 1 个 ieee/split3 配置。这与已记录的实证一致:**split3 只在 ieee 下取胜** —— ieee 没有张量核通路,`plain` 走慢的标量回退,而 split3 的 fp16 操作数能进张量核("3 次便宜 MMA 打赢 1 次昂贵非 MMA dot")。

所以这个差异是**采样覆盖差异**,不是机器差异:box2 恰好试到了那条路径。它落在 ieee 这一档上,而 ieee 不是任何一臂的冠军,因此**不影响 J2-5**。

## 一个必须声明的限制

上表全部是 **`tuned_ms`(trial median)**,不是 `final_reeval_ms`。按已记录的规矩,`tuned_ms` 系统性乐观 1.5–6.7%,**宣称胜过基线或宣称双臂差异必须用 `final_reeval_ms`**。所以这里的 0.83% **不是 J2-5 的判决**,只是"两臂正在收敛到同一处"的中途证据。J2-5 的判决要等两个 run 各自的 `RUN_FINISHED.payload.summary.best.final_reeval_ms`,由 `scripts/check_wrapup.py` 用 `max(borrowed 2.35%, 实测延迟底)` 作容差来判。

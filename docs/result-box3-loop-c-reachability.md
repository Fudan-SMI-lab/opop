# box3 是否能进 Loop C:3.53–9.66 h 对 10.23 h 预算,不干预

**日期** 2026-09-11 · box3 (A800) `run-l3-48-20260911-052647`,48 trial 时 · 全部读数来自 on-disk `events.jsonl`

## 起因:第一个候选已飞了 3 h

box3 的第一个候选在 3.4 h 时仍未结束。若这是典型成本,4 个候选装不进剩余的 10.23 h ⇒ **box3 永远到不了 Loop C,对 G27 零贡献**。这是个会影响实验有效性的问题,值得在还有预算时算清。

## 逐阶段实测(候选 1)

| 阶段 | 分钟 |
|---|---|
| parameterize + publish | 64.0(含 resume 间隙) |
| prescreen(40 配置) | 20.4 |
| **调参 40 trial** | **77.6**(116.4 s/trial) |
| analyst(classify + report) | 6.6 |
| K 扩展 + 再 prescreen | 11.0 |
| 预期再调参 40 trial | 77.6 |
| **合计(含扩展)** | **≈193 min = 3.22 h** |

## 116.4 s/trial 是**任务**不是机器

box3 每 trial 116.4 s vs box1/2 的约 25 s,在**更大的卡上**慢 4.6 倍,看着像机器问题。不是:

| | 中位间隔 | best kernel | **中位 kernel** |
|---|---|---|---|
| box1 L3:43 | 25.1 s | 3.186 ms | **5.297 ms** |
| box2 L3:43 | 24.4 s | 3.213 ms | **5.001 ms** |
| box3 L3:48 | 43.2 s | 3.606 ms | **159.539 ms** |

**box3 的中位 kernel 比 L3:43 那对慢 30 倍** —— 每 trial 要跑 20 次计时 + 5 次正确性采样,成本按 kernel 延迟等比放大。所以慢的是 L3:48 这个任务本身。

（另有尾部:top 10% 的间隔占总时间 66%,最慢一条是 2530.9 s 的 `runtime_error`。但与 box1 那次不同,box3 的**主体也确实偏移**了 1.9 倍 —— 中位 43.2 vs 24.4 s —— 所以这里不能像 box1 那样把速率差全部归给尾部。)

## 关键修正:TPE 在学,后续 trial 会更便宜

拿候选 1 全程成本外推是**高估**的。原空间前 9 个成功 trial 的中位 kernel 是 **403.7 ms**,后 9 个是 **47.3 ms** —— 降了 **8.5 倍**。TPE 逐步集中到快配置上,于是每 trial 的计时成本同步下降。

| 假设 | 每候选 | 3 个候选 | 对 10.23 h 预算 |
|---|---|---|---|
| 悲观:候选 1 原样重演 | 3.22 h | 9.66 h | **装不下**(+完成候选 1 的 1.29 h) |
| TPE 照已观测速率学习 | 1.18 h | 3.53 h | **装得下** |

**诚实的答案是区间 3.53–9.66 h,而悲观端装不下。**

## 决定:不干预

两个理由,都不是"看起来还行":

1. **区间的乐观端有实测支撑**(403.7 → 47.3 ms 是这个 run 自己的数据),悲观端假设 TPE 完全不学习,而它明显在学。
2. **没有低风险的修法。** 唯一能直接省时间的旋钮是 `trials_per_space`,而中途改它会**破坏双臂搜索量对等** —— 那正是 `scripts/check_arm_search_parity.py` 存在的理由,per-space 预算不等是比速率差更严重的缺陷。降低 `perf_trials` 同理会改变计时口径,使这个 run 与语料不可比。

按用户既定规则,这属于"高风险/大改动 ⇒ 仅记录,待全部实验结束后统一分析",而不是"确定且低风险 ⇒ 立即修"。

## 若最终确实没进 Loop C,该怎么报告

box3 是**低精度臂、跑 L3:48**,不是 J2-5 那对对照(box1/box2 都是 L3:43)。所以:

- 它不进 Loop C **不影响** J2-5/J2d-9 的双臂比较;
- 但它会使 **G27 的生产证据只来自 L3:43 一个任务**,这必须在报告里说明,不能让"G27 有生产证据了"这句话掩盖样本只覆盖一个任务。

后续实验若要让 L3:48 也进 Loop C,正确的做法是**开跑前**按任务的 kernel 延迟量级调预算(墙钟或 `trials_per_space`),而不是中途改。

## 7. 门 2 判据

**同层竞争 = 0 / 68 个 E 决策**(pilot-p2)⇒ **选 M2b(复制对),不是 M2a**。

成因是算术:`Q = int(0.125 × 40) = 5`,一个 C4 占 4 槽 + 一个 E 占 1 槽
⇒ **每空间结构上最多 1 个对比** ⇒ 竞争恒为 0。
判读写「本剂量下不可识别」,**不写「排序无用」**。测排序需 `Q≥9`(f≥0.225),
与「B 不变」红线冲突,需用户裁决。

**复制场地选型**(P1/P2 探针层对比):l3:21 有一半空间 `refused=0`(结构上无墙)
⇒ 作复制场地偏弱;若走 M2b,优先 l3:48 或 l3:43 换种子。

## 8. 已记录、不在运行中修的高风险项

1. **简报只能经 analyst 的假设影响改写**:rewriter prompt 要求「每个改写针对
   bottleneck report 里的某条假设」且 `hypothesis_id` 必填 ⇒ 简报若未被写进某条假设,
   rewriter 结构上无法沿其轴改写。P1 的 `NUM_STAGES/inward` 无一条假设指向。
   **断点在 `analyst → 假设`,不在 rewriter。**
2. **rewriter prompt 关于简报的措辞是 v3 时代的**:只说「shared memory 挡住哪个参数」、
   把简报定位成「与 bottleneck.json 冲突时以它为准」的裁决者,
   **从未说明方向(inward/outward)是什么、该拿它做什么**。
3. 两项都要动 prompt,而 prompt 是 M1 两臂的共享部分 ⇒ 运行中改则前后不可比;
   且「强令 analyst 为简报每条轴写假设」是硬塞,可能挤掉更有价值的假设。
   **实验后统一评估。**

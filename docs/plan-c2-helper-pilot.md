## 4. 原 full 晋级与独立同卡 heldout
父用原 P1 自身选中配置，子用该结构跨已运行空间的 native best；所有空间完成后只做一次最终 child3，与 fresh parent3 作 screen。
沿用 full promotion：原三块范围重叠/相触或严格 quick/full 反向才触发，最多两对确认，顺序 parent→child 再 child→parent。
首对及累计 median 均支持父/平局立即 retain；否则剩余额度允许才第二对；两对都严格支持子且累计 child median 更低及正确性有效才 promote。
缺块、失败或 cutoff 不晋级；无内部 2% 门槛，不要求累计范围消除原重叠，不修改 TPE 内部排序。
Incumbent 冻结后，三角色 parent/G0/C2 在同 host GPU0 按 `P,G0,C2 / C2,G0,P / G0,C2,P`，各 fresh3，总 9 blocks/pair。
各结构用自己的 selected 配置；retained-parent arm 也另测 fresh3，不复用共同 parent 三块；heldout 不重选或继续调优。
每 full 固定 100 performance/5 correctness，fp32 reference、原 dual_witness_relaxed/FP64 multipliers2/3、fraction0.99、cosine0.99985 不变。
计时必须同一物理 GPU 串行；helper/private 测试也不可和该卡正式 timing 并发，复用现有 worker 仲裁，不另建仲裁平台。

## 5. 必须自动执行的 host-local pair controller
| 波/rep | HOST-A GPU0/A0 | HOST-A GPU1/A1 | HOST-B GPU0/B0 | HOST-B GPU1/B1 |
|---|---|---|---|---|
| wave1/0 | task43 G0 | task43 C2 | task21 G0 | task21 C2 |
| wave2/1 | task21 C2 | task21 G0 | task43 C2 | task43 G0 |
每 host 只负责自己的两 GPU、四机会和两次 heldout；先并发启动 wave1 pair 的两个隔离进程。
一旦本 host 两个进程 terminal，立即读取并校验结果/身份/冻结 incumbent，在 GPU0 执行 9 fresh heldout，优先于 export 或人工 review。
随后立即启动本 host wave2 pair，terminal 后同样立即 heldout；两 host 各自推进，不等待全局 wave1/wave2 完成。
使用进程完成通知/event wait 唤醒，不靠两分钟轮询、不留人为 T10→T12 dispatch 间隙；记录 pair-ready→heldout-start 延迟。
进程 exit 非零不直接删除机会：解析实际结果；有效 retained parent 可测，技术缺失/censored 则明确缺失，不替换或伪造结果。
结果文件缺失/损坏时控制器生成准确的失败/censored 跟踪行；不把 shell exit0 视为科学 complete；controller 故障须可报告。
科学 pair chain 内只有必要本地 artifact staging；bulk export/独立 review 放在 heldout 后，不阻塞另一 host 或及时的下一 pair。
Wave2 不因 wave1 性能而停止；只允许真实 cutoff 或技术 blocker 阻止准入，所有未启动/未完成机会和 heldout 仍留行。

## 6. 新的五小时时钟：工作截止与 heldout 保留
结果未知前固定一个全局 `campaign_started_unix_s=S`，两 host 接同一值；S 在首次主实验机会准入前记录，不含 helper gate/setup。
`work_cutoff_unix_s=S+16800`（4h40）之后不再准入新的 framework worker、模型、probe、search、study，以及已向 context 传递该 cutoff 的 formal helper submissions。
`final_deadline_unix_s=S+18000`（5h）是 heldout 最终准入截止；最后 20min 只为 heldout 保留，不能借给新搜索。
Heldout 应在各 pair ready 后立即运行，不等最后 20min；到 final deadline 不再准入新 heldout job。
已经准入的操作可能 drain，记录相对 work cutoff/final deadline 的实际结束及 drain；此时钟不是所有工作必能完成的承诺。
不按 host、wave、阶段重置；跨机器传 Unix 时间，再本地换算剩余 monotonic，禁止共享某台机器 monotonic 原点。
现有 `CampaignRun.validate_deadline` 拒绝未来超过 14400s，且 opportunity store 用 `deadline-14400` 推起点：新 pilot 必须 opt-in 修正。
新 clock 元数据显式保存 S、work cutoff、final deadline 和用途；旧 CLI/4h 默认保持原语义，不能只放宽上限却留下假起点。
Opportunity/Heldout 的 `deadline_unix_s` 身份都用同一 FINAL deadline；opportunity 活跃准入却用较早 work cutoff，heldout 用 final。
测试身份校验与准入分离、过期启动输出、两种 drain；不得把 work cutoff 当 opportunity 身份 deadline 导致 heldout mismatch。
Pilot 各 result/store/controller receipt 都保留三时刻，避免 summary 用错误 `final-14400`；helper gate 单独 20min，不重置主时钟。

## 9. 主指标、交付和停止
主性能只取同卡 heldout 的三块 median-of-medians；改善 `100*(1-M_C2/M_G0)`，每 pair 用当次共同 fresh parent 归一化。
至少 3/4 pair 同时满足 C2 改善≥2%且 `max(C2三块)<min(G0三块)`，并覆盖两个任务，才通过描述性投入 gate。
四 pair 必须全部 resolved 才可全局阳性；失败保留行，missing/censored 为 INCONCLUSIVE，不删分母、不用 screen/跨卡分数填补。
报告八机会/各 space asked、四 pair 全部块值、原生选择/父保留、rescue/失败、真实 helper/推荐/targeted/扩域采用和所有时间边界。
该两 benchmark、两 rep 是 discovery-biased pilot；不宣称一般论文结论、统计显著性或 helper 单因素效力；软件完成不是 C2 efficacy PASS。
主实验后做一次 compact independent F1，核对 source fidelity、计数/时钟、四pair算术、真实采用与 focused tests，并发布报告及回执引用。
执行顺序为归档→真实 helper gate→controller/tests→tested SHA部署→连续 pair-local campaign→分析/usage audit→报告发布→F1；无额外大审计波次。
估算 gate10–20min、controller/preflight30–60min（bug可更久）、main通常2–4h但硬排程5h、分析30–60min；总约3–6h，不是保证。
到期诚实停止、单列 drain，收集后停止本次 owned 服务/进程并记录 cleanup；不为阳性续时、补抽、补测、第三波或自动再开campaign。

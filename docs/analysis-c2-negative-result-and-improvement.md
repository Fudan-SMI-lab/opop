# C2 的负结果:根因与改进方案(2e → 斜率引导探索)

**日期** 2026-09-13 · **checkout** `D:\Pyhon_projects\opop\v3` @ `f03e08e` ·
所有数字来自三个 step-3 run 的 `events.jsonl`(`external_files/s3_run_backups/`)与
四个 run 的离线 `find_walls` 回放。

---

## 1. 要解释什么

C2(机制 = 2e)的**机制成立**:被投递的墙确实被改写腾出了(A3 1/1,反事实 arm2 0/7);
但**没有端到端收益**,而且方向是反的 —— 同箱同 mode 的干净对比里,**关掉 2e 的臂快 8.0%**
(噪声底 ±4% 的 2.0 倍),且 arm3 的获胜族从未收到墙文本。

---

## 2. 根因:2e 的作用面被结构性限制在 prompt 上

关键事实在 orchestrator 自己的注释里(`orchestrator.py:1710`):

> 2e ... **outside the tuning loop, so it cannot touch the trial budget or what the sampler sees**

这个隔离当初是**故意的** —— 它保证三臂的 trial 预算对等、可比。但它同时就是限制。
四条假设,三条成立一条否证:

| | 假设 | 实测 | 结论 |
|---|---|---|---|
| **H1** | 太晚 | 被归因的墙:发现前 **80 个 trial**,发现后 **0 个** | ✅ 采样器永远看不到关于它自己的墙 |
| **H2** | **从不引导采样** | `find_walls` 读 `stats.param_stats[].latency_by_value` —— **调参器自己建的**表 ⇒ 斜率在循环内已存在却被丢弃。最陡的 `NUM_WARPS`(25.6%)只有 **7/80** 个 trial 采到其最高值 | ✅ **承重根因** |
| **H3** | 只覆盖一个族 | 4 个族 / 2 个有墙 / **1 个**有归因 ⇒ 覆盖 **25%**,另 3 个族改写时零墙信息 | ✅ |
| **H4** | 可归因的墙恰是最弱的 | 四 run 池化:probe-worthy 斜率 7.5/25.6/25.6/25.7/45.3/56.0% 对非 worthy 的 −359/−178/−0.7/10.7/11.2/12.3/16.3/57.9%;3 个有墙的 run 里 2 个保留了最陡的 | ❌ **否证** —— arm3 运气,非设计缺陷 |

**H2 为什么是承重的。** 现在的因果链是
「调参 → 建逐取值中位表 → **丢弃** → 事后重算斜率 → 写进 prompt → 改写」。
斜率唯一的作用是**说服模型**,而它从不改变**测了什么**。所以即使模型完全照做(A3 证明它照做了),
收益也只能来自那一次改写;而那一次改写的父代已经把 80 个 trial 花在**不知道墙在哪**的采样上了。

---

## 3. 改进方向:把斜率接进采样器(用户提出)

> 斜率不止能给模型额外信息,也应能影响参数空间的探索方向,使其**优先探索斜率大的参数的空间**,
> **更早找到斜率大的参数的资源瓶颈**。

### 3.1 可行性:实测支持

用出厂 analyzer + `find_walls` **回放真实 trial 顺序**,在 25/50/75/100% 处重算
`cand-dc87a93a`(那个唯一被归因的候选):

| 进度 | 墙排序(按尾部斜率) | probe-worthy |
|---|---|---|
| 25%(20 trial,7 拒绝) | BLOCK_N_G 54.8, NUM_STAGES_G 8.2, BLOCK_N **−89.0** | 0 |
| **50%**(40 trial,11 拒绝) | BLOCK_N_G 60.7, BLOCK_N **+43.7** | **1** |
| 75%(60 trial,18 拒绝) | NUM_WARPS 34.6, BLOCK_N 22.3 | 2 |
| 100%(80 trial,22 拒绝) | NUM_WARPS 25.6, BLOCK_N 7.5 | 2 |

⇒ **半程就有可探针的墙,而且还剩 40 个 trial 可花**;拒绝也来得早(25% 时已 7/22)。
所以「更早找到资源瓶颈」不是投影,是这份数据支持的。

### 3.2 同一份数据给出的两条硬约束

**约束 A — 早期排序不稳,不能当承诺。**
`BLOCK_N` 在 25% 处读到 **−89.0%**、50% 处 **+43.7%**,**符号翻转**。
在 25% 处按斜率引导会把预算投给一个当时看起来最差的 knob。

**约束 B — 墙会出现又消失。**
`cand-948343ba`:25% 时 2 个墙 → 75% 时 0 个 → 100% 时 1 个(换了 knob)。
墙的存在本身是"被拒值落在已测范围之外",随着采样扩大,范围会追上被拒值。

⇒ 引导必须是**建议性、可撤回、每次重算**的,不能锁定;
并且**绝不能用它缩小取值域**(用户已否决按硬编码缩小探索空间,且
`a-prescreen-timeout-is-a-cost-cap-not-a-space-restriction` 的区分在这里同样适用:
**改变采样顺序/密度是成本分配,排除取值是空间限制**)。

### 3.3 具体设计(待批准,未实施)

**S7:斜率引导的采样偏置(slope-guided sampling bias)**

1. **触发点**:每 `recompute_every` 个 trial(建议 10,即 `trials_per_space` 的 1/8),
   在调参循环内调用现有 `TuningStatsAnalyzer.analyze(space, trials_so_far)` +
   `find_walls(stats, refused_so_far)` —— **两者都已存在且是纯函数**,不需要新测量。
2. **产出**:一个 knob → 权重的映射,权重 ∝ 该 knob 的尾部斜率(仅取 monotone 且 >0 的)。
3. **施加方式**:通过 Optuna 的 `enqueue_trial` 把「高斜率 knob 取其**未测过的相邻值**、
   其余 knob 取当前最优」的配置**插队**。这只**增加**候选点,不删除任何取值 ⇒
   空间不变,只是探索顺序变了。
4. **不做的事**:不改 `trials_per_space`(预算不变,可比性只受顺序影响);
   不锁定任何 knob;不因斜率排除任何取值;权重每次重算(应对约束 A/B)。

**可证伪的预测**(必须事先声明):
- **P1** 开启后,`RESOURCE_WALL_ATTRIBUTED` 的首次出现时间(归一化到候选的调参进度)**提前**;
- **P2** 每个候选发现的 probe-worthy 墙数**增加**(现在 arm3 是 6 个墙 /19 候选);
- **P3** 覆盖的族比例从 25% 上升;
- **P4** 若 P1–P3 成立而延迟仍不改善,则**「更早知道墙」不是瓶颈** —— 该负结果同样是结论,
  且它会把 C2 的问题定位到「改写这个动作本身的转化率」而不是「信息到达时机」。

**风险与代价:**
- 改变 trial 分配 ⇒ **run 间不可比**,必须在实验之间做,之后的 run 不能与之前合并。
- 偏置采样会让 TPE 的先验偏离均匀,可能**降低**最终延迟(把预算花在斜率大但绝对收益小的维度上)。
  `boundary-saturation-does-not-predict-headroom` 已实测「调研推荐的最强空位信号」ρ 全 ≤0.24,
  所以**不能假设斜率是好的分配先验** —— 这正是 P4 要测的。
- 需要一个**关掉它的对照臂**才能归因 ⇒ 又是一对 12h。

### 3.4 更便宜的替代:先扩大覆盖面(H3)

如果不想动采样器,H3 有一个零风险的改法:**把墙文本发给所有族的改写者**,
而不只是发给被归因的那个族。现在 3/4 个族改写时零墙信息,而墙是**候选级**的事实,
其他族的候选也有自己的墙(arm3 有 2 个族有墙、只有 1 个被投递)。
这不改变测什么,只改变谁看到 —— **可比性风险等同于原 2e**,且能把 A3 的样本从 n=1 扩大。

---

## 4. 建议的次序

1. **先做 3.4(扩大覆盖面)** —— 零风险、扩大 A3 样本,可与任何实验同批。
2. **再评估 3.3(接进采样器)** —— 它是 C2 唯一可能翻转负结果的改动,但会破坏 run 间可比性,
   且有理论风险(斜率未被证明是好的分配先验)。**需要你批准后再实施。**
3. **无论哪条,报告都必须保留当前的负结果** —— 「2e 只进 prompt 时无端到端收益」
   是一个已测的事实,改进版若成功,它就是改进的对照。
